# 医疗报告解读

## 能力边界

基于 [医疗报告解读规范](references/report-analysis.md)，本能力用于对目标医疗报告进行医疗报告解读，或审核、补充、更新、重写既有解读结果时使用。

需要保存时使用 `write_report_analysis` 写入目标医疗报告；只在会话中回答时，也按本技能生成完整解读结果。

## 证据范围与完成标准

医疗报告解读覆盖发生于目标医疗报告日期当天及此前的全部健康档案。

- 先确定目标医疗报告及其发生日期。目标医疗报告日期缺失时询问用户，不能用保存时间代替。多份目标医疗报告分别确定证据截止日期。
- 完整读取医疗报告、健康日记和用药目录，记录已读取的目标标识与尚未读取的范围。
- 医疗报告事实、既往史、健康日记和用药资料分批完整读取。医疗报告基础信息与结构化内容均需覆盖；需要核对原件、补足来源内容或解释矛盾时读取相应来源原文。
- 身体指标先读取涵盖截止日期及以前的全量统计，核对匹配记录数量、覆盖日期、缺失和排除情况；不同来源、设备、方法、单位及评分满分分别判断。高频测量不要求逐条展开，按异常、趋势、数据冲突和当前判断需要读取对应序列及记录明细。统计分页只限制数据页，不能把一页当作完整统计。
- 时间依据为资料中的发生时间。记录日期只能证明日志的记录日，正文记载的其他发生时间仍须核对；药品资料的保存时间不能证明当时已经服用。当前既往史中无发生日期或时间不明的内容列为待核对，不自动视为历史事实。晚于截止日期的事实不参与本次医学判断。
- 审核、补充、更新或重写前，另行读取目标医疗报告的现有解读结果，并与已读取的医学证据核对。
- 任一资料读取失败、目录未读完、运行预算不足、时间无法确定或统计覆盖有缺口时，明确说明已覆盖范围与缺口；继续取证或询问用户，不宣称完成完整医疗报告解读。保存了部分内容也不能改变这个完成判断。

## 安全约束

- 只处理目标医疗报告的解读结果，不更新其基础信息、来源或结构化内容；
- 解读结果正文为中文 Markdown 正文，不输出 JSON、代码围栏、思考过程或“解读结果”总标题，遵循 [医疗报告解读规范](references/report-analysis.md)；
- 审核、补充、更新、重写的目标医疗报告不存在既有解读结果时，应说明解读结果不存在，不得声称完成了补充、审核、更新或重写。

## 完成结果

- 只在当前会话中回答时直接返回解读结果；涉及写回时，说明各份医疗报告的解读结果是否已保存及取证是否完整；
- 没有可写回的已保存目标时，也只在当前会话中回答；
