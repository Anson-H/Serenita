# 医疗报告导入

## 能力边界

### 描述

本能力用于解析、校验并导入医疗报告事实。当前任务包含医疗报告时使用；要求“只查看”或“不保存”时除外。

不构成医疗报告的内容按普通资料处理。

### 判断依据

依据待导入内容、医疗报告目录和按需读取的医疗报告事实判断写入方式；当前任务涉及检验报告时，还必须具备检验指标分类目录的工具观测。

- 医疗报告目录用于定位；关联重复来源或无冲突合并必须依据目标医疗报告事实；
- 涉及检验报告时，必须读取检验指标分类目录，依据其确认指标映射。

建议先读取医疗报告目录，再选择相近医疗报告读取详情。没有相近医疗报告且证据支持独立创建时，可以直接选择创建新报告，无需读齐全部既有报告详情。

### 选择写入方式

| 写入方式 | 适用条件 | 对应动作 |
| --- | --- | --- |
| 创建 | 目录中没有相近医疗报告且证据支持独立创建，或读取相近医疗报告后确认是独立医疗报告 | 调用 `create_report` |
| 关联重复来源 | 医疗报告事实确认是某条既有医疗报告的另一个来源 | 调用 `link_duplicate_sources` |
| 无冲突合并 | 医疗报告事实确认属于某条既有医疗报告，并补充与既有内容不矛盾的信息 | 调用 `merge_report` |

支持单独写入与批量写入，结束前核对是否有遗漏。

## 安全约束

### 事实与日期

- 医疗报告日期优先采用医疗事件的实际发生时间：
  - 检验报告：采样时间，若无则依次取送检、标本接收、医疗报告出具时间；
  - 检查报告：执行时间，无则取医疗报告出具时间；
  - 病理报告：手术/取材时间，无则依次取标本送检、接收、医疗报告出具时间；
  - 手术报告：手术时间，无则取医疗报告出具时间；
  - 门诊病历、急诊病历：原件记载的就诊时间；
  - 其他医疗报告：事件发生时间，无则取医疗报告出具时间。

### 医疗报告拆分

- 先根据每个检验指标的医学功能语义判断其主分类；原件标题、检验科室大类或组合套餐名称不是指标分类的证据。
- 同一张医疗报告存在多个主分类时，必须按主分类拆成多份医疗报告。
- 拆分后的多份医疗报告可以共同引用同一原件。

### 检验报告参数映射

- 既有指标必须使用检验指标分类目录中的主分类，不得使用关联分类或自创分类；
- 检验指标分类目录为空或其中不存在某项指标时，必须依据该指标的医学功能语义判断主分类，并分配一个新的唯一标识；
- 同名指标可能分别属于不同主分类。必须结合当前医疗报告分类选择对应指标；无法判断是否为同一指标时不得猜测，应向用户追问；
- 不得把“生化检验”、“综合生化”等原件标题、检验科室大类或组合套餐名称当作跨功能指标的统一主分类；
- 不存在记录单位的参数，因此结果值和参考值能带单位时必须保留单位，不得在解析过程中丢失已提供的单位；
- 一份检验报告内的全部指标必须属于同一个主分类，且医疗报告名称必须与该唯一主分类完全一致。

### 来源

- 每份医疗报告至少包含一个来源，同一份医疗报告内不得重复绑定同一来源；
- 附件来源使用 `RUNTIME_CONTEXT.visible_attachments` 中的资源标识和对应的附件来源类型；
- 一个附件可以由多份医疗报告共同引用；多个附件共同构成一份医疗报告时，应按来源顺序绑定全部附件；
- 文本来源必须使用对应的文本来源类型。原文和消息标识由服务端绑定，模型不得重传或伪造。

### 工具观测的失败反馈

- 写入工具返回校验失败时，依据错误修正内容或来源后重试；
- 不得依赖 `create_report`、`link_duplicate_sources` 或 `merge_report` 修正名称、分类或其他解析错误；
- `merge_report` 只能无冲突地补充信息，不得覆盖不同旧值，也不得代替模型处理指标映射歧义。

## 完成结果

- 用户未要求医疗报告解读时，最终回答说明每份医疗报告的医疗报告事实导入效果和必要差异；
- 如实列明当前任务中每份医疗报告的真实处置：已创建、已关联重复来源、已无冲突合并、因不确定而追问、无需写入、明确失败或尚未执行。
