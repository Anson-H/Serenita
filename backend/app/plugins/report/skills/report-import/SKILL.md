# 报告导入

## 成员与健康档案权限

运行时资料不包含 `member` 时，当前聊天不关联成员，也不提供报告工具。可以根据用户目标临时阅读当前聊天附件，但不得将其写入报告档案库。用户表达保存意图时，应结合当前任务自然提示先添加或选择成员，再在新聊天中继续。这是模型可见的行动指引，不是固定回复、强制流程或硬编码业务分支。

存在 `member` 时，当前任务只作用于它指定的固定成员。操作账号和健康档案所有者账号都不一定是医疗资料所属的人；医疗资料所属的人始终是当前成员。共享健康档案中指向医疗资料所属人的“本人”按当前成员理解，不能按当前登录账号或健康档案所有者账号推断。所有查询、判重、合并、更新和删除只在该成员作用域内进行；不能跨成员猜测、关联或切换目标。

只读权限允许读取和在操作者自己的聊天中回答，但不得写入报告档案库；即使用户提出保存要求也不能越权。编辑权限可以修改成员基础资料和医疗报告，不含再次授权、账号设置或目录管理。检验指标分类目录由健康档案所有者账号共用，导入可以补充新指标与别名，但不能修改已有分类口径。撤权或降为只读后，以真实权限失败为准，不重试到其他成员。

## 能力边界

### 目标与判断依据

本能力用于解析、校验并导入由基础信息、来源与结构化内容组成的报告事实。当前任务包含医疗报告或要求导入报告时使用；要求“只查看”或“不保存”时除外。

任何决定都必须建立在当前任务（当前用户消息及与其相关会话历史）与以下两类工具观测上：

- 既有医疗报告的报告事实；
- 本批医疗报告的完整解析校验结果。

当前任务涉及检验报告时，还必须具备检验指标分类目录的工具观测。

### 可执行步骤

1. **读取检验指标分类目录（涉及检验报告时执行）与既有医疗报告的报告事实**

2. **校验本批解析结果**

   针对本批最终医疗报告，调用 `validate_parsed_reports` 校验报告结构、类型、日期、名称、分类与指标，并去重和规范化来源，生成本批完整解析校验结果。

   该工具只返回完整解析校验结果，不写入报告档案库；它只能确认提交结构内部自洽，不会替你判断分类粒度是否正确。

3. **选择处理结果**

   基于当前任务，根据完整解析校验结果与既有医疗报告的关系，为每份报告选择以下一种处理结果：

   | 处理结果 | 适用条件 | 对应动作 |
   | --- | --- | --- |
   | 创建新报告 | 与既有医疗报告不重复、不冲突 | 调用 `create_report` |
   | 关联重复来源 | 是某条既有医疗报告的另一个来源 | 调用 `link_duplicate_sources`，只为对应既有报告追加来源 |
   | 无冲突合并 | 属于某条既有医疗报告，并带来不矛盾的新增信息 | 调用 `merge_report` 填补该报告缺失的内容 |
   | 如实追问 | 工具观测不足以得出结论，例如无法唯一匹配既有报告，或同一指标出现不同值 | 不猜测、不覆盖，如实追问用户 |
   | 不写入 | 内容不应导入报告档案库，例如零散数值、假设示例、不属于当前成员的他人数据，或用户明确要求“只查看”或“不保存” | 不擅自保存到报告档案库，按普通资料处理 |

其中，创建新报告、关联重复来源和无冲突合并会产生写入；如实追问和不写入不会产生写入。

创建新报告写入报告事实；关联重复来源只补充来源；无冲突合并只补充不矛盾的结构化内容。

## 证据规则

由于报告档案库可能在会话之外被修改或删除，会话历史里早前轮次的导入结果、助手自述或用户转述都不代表当前报告档案库状态，因此：

- 强烈建议读取既有医疗报告与检验指标分类目录；
- 必须调用 `validate_parsed_reports` 生成本批医疗报告的完整解析校验结果。

确保指标映射、创建、关联、合并、追问或不写入建立在完整工具观测上。

## 安全约束

### 事实与日期

- 只转换用户明确提供的事实，只引用当前任务的工具观测；
- 不得补造未确定或未提供的内容，不得复用旧版本，缺少必要信息或出现矛盾信息时应如实追问；
- 报告日期优先采用医疗事件的实际发生时间：
  - 检验报告：采样时间，若无则依次取送检、标本接收、报告出具时间；
  - 检查报告：执行时间，无则取报告出具时间；
  - 病理报告：手术/取材时间，无则依次取标本送检、接收、报告出具时间；
  - 手术报告：手术时间，无则取报告出具时间；
  - 其他报告：事件发生时间，无则取报告出具时间。

### 报告拆分

- 先根据每个检验指标的医学功能语义判断其主分类；原件标题、检验科室大类或组合套餐名称不是指标分类的证据。
- 同一张医疗报告存在多个主分类时，必须按主分类拆成多份医疗报告。
- 拆分后的多份报告可以共同引用同一原件。

### 检验报告参数映射

- 既有指标必须使用检验指标分类目录中的主分类，不得使用关联分类或自创分类；
- 检验指标分类目录为空或其中不存在某项指标时，必须依据该指标的医学功能语义判断主分类，并分配一个新的唯一标识；
- 同名指标可能分别属于不同主分类。必须结合当前报告分类选择对应指标；无法判断是否为同一指标时不得猜测，应向用户追问；
- 不得把“生化检验”、“综合生化”等原件标题、检验科室大类或组合套餐名称当作跨功能指标的统一主分类；
- 不存在记录单位的参数，因此结果值和参考值能带单位时必须保留单位，不得在解析过程中丢失已提供的单位；
- 一份检验报告内的全部指标必须属于同一个主分类，且报告名称必须与该唯一主分类完全一致。

### 来源

- 每份医疗报告至少包含一个来源，同一份医疗报告内不得重复绑定同一来源；
- 附件来源必须引用 `RUNTIME_CONTEXT.visible_attachments` 中当前分支可见附件的准确资源标识，并使用对应的附件来源类型；不得以文件名、序号、临时别名或猜测值代替资源标识；
- 一个附件可以由多份报告共同引用；多个附件共同构成一份报告时，应按来源顺序绑定全部附件；
- 文本来源必须使用对应的文本来源类型。原文和消息标识由服务端绑定，模型不得重传或伪造。
- 来源元数据只表示来源身份及其与报告的关联，不代表原件正文已被读取；只有实际读取并用于判断的来源原文才可称为原始证据。

### 工具观测的失败反馈

- 工具或模型输出失败时，必须依据当前任务与工具观测决定继续取证、修正结构、询问用户或停止；
- 校验在返回完整解析校验结果前失败时，必须基于当前任务依据真实错误修正问题后再次提交校验；
- 不得依赖 `create_report`、`link_duplicate_sources` 或 `merge_report` 纠正名称、分类或其他解析错误；
- `merge_report` 只能无冲突地补充信息，不得覆盖不同旧值，也不得代替模型处理指标映射歧义。
- 若目标报告或其依赖在会话之外被修改或删除，应如实反馈，不得猜测、恢复或静默修改。

## 完成结果

- 报告解读不由导入自动启动，导入也不自动包含报告解读授权。用户未要求报告解读时，最终回答只如实说明每份医疗报告中报告事实（基础信息、来源与结构化内容）的导入效果和必要差异；
- 如实列明本批每项报告的真实处置：已创建、已关联重复来源、已无冲突合并、因不确定而追问、无需写入或明确失败；
- 多次尝试后仍无法导入报告时，如实说明失败的报告内容和原因，包括附件无法解析、内容提取失败，或写入工具返回失败等情形。
