# 报告解读

## 成员与健康档案权限

运行时资料不包含 `member` 时，当前聊天不关联成员，也不提供报告工具。可以根据用户目标临时阅读当前聊天附件，但不得将其写入报告档案库。用户表达保存意图时，应结合当前任务自然提示先添加或选择成员，再在新聊天中继续。这是模型可见的行动指引，不是固定回复、强制流程或硬编码业务分支。

存在 `member` 时，当前任务只作用于它指定的固定成员。操作账号和健康档案所有者账号都不一定是医疗资料所属的人；医疗资料所属的人始终是当前成员。共享健康档案中指向医疗资料所属人的“本人”按当前成员理解，不能按当前登录账号或健康档案所有者账号推断。所有查询、判重、合并、更新和删除只在该成员作用域内进行；不能跨成员猜测、关联或切换目标。

只读权限允许读取和在操作者自己的聊天中回答，但不得写入报告档案库；即使用户提出保存要求也不能越权。编辑权限可以修改成员基础资料和医疗报告，不含再次授权、账号设置或目录管理。检验指标分类目录由健康档案所有者账号共用，导入可以补充新指标与别名，但不能修改已有分类口径。撤权或降为只读后，以真实权限失败为准，不重试到其他成员。

## 能力边界

基于 [报告解读规范](references/report-analysis.md)，本能力用于对目标医疗报告进行报告解读，或审核、补充、修改、重写既有解读结果时使用。

具有编辑或所有者权限时，默认将解读结果写入当前成员的目标医疗报告中，要求“不保存”或“仅会话中回答”时除外：

- 未要求“不保存”或“仅会话中回答”时，默认调用 `write_report_analysis` 写入报告档案库中的目标医疗报告，不重复询问；
- 要求“不保存”或“仅会话中回答”时，也应使用本能力生成完整解读结果，但不得调用 `write_report_analysis`。

## 证据规则

- 生成目标医疗报告的解读结果时，证据时间范围必须截止于该报告日期，必须覆盖当天及此前的全部语料，不得使用目标日期之后的语料；
- 新增解读结果前，工具观测必须覆盖证据时间范围内目标报告当前存在的基础信息与结构化内容；
- 审核、补充、修改、重写既有解读结果前，除覆盖上述内容外，工具观测必须覆盖目标报告当前的解读结果，但它仅作为待审核或待变更对象，不计入医学证据。

## 安全约束

- 目标医疗报告以医疗报告目录中指定的报告为准；
- 范围不明、目标无法确定或证据不足时，继续取证或追问用户；
- 只处理目标医疗报告的解读结果，不修改其基础信息、来源或结构化内容；
- 解读结果正文为中文 Markdown 正文，不输出 JSON、代码围栏、思考过程或“解读结果”总标题，遵循 [报告解读规范](references/report-analysis.md)；
- 审核、补充、修改、重写的目标医疗报告不存在既有解读结果时，应说明解读结果不存在，不得声称完成了补充、审核、修改或重写。

## 完成结果

- 只在当前会话中回答时直接返回解读结果；涉及写回时，最终回答区分已保存、未保存和仍缺证据的目标，不把内容已生成等同于写回成功；
- 没有可写回的已保存目标时，也只在当前会话中回答；
- 只有 `write_report_analysis` 明确返回写回成功，才能声称对应报告的解读结果已保存。多份报告应分别确认结果，并如实说明部分失败。
