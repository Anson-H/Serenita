# Serenita 文档中心

本目录只维护两种状态：当前执行文档和未来愿景。历史版本、发布快照与已经废弃的内部行为不保留在这里。

## 文档入口

| 状态 | 入口 | 是否可直接用于开发 |
| --- | --- | --- |
| 当前执行 | [当前执行文档](当前执行/README.md) | 是 |
| 未来愿景 | [未来愿景](未来愿景/README.md) | 否；必须先进入明确版本并冻结范围 |

当前执行版本为 v0.2.0。第一次阅读建议从[产品需求](当前执行/产品/产品需求.md)和[技术架构总览](当前执行/架构/技术架构总览.md)开始；要查某个精确规则时，使用[当前执行文档的内容归属表](当前执行/README.md#唯一内容归属)，术语歧义查[当前术语表](当前执行/术语表.md)。

未来愿景在当前医疗报告管理、成员授权和通用 Agent Harness 基础上，记录手机自动同步、厂商文件适配、设备接入、外部推送及多智能体协作评估等未来增量。它们不覆盖当前接口、数据结构或验收标准。

## 状态与类型

状态和类型是两个不同维度：

- 状态回答“现在是否执行”：当前执行或未来愿景。
- 类型回答“这份文档负责什么”：产品、架构、领域、接口、前端或运维。

“技术参考”不再作为模糊状态，“共享参考”不再作为混合分类。成员是领域契约，会话事件是架构协议，本地存储与数据库结构是运维和存储契约；它们都属于当前执行。

## 目录结构

```text
docs/
  README.md                       # 文档入口与管理规则
  当前执行/                       # 当前执行的唯一契约集合
    README.md                     # 阅读入口与内容归属表
    产品/                         # 产品范围与产品验收
    架构/                         # 系统结构、运行时与协议
    领域/                         # 业务身份、证据与领域不变量
    接口/                         # HTTP 与组件职责边界
    前端/                         # 页面行为和反馈
    运维/                         # 本地数据、SQLite、JSONL 与运行维护
  未来愿景/                       # 不绑定版本、不承诺交付的未来愿景
```

根目录 [`DESIGN.md`](../DESIGN.md) 是当前视觉契约；根目录 [`AGENTS.md`](../AGENTS.md) 是唯一智能体开发规则入口。后端与前端开发入口分别位于 [`backend/README.md`](../backend/README.md) 和 [`frontend/README.md`](../frontend/README.md)。这些仓库级入口不会成为第二份产品或领域契约。

## 文档管理规则

### 当前执行

- `当前执行/` 只保存当前执行版本，不按版本累积历史目录。
- 切换当前版本时直接更新当前产品契约和受影响专题文档，不保留旧协议、兼容说明或发布快照。
- 当前版本由产品需求定义范围，由专题契约分别定义架构、领域、接口、前端和存储的精确规则。
- 新功能先进入产品需求与验收，再更新相应专题契约和实现。

### 唯一权威正文

- 技术专用名词采用[英文专用名词](当前执行/术语表.md#英文专用名词)中的固定写法，例如 Skill、Observation、Schema；长期记忆文档中表达架构对象、层级和状态的关键术语采用固定英文名称，正文、图示和算法说明同步使用，术语表提供中文释义；模块名称保留中文，研究对象沿用英文原名，具体见[长期记忆固定术语](未来愿景/长期记忆与认知架构.md#固定术语)。术语表提供中文释义，医疗业务名称与普通动作使用中文。
- 项目自有文案按[动词使用规则](当前执行/术语表.md#动词使用规则)区分查询、定位、读取、查看及各类变更动作；同一动作跨 Skill、界面与文档使用同一称呼。
- 总览回答“有哪些部分、为什么这样分”，专题契约回答“准确规则是什么”。
- 每个主题只允许一个权威正文；其它文件写必要摘要并链接。
- 产品文档不保存事件字段、工具参数、HTTP 路由或数据库表。
- 架构总览不保存完整 API、Schema、页面交互或领域流程。
- 领域文档不保存端点表和像素级 UI；接口文档不替领域作业务判断。
- 本地存储只维护物理布局、数据库文件分配、密钥、文件权限和 Schema 生命周期。
- 数据库结构统一维护 SQLite 表、列、键、索引、约束，以及跨数据库、JSONL、文件系统和允许目标先删除的引用清单；字段业务含义回到对应领域文档。
- 会话 JSONL 格式统一维护逐行编码、header、事件信封、最低事件字段和写入恢复边界；会话事件文档维护其语义、顺序和投影。

### 文档头与链接

每份当前专题文档应明确声明：文档层级、负责、不负责、上位文档与相关契约。文件名和目录表达主题归属，不再依赖“共享参考”标签。

跨文件链接优先指向语义标题，避免依赖易变的数字章节编号。移动或拆分文档时同步更新根目录 README、`AGENTS.md`、`DESIGN.md`、后端与前端 README，以及受影响专题文档的链接。

### 未来愿景

- `未来愿景/` 及其入口必须保留。
- 未来愿景不得直接作为当前开发或验收依据。
- 未来能力只有先纳入明确当前版本、冻结范围并迁入 `当前执行/`，才成为执行契约。
- 未来愿景中的接口、目录、术语或技术选型与当前执行文档冲突时，以当前执行文档为准。

### 代码同步

代码、测试和当前文档不一致时，先依据当前安全与数据边界确认应更新哪一侧，再同步唯一权威文档。不得通过添加兼容层、迁移说明或第二份契约来掩盖冲突。
