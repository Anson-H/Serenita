> 文档状态：当前执行 / 当前执行版本
>
> 所属索引：[v0.1.0 产品需求文档索引](./README.md)
>
> 对应技术设计：[首页对话技术设计](../technical/home-conversation.md)

## 1. 目标

首页对话模块负责患者主工作台中的基础健康问答、会话历史、上下文资源和对话恢复。v0.1.0 只允许从首页工作区发起真实模型请求；侧栏 `报告`、`生活` 场景和 `原始文件` 辅助入口仅作为占位入口。

本模块交付：

- 首页工作区基础问答
- 底部共享输入区
- 模型和推理强度选择
- 文件上下文资源上传
- 历史消息选中文字引用
- Markdown 输入输出展示
- 可折叠思考过程展示
- 会话时间线持久化
- 最近会话列表
- 会话详情恢复
- 指定会话 URL `/chat/{session_id}` 恢复
- 消息复制
- 编辑历史提问并重发
- 重新生成助手回答
- 生成中停止回答
- 从助手回答后创建分支
- 分支切换
- 删除会话
- 报告、生活、原始文件占位边界

本模块不交付：

- 报告结构化字段抽取
- 报告上传入库或刷新报告列表
- 生活管理正式能力
- 报告/生活场景真实发送
- 分屏对话模式
- 长会话自动压缩

当前代码实现说明：

- 发送消息会校验默认/指定模型、推理强度、文件资源和历史引用，并写入会话索引与 JSONL 时间线。
- 助手回复通过已配置模型服务生成，流式接口输出 `thinking_delta`、`content_delta`、`completed`、`failed` 或 `cancelled` 事件。
- 发送接口本身不调用模型；模型调用发生在前端订阅 `GET /api/conversations/streams/{stream_id}` 时。
- 完成回答后，系统优先使用账号设置中的 `title` 默认模型根据完整问题和回答生成短会话标题；未设置 `title` 时回退 `chat` 默认模型，模型调用失败时回退为本地规则标题。
- 生成中点击停止会把已展示的半截回答保存为 `cancelled` 助手消息；生成中点击重新生成会先取消当前轮次但不保存半截回答，再开启新的生成轮次。
- 文件上下文当前完成上传、登记、过期和模型能力校验。发送时，若 `chat` 模型原生支持附件 MIME，后端直接转发给 `chat` 模型；若 `chat` 模型不支持但 `vision_parse` 模型支持，后端直接调用视觉解析模型并把附件作为原生输入发送，由 `vision_parse` 生成本轮回答；两者都不支持时拒绝上传或发送。
- 仅上传文件但尚未发送问题时，后端会创建可通过详情接口读取的草稿会话；该草稿没有活动消息路径，不进入左侧最近会话列表。用户真正发送后才出现在会话列表。
- `报告` 和 `生活` 场景当前复用首页工作区外壳和模型选择控件，但文本输入框被禁用，附件入口隐藏，提交动作在前端直接阻止；当前不额外调用后端，也不弹出单独发送错误，以场景标题和输入框 placeholder 作为占位提示。

## 2. 工作台结构

右侧主工作区从上到下包含：

- 工作区标题栏。
- 场景内容区：根据当前首页、报告或生活场景渲染内容；报告和生活场景入口在左侧侧栏。
- 底部共享输入区：在首页、报告和生活场景中保持同一套视觉结构；非首页场景当前禁用文本输入并隐藏附件入口。

交互要求：

- `首页`、`报告`、`生活` 可统一维护输入文本、附件、错误信息和推理强度选择。
- v0.1.0 只有 `首页` 允许发起真实对话请求。
- `报告`、`生活` 场景只保留视觉占位和轻量引导。
- 从 `报告` 或 `生活` 场景点击发送时，不得发起真实大模型请求；当前前端直接阻止提交，以占位标题和输入框 placeholder 展示该能力尚未开放，不额外弹出发送错误。
- `原始文件` 左侧入口可显示占位状态，不录入正式文件或报告结构化数据。

## 3. 底部共享输入区

输入区从上到下包含：

- 输入主体区：多行文本输入框，展示当前场景的占位文案。
- 操作区：左侧为文件上传按钮，右侧为模型选择、推理强度选择和发送按钮。

控件要求：

- 文件上传按钮使用回形针或明确的附加文件入口。
- 推理强度选择器展示当前档位。
- 模型弹层当前会刷新并展示当前账号全部已添加模型，`chat` 默认模型置顶；未添加模型时展示“未添加聊天模型”或等价引导。前端推理强度随当前选中模型变化，附件按钮同时参考当前 `chat` 模型和 `vision_parse` 模型的文件能力；v0.1.0 后端上传和真实发送仍只能使用 `chat` 默认模型作为请求模型，后端会拒绝非 `chat` 默认模型提交。
- 切换模型后，推理强度菜单按该模型能力自适应展示。
- 有文本时，发送按钮可提交；无文本但已有附件或历史引用等上下文资源时也可提交；没有文本且没有上下文资源时不可触发或展示明确提示。
- 模型生成过程中应禁用重复提交，并展示明确加载状态。
- 切换首页、报告或生活场景时，输入区控件位置不变；报告和生活场景当前禁用文本输入，附件入口随场景能力隐藏。
- 输入区不展示快捷问题或示例提问按钮。
- 用户输入 Markdown 源文本；用户消息、助手回答、思考过程和收藏快照均使用 Markdown 渲染。
- 空首页的提示文案和输入框应作为一个整体在首页内容区居中；提示字号和提示到输入框的间距不随响应式布局变化。进入真实对话后，只有对话历史区域可以滚动，底部输入区固定在工作区底部并作为覆盖式悬浮层浮在对话历史上方。
- 对话历史内容不得出现在输入框下方；历史滚动容器应为悬浮输入框保留遮挡安全距离，滚动条属于整块对话历史区域并尽量贴近工作区最右侧。
- 最新生成过程、助手回答和对话历史尾部在自动滚动到最新时必须显示在输入框上方，不得被悬浮输入框遮挡或落到输入框背后。
- 输入框行数增多时，只允许输入框自身增高或内部滚动；对话历史滚动容器的高度、滚动范围和滚动条位置只随对话历史内容变化，不随输入内容行数变化。
- 多行输入框所有行的输入光标高度必须一致，并与当前文字字号和行高一致。
- 对话过程中主标题显示当前会话标题。
- 思考过程以可折叠区域展示。

推理强度枚举：

| UI 文案 | payload | 说明 |
| --- | --- | --- |
| 默认 | `default` | 平衡速度与完整性 |
| 快速 | `fast` | 不进行思考，直接输出回答 |
| 低 | `low` | 轻量推理 |
| 中 | `medium` | 中等分析深度 |
| 高 | `high` | 更深入展开依据与建议 |
| 超高 | `xhigh` | 仅在模型能力声明支持时展示 |

前端只展示当前模型 `thinking_modes` 中包含的档位；未出现在模型能力列表中的档位不展示、不可选。

## 4. 用户流程

1. 用户进入首页。
2. 用户输入健康问题。
3. 用户可附加图片、provider adapter 原生支持的 PDF、OpenRouter 或阿里云百炼对应模型原生支持的音频/视频，或引用历史消息中的选中文字作为本轮上下文资源；Office 文档仍不支持，除非 provider adapter 后续实现原生文件输入。
4. 用户点击发送。
5. 系统创建或延续当前 `session_id`，为本次提交生成 `turn_id`。
6. 若本轮包含文件，前端只提交已登记资源的 `resource_id`；后端校验资源归属后补全文件元数据。
7. 后端先向会话时间线追加 `file_upload`，再追加 `user_message`。
8. 系统展示生成中状态，并阻止重复提交。
9. 前端在线时通过流式接口触发真实模型请求并展示 AI 回答内容；对已经完成、取消或失败的轮次，流式接口按已落盘状态回放终态事件。
10. 用户重新进入时，通过会话详情或轮次状态接口展示时间线中已经完成或仍在生成的回答状态。
11. 系统向会话时间线追加可选 `thinking_process` 和 `assistant_message`，并更新会话索引。
12. 用户可复制、引用、重新生成、收藏回答，或从某条助手回答后继续创建分支。

## 5. 功能需求

### FR-CONV-001 基础问答

- 首页必须支持自然语言文本输入。
- 没有文本且没有附件或历史引用等上下文资源时，发送按钮不可触发或给出明确提示；只有上下文资源而无文本时允许提交。
- 提交后应展示加载状态，并阻止重复发送。
- AI 回答应展示在首页对话区；当前实现通过已配置模型服务生成，不再使用后端同步占位回答。
- 回答应以清晰文本展示，必要时可由前端做分段或卡片化呈现。
- 系统提示词或响应模板应引导 AI 回答至少包含核心结论和下一步建议。
- 当回答涉及风险时，应优先提示风险等级或需要关注的信号。
- 请求失败时，应展示错误提示并允许重试。

### FR-CONV-002 模型和推理强度

- 每轮对话需记录本轮实际使用的模型 ID。
- 若用户尚未配置任何模型服务、未添加可用模型或未设置可用 `chat` 默认模型，发送消息时后端返回 `MODEL_NOT_CONFIGURED`。
- 前端展示模型配置引导，引导用户前往账号设置完成配置。
- 当前前端模型弹层可查看全部已添加模型，并按所选模型切换推理强度和附件按钮可见性；上传和真实发送阶段以后端 `chat` 默认模型校验为准，非 `chat` 默认模型返回 `INVALID_REQUEST`。
- `thinking_mode` 在 UI 层显示中文文案，接口层统一传英文枚举。
- 后端必须校验 `thinking_mode` 是否包含在当前模型 `thinking_modes` 中。
- 不支持的档位不得发起无效请求。
- 若模型显式返回可展示的思考过程或思考摘要，系统应将该内容作为本轮助手输出的一部分保存到会话记录。
- 若模型未返回或供应商不允许暴露，则不生成、推测或伪造思考过程。
- 收藏默认只保存最终回答内容，不自动把思考过程写入收藏快照。

### FR-CONV-003 上下文资源

- 首页对话需支持图片、provider adapter 原生支持的 PDF，以及 OpenRouter 或阿里云百炼对应模型原生支持的音频/视频等非文本材料作为上下文资源；Office 文档仍不支持，除非 provider adapter 后续实现原生文件输入。
- 单文件大小上限为 20MB。
- 支持的文件类型白名单由当前模型和 provider adapter 的原生附件能力共同决定；图片 MIME 可作为视觉输入发送，PDF 仅在 provider adapter 支持原生文件输入时发送，OpenRouter 和阿里云百炼支持音频/视频的模型按原生音视频 content part 发送，Office 文档仍不支持，除非 provider adapter 后续实现原生文件输入。
- 文件上传由共享输入区触发。
- 文件上传接口只负责保存资源并返回引用；是否参与某轮 AI 请求，由发送消息接口的 `context_resources` 决定。
- 前端提交文件上下文时只能提交 `resource_id` 和必要的引用类型。
- 文件路径、哈希、MIME 类型和大小以后端登记记录为准。
- 后端必须校验资源属于当前 `account` 和当前 `session_id`。
- 文件上传成功但用户未发送时，资源保持待使用状态，并设置过期清理规则。
- 过期或被清理的资源不得再被发送接口引用。
- 当前 `chat` 模型和 `vision_parse` 模型都不支持所附文件格式时，后端返回 `MODEL_FILE_UNSUPPORTED`，且不写入 `file_upload` 或 `user_message`。
- 当前模型元数据声称支持、但 provider adapter 不能原生转发该 MIME 时，后端返回 `MODEL_ATTACHMENT_UNSUPPORTED`，且不写入 `file_upload` 或 `user_message`。
- v0.1.0 当前代码完成文件资源登记、模型文件能力校验、视觉解析回退和时间线写入。发送时，若 `chat` 模型原生支持附件 MIME，后端直接转发给 `chat` 模型；若 `chat` 模型不支持但 `vision_parse` 模型支持，后端直接调用视觉解析模型并把附件作为原生输入发送，由 `vision_parse` 生成本轮回答；两者都不支持时拒绝上传或发送。
- 文件上下文只进入会话时间线和本轮 AI 上下文，不触发报告结构化字段抽取、指标入库或报告列表刷新。

### FR-CONV-004 历史消息引用

- 用户可从历史消息中选中文字作为本轮上下文引用。
- 前端提交历史消息引用时只提交被引用消息的 `message_id`、引用类型和选中文本。
- 后端必须校验被引用消息属于当前 `account` 和当前 `session_id`。
- 后端必须校验选中文本来自该消息内容。
- 刷新后仍能看到该引用关系。

### FR-CONV-005 会话历史与恢复

- 每轮消息都绑定当前 `account` 和 `session_id`。
- 每次用户提交需生成新的 `turn_id`。
- 左侧展示最近会话列表。
- 点击历史会话能恢复对应消息。
- 浏览器访问 `/chat/{session_id}` 时，应打开该会话并复用患者主工作台外壳。
- 刷新页面后能恢复最近会话。
- 仅上传上下文文件但尚未发送问题的草稿会话，不应出现在最近会话列表；发送第一条用户消息后才进入列表。
- 关闭页面或流式连接中断时，应通过轮次状态接口或会话详情恢复已完成内容或生成中状态。
- 快速切换会话或开启新对话时，前端应忽略已经过期的会话详情响应，避免旧响应覆盖当前会话。
- 同一会话中，若上一轮生成尚未完成，用户不得发起新一轮提交；用户可先停止当前生成，停止后允许继续发送或重新生成。
- 后端收到同一会话的并发请求时，应返回 `INVALID_REQUEST` 并提示当前会话有正在进行的生成任务；取消当前生成不视为并发请求。
- v0.1.0 不实现长会话自动压缩；`compact` 默认模型只在账号设置和数据库中预留，不触发真实压缩流程。当前代码也不做 token 级上下文窗口裁剪，后端按当前活动路径构造历史 user/assistant 文本发送给模型；若超出供应商上下文限制，由模型服务失败路径返回错误，前端仍可完整展示已落盘历史。

### FR-CONV-006 消息操作与分支

- 每条用户消息和助手消息底部展示操作按钮组。
- `复制`：复制该消息文本内容到剪贴板。
- 用户消息支持 `编辑重发`：保留原消息链，以原父节点追加新的用户消息，形成分支。
- 助手消息支持 `重新生成`：保留原回答，以同一用户消息追加新的助手回答，形成并列分支。
- 生成中的助手消息支持 `停止生成`：普通停止保留已展示半截回答并标记为已取消；生成中点击 `重新生成` 时丢弃当前半截回答并重新开始生成。
- 助手消息支持 `分支`：点击后，该助手回复之后的后续消息暂时从当前展示路径中隐藏，输入框聚焦等待用户输入新问题。
- 用户从分支起点发送新问题后，新消息的 `parent_message_id` 指向该助手回复。
- 存在分支时，前端在分支点消息下方展示分支切换控件：显示“当前序号/总分支数”，左右箭头可切换到相邻分支路径。
- 切换分支后，后端校验活动路径属于当前 `account` 和当前会话，且消息链路连续。
- 若消息链中存在 `thinking_process` 节点，前端分支控件按用户可见的逻辑消息路径统计分支。

### FR-CONV-007 删除会话

- 当前会话存在时，首页提供删除会话入口。
- 删除会话前端应清空当前会话详情、当前会话 ID、待上传资源、历史引用和分支起点状态。
- 后端删除会话索引、轮次记录、资源索引、会话 JSONL 时间线文件和该会话附件目录。
- 删除会话不删除已经创建的收藏快照。
- 删除后最近会话列表刷新。
- 收藏详情中若原会话已删除，仍展示收藏快照，但不展示返回原对话入口。

## 6. 输入提示边界

首页不展示快捷问题或示例提问按钮，也不主动给出“是否需要马上去医院”“药物副作用”“复查前注意事项”这类建议问题。输入框只承担用户 Markdown 源文本编辑职责；发送后的用户消息和模型输出在对话历史中按 Markdown 渲染。

## 7. 页面状态

| 状态 | 展示要求 |
| --- | --- |
| 空状态 | 展示欢迎文案，不展示快捷问题 |
| 输入中 | 可编辑输入框 |
| 文件待发送 | 展示待发送文件名称，可继续发送或清理 |
| 已添加历史引用 | 展示引用预览，并提供清除入口 |
| 发送中 | 展示加载态，禁止重复发送 |
| 回答成功 | 展示 AI 回答和消息操作入口 |
| 回答失败 | 展示错误提示和重试入口 |
| 回答已取消 | 展示已保存的半截回答和取消状态 |
| 分支起点已选定 | 展示提示，下一条消息将从选定历史节点分支 |
| 报告/生活占位 | 禁止真实发送；以占位标题和输入框 placeholder 展示未开放，文本输入禁用且附件入口隐藏 |
| 原始文件占位 | 展示占位状态，不录入正式文件 |
