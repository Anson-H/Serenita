# Serenita v0.1.0 账号设置需求文档

> 文档状态：当前执行 / 当前执行版本
>
> 所属索引：[v0.1.0 产品需求文档索引](./README.md)
>
> 对应技术设计：[账号设置技术设计](../technical/account-settings.md)

## 1. 目标

账号设置模块负责当前账号的可变资料、密码更新、模型服务配置和默认模型设置。用户完成该模块配置后，首页对话才能使用已添加的聊天模型发起真实问答。

本模块交付：

- 账号设置页 `/setting`
- `账号资料` 子模块
- `密码安全` 子模块
- `模型提供方` 子模块
- `默认模型` 子模块
- 修改用户名称
- 修改密码
- 配置 OpenRouter、深度求索、阿里云百炼
- 自动保存官网地址、API key 和 API 地址
- 测试连接
- 添加模型弹窗
- 添加、删除模型
- 设置默认聊天模型、标题生成模型、视觉解析模型和压缩上下文模型
- 密码与 API key 输入显示/隐藏控件

本模块不交付：

- 修改 `account`
- 账号注销
- 多用户管理后台
- 模型计费管理
- 设置页独立加载中占位
- 密码修改提交中的禁用防重复状态

## 2. 页面结构

账号设置从左下角账号按钮直接进入 `/setting` 页面，页面仍保留患者主工作台左侧主工作栏。

账号设置页内部包含一个左侧导航栏，用于在设置子模块之间切换；该内部导航只作用于账号设置页内部，不替代产品左侧主工作栏。

内部导航包含：

1. `账号资料`
2. `密码安全`
3. `模型提供方`
4. `默认模型`
5. `退出登录`

离开账号设置页后，当前登录态和左侧用户摘要应保持不变。

## 3. 账号资料与密码安全需求

### FR-SET-001 展示账号资料

- 展示当前 `account` 和 `user_name`。
- `account` 是登录凭证主键和账号私有目录名，v0.1.0 不支持修改。
- `account` 不提供可编辑输入框。

### FR-SET-002 修改用户名称

- 用户可修改 `user_name`。
- `user_name` 不能为空。
- `user_name` 不能包含空白字符。
- 用户名称输入短暂停顿后自动保存，不展示单独保存按钮。
- 修改成功后，左侧全局导航的当前登录用户摘要、会话恢复接口返回值和后续登录态中的用户名称都应更新。
- 保存失败时展示明确错误提示，并保留用户已输入内容。

### FR-SET-003 修改密码

- 修改密码时必须填写当前密码、新密码和确认新密码。
- 新密码不能为空。
- 确认密码必须与新密码完全一致。
- 当前密码必须能通过当前账号的 `password_hash` 校验。
- 密码不设置长度限制，不做复杂度要求，但不得明文保存。
- 密码修改成功后应给出明确反馈。
- 当前会话可继续保持，其它已登录会话应失效，避免旧设备继续使用旧凭证。
- 当前密码、新密码和确认新密码输入框应支持显示/隐藏切换。

## 4. 模型提供方需求

### FR-SET-004 模型提供方列表

- 支持的模型服务为 `OpenRouter`、`深度求索`、`阿里云百炼`。
- 当前 UI 中该模块名称为 `模型提供方`；模型提供方列表展示服务名称、连接测试图标状态和进入详情的箭头，不展示 API 地址。
- 后端接口仍返回 `configured` 和 `default` 字段作为数据状态；当前前端列表不单独展示 `default_provider` 标记。
- 未配置的模型服务也应展示，便于用户选择和配置。

### FR-SET-005 模型提供方表单

选择某个模型服务后，表单展示：

- 官网地址
- API 地址
- API key 输入框
- 已添加模型列表
- 添加模型按钮

账号设置页采用响应式设置布局：账号资料、密码安全和默认模型在非窄屏下使用设置入口加详情区两列，不渲染空的第二栏；模型提供方在非窄屏下保留设置入口、服务列表和详情区三列。`max-width: 650px` 时采用手机设置式逐级推进，根层展示 `账号资料`、`密码安全`、`模型提供方`、`默认模型` 和 `退出登录`，点击模型提供方后先进入服务列表，再进入具体服务详情；点击账号资料、密码安全或默认模型直接进入对应详情。模型提供方中栏只展示服务名称、连接测试图标和进入详情箭头，不展示 API 地址。模型提供方右栏按从上到下的顺序展示官网地址、API 地址、API key 和已添加模型列表；连接测试从服务列表行内图标触发，使用当前草稿 API 地址和 API key。

官网地址允许用户修改，用于访问充值、控制台或 API key 管理页面。官网地址输入后自动保存。

API 地址允许用户修改，用于兼容代理、自建兼容服务或供应商地址变化。API 地址输入后自动保存。

API key 要求：

- 用户自行输入 API key。
- 已保存的 API key 回填到输入框。
- 用户可直接编辑 API key，输入后自动保存并覆盖当前账号该模型服务的已保存值。
- API key 输入框应支持显示/隐藏切换。
- API key 不得写入前端本地持久化存储。

### FR-SET-006 测试连接

- 测试连接使用当前表单中的 API 地址和 API key 发起。
- 测试连接不持久化请求体中的临时 API key。
- 若请求体未提供 API key，但当前账号已保存过该模型服务 API key，后端可使用已保存密钥测试。
- 若两者都不存在，应提示用户先输入或保存 API key。
- 测试成功、认证失败、连接超时和模型服务错误都应展示明确反馈。

### FR-SET-007 获取和添加模型

- 模型提供方详情中的模型列表展示当前账号已添加模型，不直接展示远端全部模型。
- 用户点击 `添加模型` 后打开弹窗；弹窗必须使用当前账号已保存的 API 地址和 API key 真实请求远端模型服务。
- 后端请求远端模型服务时使用 `GET {API 地址}/models`，并通过 `Authorization: Bearer <API key>` 传递密钥。
- 未保存 API 地址或 API key 时，应提示用户先补全配置。
- 返回模型列表时应标记模型能力，包括文本、图片/文件理解、支持的文件 MIME 类型、推理强度、工具调用、JSON 输出和上下文/输出长度上限。
- 添加模型弹窗中的远端模型列表必须保持厂商返回顺序，前端不得重新排序。
- 用户可从真实远端模型列表中添加可用模型；每个远端模型右侧提供添加按钮。
- 用户添加模型时，系统应保存拆分后的能力字段。远端没有完整能力元数据时，后端按模型服务适配器和保守默认能力补齐。
- 当前前端添加模型成功后，若当前账号尚未设置 `chat` 默认模型，会自动把本次添加的模型设置为 `chat` 默认模型；已有 `chat` 默认模型时，新增模型不自动切换默认用途。
- 前端和后端不得在未成功调用远端模型列表接口时展示假模型列表。
- 用户可删除某个已添加模型；删除模型后，系统应清理或重新校验引用该模型的默认模型设置。
- 默认模型不在模型提供方详情中作为单一星标维护，而在一级设置 `默认模型` 中按用途维护。
- 模型服务配置、官网地址、API key、已添加模型和默认模型设置必须按当前 `account` 隔离。

## 5. 默认模型需求

### FR-SET-008 默认模型入口

- 账号设置一级导航包含 `默认模型`。
- 点击 `默认模型` 后，用户可分别设置默认聊天模型、标题生成模型、视觉解析模型和压缩上下文模型。
- 默认模型候选项来自当前账号已添加模型，不直接展示远端未添加模型。
- 默认模型设置必须按当前 `account` 隔离。

### FR-SET-009 默认模型用途

默认模型用途固定为：

| 用途 | key | v0.1.0 行为 |
| --- | --- | --- |
| 默认聊天模型 | `chat` | 首页真实发送的后端最终校验以该模型为准；首页模型弹层会把该模型置顶 |
| 标题生成模型 | `title` | 会话标题生成优先使用该模型；未设置时回退 `chat` 模型 |
| 视觉解析模型 | `vision_parse` | 当 `chat` 模型不能原生处理附件时，直接处理附件并生成本轮回答 |
| 压缩上下文模型 | `compact` | v0.1.0 只提供设置入口和数据库预留，不触发长会话压缩流程 |

- `chat` 是首页真实问答的默认模型；未设置可用 `chat` 默认模型时，即使当前账号已有其它已添加模型，发送消息时后端也返回 `MODEL_NOT_CONFIGURED`。
- 首页模型弹层当前会刷新并展示当前账号全部已添加模型，`chat` 默认模型置顶；前端推理强度随当前选中模型变化，附件按钮同时参考当前 `chat` 模型和 `vision_parse` 模型的文件能力。v0.1.0 后端上传和真实发送仍只接受 `chat` 默认模型作为请求模型，提交非 `chat` 默认模型会返回 `INVALID_REQUEST`。
- `title`、`vision_parse`、`compact` 可为空；为空时不阻断首页问答。
- `vision_parse` 只能从 `file_mime_types` 中包含图片 MIME 的视觉模型中选择；当 `chat` 模型不支持所附 MIME 而 `vision_parse` 支持时，系统直接调用视觉解析模型完成最终回答。
- `compact` 应优先选择文本能力稳定、上下文窗口较大的模型；v0.1.0 仅做设置和存储，不执行历史压缩。
- 删除已添加模型时，如果该模型被某个默认用途引用，系统应清空对应用途或要求用户重新选择；不得保留悬空引用。

## 6. 页面状态

| 状态 | 展示要求 |
| --- | --- |
| 账号资料可编辑 | 展示当前账号标识和用户名称表单 |
| 账号资料自动保存中 | 展示保存中状态，不阻断用户继续输入 |
| 账号资料自动保存失败 | 展示错误原因并保留用户已输入内容 |
| 修改密码成功 | 展示成功反馈并清空三个密码输入框 |
| 修改密码失败 | 展示当前密码错误或参数错误等明确原因 |
| 模型提供方未配置 | 展示官网地址、API 地址、API key 输入框和添加模型入口；连接测试由服务列表行内图标触发 |
| 模型提供方已配置 | 展示官网地址、API 地址、可编辑 API key 输入框和已添加模型管理入口 |
| 模型提供方加载失败 | 在模型提供方列表展示错误消息 |
| 模型提供方自动保存中 | 展示自动保存状态，不阻断用户继续输入 |
| 模型提供方自动保存失败 | 展示错误原因并保留用户已输入内容 |
| 测试连接中 | 禁用重复测试，连接测试图标展示测试状态 |
| 测试连接成功 | 连接测试图标切换成功状态并通过按钮提示展示反馈，短时间后复位 |
| 测试连接失败 | 连接测试图标切换失败状态并通过按钮提示展示错误，短时间后复位 |
| 添加模型弹窗加载中 | 展示加载状态 |
| 添加模型弹窗加载失败 | 展示错误原因和重试入口 |
| 添加模型弹窗加载成功 | 展示远端模型列表、已添加状态和添加入口 |
| 已添加模型为空 | 展示空状态和添加模型入口 |
| 默认模型无已添加模型 | 展示引导用户先前往模型提供方添加模型 |
| 默认聊天模型未设置 | 首页发送时展示模型配置引导或后端返回 `MODEL_NOT_CONFIGURED` |
| 默认模型自动保存中 | 展示保存中状态，不阻断用户继续查看其它用途 |
| 默认模型自动保存失败 | 展示错误原因，并保留用户当前选择状态 |

## 7. 接口范围

| 接口 | 说明 |
| --- | --- |
| `PATCH /api/auth/account` | 修改当前账号资料 |
| `PATCH /api/auth/password` | 修改当前账号密码 |
| `GET /api/model-providers` | 获取模型服务配置 |
| `POST /api/model-providers` | 自动保存模型服务配置 |
| `PATCH /api/model-providers/{provider_id}` | 更新模型服务配置 |
| `POST /api/model-providers/{provider_id}/test` | 测试模型服务连接 |
| `GET /api/model-providers/{provider_id}/models` | 获取模型服务的模型列表 |
| `POST /api/models` | 添加可用模型 |
| `GET /api/models` | 获取已添加模型 |
| `DELETE /api/models/{model_id}` | 删除已添加模型 |
| `GET /api/model-defaults` | 获取默认模型用途设置 |
| `PATCH /api/model-defaults` | 批量更新默认模型用途设置 |

详细请求、响应和错误码见 [technical/account-settings.md](../technical/account-settings.md)。
