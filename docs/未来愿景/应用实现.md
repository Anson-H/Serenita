## 从用户目标确定范围

每次选取一个可以独立说明和验收的用户目标，例如“持续同步某位成员的手机健康数据”或“整理一次就医经过”。先明确输入、可见结果、证据、授权和失败处理，再定义具体接口与数据结构。

当前开发命令、配置和路由分别见[后端入口](../../backend/README.md)、[前端入口](../../frontend/README.md)与 [HTTP 接口](../当前执行/接口/HTTP接口.md)。本目录不提供另一套可执行骨架。

## 候选能力与前提

| 候选能力 | 需要解决的工程问题 | 进入版本时的验证重点 |
| --- | --- | --- |
| 手机健康同步 | 平台授权、增量游标、来源优先级和撤权 | 数据可追溯，重叠区间与删除传播正确 |
| 健康日记与长期记忆 | 健康日记沿用领域 CRUD；长期记忆以 Append-only Record 保存新 Event、关系、状态与派生认识 | 旧记忆及派生内容不可改写，当前 Projection 与历史读取正确，访问限制及时生效 |
| 趋势与就医摘要 | 查询范围、缺失数据、来源定位 | 每项展示有依据，摘要覆盖范围可核对 |
| 提醒与持续任务 | 调度、时区、权限变化、取消和通知 | 不重复产生副作用，取消与撤权及时生效 |
| 主动推荐 | 持续关注授权、新资料与定时触发、记忆召回、建议依据、用户反馈和结果跟踪 | 能发现未被逐项提问的相关问题；建议有依据，资料不足时表达缺口；无新内容时可结束检查；通知频率与免打扰设置生效 |
| 设备接入 | 平台授权、同步、重复记录与断连 | 数据来自真实服务，来源与更新时间可核对 |
| 分享与导出 | 资料选择、接收范围、有效期与撤销 | 不越权包含其它成员资料，导出边界清楚 |
| 多智能体协作 | 委派、证据返回、预算和写入协调 | 相比现有行动循环存在可测收益，失败可追溯 |

## 能力接入方式

为领域增加智能体能力时，Skill 目录描述只说明适用任务和能力范围，Skill 正文承载判断规则、取证和完成标准。工具顶层描述说明能力与高层返回效果，工具参数 Schema 完整说明准确约束。

每次工具调用返回真实工具结果，形成 Observation 并回到动态行动循环。Service 和 Repository 负责权限、事务和存储一致性。页面手工操作使用普通 HTTP API。

不通过新接口预先生成业务步骤，也不在数据接入层根据附件类型替模型决定完整任务流程。

主动推荐沿用同一行动循环。应用交付新资料到达或定期检查的触发事实，模型根据持续关注范围自主召回记忆、核对证据并决定建议。应用根据结果及通知设置确定性投递；用户采纳、拒绝、纠正和实际执行分别记录，供后续任务判断。具体事件交付、建议标识、重复判断及结果关联规则在进入当前执行时确定。

## 数据生命周期

业务记录应有明确的成员归属、来源、更新和删除规则。未来独立记忆存储遵循[Append-only 规则](长期记忆与认知架构.md#append-only全部记忆只允许追加)：全部已提交记录、关系、状态、索引和派生内容只追加；来源删除、成员删除、撤权或停止使用通过追加记录及实时访问限制作用于查询，不能清空对应记忆历史。健康档案授权变化及关联业务文件清理仍按业务契约处理。

添加数据库保持单一 Python 定义，并同步 Repository、Service、HTTP API、工具参数 Schema、前端类型与当前文档。跨数据库、会话 JSONL 和文件关系由明确的应用事务及存储规则保证。

本地开发账号、模型与联网配置及配套密钥按项目规则保留。运行时只接受当前契约，不通过启动扫描转换历史数据。

## 进入当前执行

候选能力确定后，将用户目标和产品验收纳入当前产品需求，再把准确规则写入对应领域、架构、接口、前端和运维专题。未来愿景只保留后续增量并链接当前契约。

实现后的验证应覆盖真实能力、证据与授权、数据一致性、失败反馈和用户操作。涉及性能或质量的结论应保留测量依据，不用演示成功代替真实验收。
