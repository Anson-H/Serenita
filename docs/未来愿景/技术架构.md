# Serenita 未来愿景：技术架构

> 文档状态：未来愿景 / 不绑定版本
>
> 负责：未来能力的架构约束、技术选项和评估问题。
>
> 当前依据：[技术架构总览](../当前执行/架构/技术架构总览.md)、[智能体运行时](../当前执行/架构/智能体运行时.md)。

## 扩展基础

未来领域能力沿用通用 Agent Harness。系统提示词提供全局边界，技能正文提供领域知识和执行要求，工具提供可组合能力；工具观测回到行动循环，由模型决定后续行动。

身体指标、医疗日志或用药记录可以新增自己的技能、工具、Service 和 Repository。页面手工操作沿用 API → Service → Repository；会话智能体写入沿用工具 → Service → Repository。

账号身份和成员身份继续使用当前契约。新增资料类型要明确健康档案归属、操作者权限和删除行为，不能因接入新的数据源而另建一套患者身份。

## 数据与证据

未来可探索结构化健康记录、时间序列查询和跨资料检索。每种能力先定义事实来源、时间、可比性、冲突处理和可追溯方式，再决定存储与索引。

统计、排序、去重校验和数值计算可由确定性工具提供；医学解释由模型在证据与安全边界内完成。聚合结果需要说明覆盖范围、缺失情况和计算方式，并允许按需读取支持当前判断的原始证据。

检索索引和摘要可以提高定位效率。摘要不是原始证据，检索命中也不能替代需要实际读取的来源原文。

## 长期资料与记忆

长期记忆需要明确保存授权、依据、适用时间、修正和删除机制。会话历史、用户确认的健康事实与模型整理内容各自承担不同职责。

新增领域存储沿用当前成员生命周期与授权机制，显式定义跨数据库和文件的关系。数据库定义、字段名和事务边界进入对应当前契约后统一维护，不在愿景中预设另一套 SQL 或文件目录。

## 持续任务

可以探索一个通用调度能力，为明确授权的任务提供唤醒、暂停、取消、重试边界和执行记录。

调度器只决定何时尝试运行，任务内部仍进入动态行动循环。每次运行重新校验账号、成员、资料权限和任务有效性；授权变化后不能继续使用先前权限。

对已经可能产生副作用但结果未知的操作，需要核对真实状态再决定处理方式。通知是否发送、发送给谁和发送哪些内容，也需要独立授权与可追溯结果。

## 多智能体协作

多智能体协作是待验证选项。只有在任务质量、耗时或资源利用有明确收益时，才值得引入。

如开展探索，应由主智能体根据任务动态决定是否委派，子智能体返回证据、不确定性和真实执行结果，供主智能体继续判断。权限、资源预算、取消、并发写入和最终回答责任需要统一约束。

领域专业知识优先通过技能表达。不能按页面、关键词或附件类型固定分发给若干专家，也不能以多数意见替代证据核对。独立子会话并不等于已经具备多智能体协作。

## 资源预算与可靠性

上下文预算根据当前模型能力、输入内容和输出预留计算。大规模记录可以分页、检索或聚合；具体方式应保留任务所需证据，超出处理能力时返回真实限制。

写入幂等性由操作标识、事务和业务约束保证，不能依赖模型重复生成相同文本。降低采样随机性不能作为数据库幂等保障。

失败应保留真实错误。演示样例只用于明确隔离的展示或测试，不能在真实任务失败时充当成功结果。

## 基础设施选项

当前存储与运行方式以[本地存储](../当前执行/运维/本地存储.md)和开发入口为准。未来选型按需要评估：

| 选项 | 值得评估的条件 | 需要回答的问题 |
| --- | --- | --- |
| 服务型关系数据库 | 当前部署或并发需求已超出现有存储适用范围 | 事务、权限、运维和成本是否有实际收益 |
| 时间序列存储 | 连续设备数据的规模和查询已形成明确需求 | 保留周期、降采样及原始数据追溯如何处理 |
| 全文或向量检索 | 资料量使现有定位方式不足 | 检索质量、成员隔离、来源定位和删除同步如何验证 |
| 图关系存储 | 有具体的关系查询需求且现有方案不足 | 关系依据、更新和错误纠正如何维护 |
| 容器与独立任务服务 | 部署隔离或持续任务需要独立生命周期 | 增加的运维复杂度是否合理 |

选择新技术时直接形成新的唯一执行契约；不为尚未发布的旧方案增加兼容层或自动迁移流程。

## 评估方式

未来实验应记录任务样本、模型与配置、输入规模、运行环境、测量时间和失败情况。分别观察完成质量、证据准确性、授权遵循、耗时、费用及中断恢复。

性能目标需要结合真实场景制定。未经测量的延迟、可用性和压缩率只可作为待验证假设，不能写成已达标结果。
