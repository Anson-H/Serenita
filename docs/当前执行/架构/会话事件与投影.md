# 会话事件与投影契约

> 文档层级：当前执行 / 架构协议
>
> 负责：会话事件语义、追加顺序、Provider 输入溯源、线性投影、压缩和独立子会话的事件关系。
>
> 不负责：JSONL 逐行编码和损坏恢复、轮次 Worker 与队列策略、领域工具规则、页面布局、HTTP 路由清单或物理存储总览。
>
> 上位文档：[技术架构总览](技术架构总览.md)；运行语义见 [Agent Harness](智能体运行时.md)，准确 JSONL header、信封和最低字段见[会话 JSONL 格式](../运维/会话JSONL格式.md)，物理路径见[本地存储](../运维/本地存储.md)，SQLite 表和键见[数据库结构](../运维/数据库结构.md)，页面展示见[前端行为](../前端/行为与交互.md)。

会话内容可信源是只追加的 `SessionEvent`，当前会话契约统一采用版本 2 身份与事件格式。会话详情、当前线性模型上下文和 SSE 都从同一事件日志投影；SQLite 中的 session/turn/resource 表维护索引和运行状态。

会话索引保存可空目标 `member_id`，不保存成员名称快照；成员删除后清空关联，不逐行重复操作者 `account_id`。认证上下文和 `accounts/{account_id}` 私有目录共同确定操作账号；账号资料更新后仍指向相同会话目录和成员，日志与附件始终属于操作者。可信成员资料与健康档案权限随实际 Provider payload 持久化，并从同一 payload 切片溯源。历史事件中的成员身份及名称保持原样，不恢复当前关联或授权。

会话列表、详情和顶层命令使用当前认证 `account_id` 打开对应账号私有 `conversations.db`，再通过 `session_id` 访问轮次、资源和附件清理队列，并定位 JSONL 事件日志。JSONL header、调用身份与账号目录共同表达同一账号作用域；SQLite 会话索引不逐行重复该账号字段。

每个日志以唯一的版本 2 header 开始，事件 payload 不重复保存 `session_id`，归属只由 header 和外部会话作用域决定。存储接口通过一次 `create(header, seed)` 创建 JSONL，一次落盘 header 与全部 seed。准确字段、类型、分叉 header 和非当前版本拒绝规则只在[会话 JSONL 格式](../运维/会话JSONL格式.md)维护。

## 事件角色与类型

等候输入使用 `input/queued`、`input/queue-reordered` 和 `input/queue-removed`；它们只参与队列投影，不进入正文或模型上下文。提升时追加 `turn/start` 与 `user/message`。因调整方向结束的 `turn/end.reason.kind="steered"` 投影为取消并保留正文。SSE 文本增量包含绝对 UTF-16 `offset`，可幂等重放到已有详情快照。

当前 23 种事件分为：等候输入，轮次与步骤，用户与助手消息，模型请求与结果，工具调用与结果，工具观测，资源、工作流及上下文压缩。准确类型清单、封闭信封和每种事件的最低 `data` 字段只在[会话 JSONL 格式](../运维/会话JSONL格式.md#23-种事件的最低-data-格式)维护。

`seq` 表示会话内唯一顺序，`sourceEventSeqs` 表示该记录由哪些更早事件派生，`surfaceOp` 表示它对当前线性模型表面的追加或遮蔽；这些字段的结构校验不代替跨事件的业务关系校验。`turn/thinking_mode_changed` 只在当前轮次实际使用的推理模式不同于用户请求时追加，保存请求模式、有效模式与能力不足原因；它通过独立 SSE 事件同步输入区，但不伪装成执行时间线记录。

`assistant/message` 的 `content` 可以为 `null`，并可带 OpenAI-compatible `tool_calls`。`tool/result` 必须以 `tool_call_id` 对应先前的 assistant tool call，并保存结构化 result、status 和安全错误。工具业务 output 中两个及以上键集合相同的对象数组使用 `$keys`/`$rows` 无损列式编码；`$keys` 必须保持工具逻辑输出中第一条对象的字段顺序，不按字母或其它规则重排，`effects` 等控制元数据不参与编码。时间线、SSE 与后续模型请求共享这一编码形态；工具观测引用解析、压缩保留等需要结构访问的确定性消费者先调用 `decode_tabular_json` 还原。`harness/observation` 独立保存原始工具观测、错误、关联 step/call、状态和时间；模型历史把它转换为工具观测消息，不能伪装成持久化用户消息。`request/header.header.provider_payload` 保存去除凭证和附件二进制后的最终 Provider payload，是唯一持久化模型输入；header 只额外保存模型标识、该次请求的完整 `context_window_tokens` 快照、thinking mode、transport mode、模型运行配置和父调用标识，不复制 system、messages、tools、tool choice 或 normalized request。模型记录以及 `record_started`、`record_completed` SSE 投影同一窗口快照，用于在刷新与实时流中计算最近一次真实会话模型调用的上下文占用。会话详情不直接展示完整 `provider_payload`，也不展示由 `provider_message_metadata` 或 `provider_parameter` 表示的系统消息字段和 Provider 顶层参数；这些记录继续持久化并参与来源覆盖校验。

所有直接工具和技能授权工具使用同一事件契约。工具返回的完整业务结果、供应商明确报告的单项失败和 usage 可以进入 `tool/result`、工具观测、SSE 重放及后续模型上下文；Harness 不为适配上下文预算持久化截断版或部分成功版工具结果。无法完整容纳时，预算失败事件携带已经取得的完整结果用于审计，模型可读投影只包含安全错误；完整结果不能随错误再次进入模型请求，也不能作为部分成功结果展示。预算失败不抹除工具已经执行及可能已产生业务效果的事实。凭证不属于工具业务结果，也不得出现在事件或安全 `provider_payload`。公网研究的内容与引用规则见[公网研究领域契约](../领域/公网研究.md)。

## 轮次事件顺序

输入提升后先持久化 turn 和 user 事件；Worker 领取与队列语义见 [Agent Harness](智能体运行时.md#轮次-worker-与等候队列)。每次模型调用只准备一次 Provider transport request 与最终 payload，事件日志和网络发送复用该对象，不存在独立快照。事件严格按 `step/start → request/context* → request/header → assistant/chunk* → model/result → step/end` 追加。

`request/context.context.provider_source` 使用 RFC 6901 JSON Pointer 和可选的 Unicode 左闭右开字符区间定位同一个持久化 `provider_payload`；所有切片必须逐值相等并完整覆盖 payload，未知字段使用通用标签而不丢弃。上下文顺序为系统指令、工具协议或目录、技能目录、运行时内容、按 Provider 索引排列的非系统消息、其余顶层参数。

`update_plan` 只写入普通 `tool/call` 和 `tool/result`。`load_skill` 的完整正文只存在于真实工具结果；当该工具观测实际进入下一次 Provider message 时，按普通 `tool_observation` 投影，不产生技能专用事件、上下文类别、激活或完成状态。能力目录显示为“`N 个可用 Tool`”和“`N 个可用 Skill`”，工具在技能之前。每个行动、压缩和工具内部模型调用都有独立递增 step；工具失败也必须有真实 `tool/result`。技能恢复与可见性规则由 [Agent Harness](智能体运行时.md#load_skill)定义。

Worker 更新持久化心跳。租约过期或进程恢复时，开放工具生成带原 `tool_call_id` 的 `TOOL_OUTCOME_UNKNOWN` result，开放 step 和 turn 随后关闭；可能已经产生副作用的调用不会自动重试。SSE 以 `(session_id, stream_id)` 持续追尾并重放这些持久化记录，不启动 Worker；任务运行期间一旦有新记录就立即推送，重复连接会重放当前完整记录并继续跟随到相同终态。

## 记录与传输

会话详情和 `record_started`、`record_completed` 使用同一个记录投影函数。开始事件在完整记录字段上清空待增量传输的正文并标记执行中，完成事件补齐最终值；前端以判别类型处理记录和增量。事件名称、记录标识、排序、UTF-16 偏移、标题更新及重连语义保持统一。

后台执行不生成无人订阅的 SSE，也不额外查询或回放记录。事件写入、取消检查、失败记录和终态维护仍由执行任务完成；HTTP 订阅只观察已持久化结果。

## 投影与展示

取消或恢复先记录 `TOOL_OUTCOME_UNKNOWN` 后，若原调用的真实结果已经取得，允许追加一条 `tool/result` 精确替换该未知结果；其最低字段和来源校验唯一维护在[会话 JSONL 格式](../运维/会话JSONL格式.md)。模型表面在原未知结果位置显示同一调用的真实结果，来源序号改为新事件序号，不在日志尾部另追加第二条模型可读工具结果。引用旧未知结果的 checkpoint 及其后续连续摘要随来源失效，不能继续把未知结果当成当前事实。目标不满足精确替换条件或来源不可用时，不将替换事件追加成无对应调用的工具消息；原始未知结果与收尾事件均保留供审计。

页面记录判别类型为 `user | assistant | error | context | model | observation | tool`。不存在 `plan` 记录；`update_plan` 只投影为普通的模型工具调用请求和工具结果。`model` 再以平级 `channel` 区分 `input | reasoning | content | raw_output | tool_request | result`；每个真实模型工具调用请求独占一条记录，并通过 `tool_call_id` 与平级工具调用对应，不通过视觉嵌套表达。文本通道（`reasoning`、`content`、`raw_output`）在流式输出切换到其他通道时追加 `channel-end` chunk 记录该通道的结束与耗时，投影随即将对应记录标记为完成并显示耗时，不再等待同一模型调用的其余通道结束；若同一通道之后又有新 delta，记录重新打开直至 `model/result`。非完成、取消或主动中止的 `turn/end` 原因投影为 `error`，页面直接显示持久化失败信息。会话按事件顺序形成确定性线性视图；编辑或重新生成追加一个带 `supersedes_turn_id` 的替代轮次，旧尝试继续留在原始日志，但页面和后续模型请求只投影当前尝试。模型历史包含当前线性视图的 user、assistant、assistant tool calls、tool results 和工具观测消息；UI 投影把 `harness/observation` 显示成独立 `observation` 记录。

压缩状态使用 `compaction/status` 持久事件投影为 `context` 记录：`context_type="compaction_status"`、`purpose="context_compaction"`、`label="上下文压缩"`。同一次操作使用相同 `record_id`，从 `running` 原位更新为 `completed` 或 `failed`；状态记录先于该操作的全部分块模型调用，投影更新保持首次出现的位置。状态、估算词元字段与安全错误通过详情和 SSE 返回一致的值。checkpoint 通过 `compaction_id` 关联该操作的状态事件 `message_id`；已持久化的有效 checkpoint 就是操作完成依据。即使后续 completed 状态行因崩溃未完整写入或损坏，投影仍根据保留的有效 checkpoint 将同一操作恢复为 `completed`，采用其压缩前后估算值和目标值，并清除失败错误；单个分块模型成功不代表压缩提交成功。此规则不改变 JSONL 的损坏恢复边界，也不允许从无效 checkpoint 推断完成。

状态记录默认可见，不受上下文装配或工具显示偏好控制；每次操作只有一条状态栏，展开后可检查该状态记录至下一条压缩状态记录之间、同一轮次的 `purpose="context_compaction"` 模型输出与结果。分块模型记录继续真实持久化并参与原有词元汇总，不单独生成压缩活动卡，也不投影为最终回答或可注释的过程正文。完整模型输入继续隐藏；checkpoint 和后续请求中的 `compacted_summary` 正文仍由输入追溯偏好控制。

普通 API 与 SSE 返回同一批已持久化记录。前端按真实事件顺序平级展示可见记录，但过滤完整 `model.input`、`model.result`、`provider_message_metadata` 和 `provider_parameter`；这些隐藏记录仍用于溯源、状态和按轮次汇总 Token。原生模型工具调用请求的 `value` 直接取持久化 `model/result.tool_calls[index].function`，文本工具协议的 `value` 直接取持久化 `raw_content`；前端不拼接、解析、格式化或补充请求字段。文本协议未产生模型工具调用请求时，`raw_content` 进入独立 `raw_output` 记录；产生模型工具调用请求时合并到该调用，不重复展示服务端解析值。工具结果区优先按 `tool_call_id` 查找后续 `request/context` 中来自真实 `provider_payload` 的工具观测消息，并只显示模型可读 `content`；原生协议的 role、name 与路由 ID 外层不显示，文本协议位于 `content` 内的可读封装保留。尚未产生下一次请求时，页面即时回退到 `tool/result.result` 将进入模型消息的完整逻辑工具观测或安全错误，禁止从 workflow payload 或默认字典补造。模型结束记录保留 status、usage、stop reason、error 和 duration，但不生成可见时间线记录。成功的 `update_plan` 只保留标准工具调用/工具结果，不生成计划状态块或其它专用投影。终态 `model/content` 继续持久化并通过同一轮次的正式 assistant surface 展示，不在根执行折叠中重复投影；同一轮次全部模型结束记录的可用 usage 在最终回答下汇总为输入、输出及供应商提供的文本、图像、缓存命中和推理 Token 明细。API Key、登录凭证、Cookie 和附件二进制不写入会话事件。

会话标题生成属于会话索引元数据，不属于 智能体轮次的执行事件。首次消息只有附件时可以先使用附件名生成临时标题，随后只向界面发送最终标题更新；标题提示词、标题模型 thinking/reasoning 和原始输出不写入会话详情事件。

## 上下文压缩

### 预算与选择范围

输入预算为行动模型的 `context_window_tokens - reserved_output_tokens`，估算必须使用将要发送的完整请求结构，包含系统提示词、技能与工具目录、附件及完整工具结果。达到输入预算的 80% 时自动触发，目标为输入预算的 60%。从近期向前按完整行动组选择约占输入预算 16% 的保留区，不能拆开模型工具调用请求及其全部工具结果、工具观测。当前用户输入、未完成工具组和最近一个完整行动组始终受保护，保护要求优先于比例目标；不能因目标不可达删除受保护内容。

`status="interrupted"` 且 `error.code="TOOL_OUTCOME_UNKNOWN"` 的工具结果仍表示执行结果未知；内部模型表面投影为它设置 `_pending_execution=true`，压缩选择必须保护所在的整个工具协议组，包括模型工具调用请求及对应结果和工具观测。已有中断结果或轮次终态不能把这一组视为已经完成。该标记仅供内部选择使用，不进入 Provider payload；原调用的真实结果通过精确 replace 收尾后，依据新结果重新确定保护状态。

压缩范围可以包含已结束轮次和当前轮次的早期完整行动组，也可以包含已有 checkpoint，以支持单个长任务和连续摘要。选择依据是当前可见模型表面，不能仅按轮次数量或连续事件区间决定删除范围。

### 三层上下文与摘要类型

聊天内容由历史摘要、轮次前半段摘要、近期原文组成。先选择近期完整行动组，再按模型表面的实际顺序判断切分位置；替换事件的追加序号不能代替表面顺序。选中记录的末尾所在轮次若还有保留的后续步骤，就把该轮次本次选中的早期步骤单独生成轮次前半段摘要，其余选中记录生成历史摘要；切在轮次之间时只生成历史摘要。当前用户请求始终保留原文，可额外作为摘要模型理解原始请求的参考，标记 `preserved_original_request=true`，不能加入 checkpoint 的替换来源。

三套摘要提示词采用 Pi 对应提示词的中文输出格式。首次和更新历史摘要均使用二级标题：目标、限制与偏好、进度、关键决策、下一步、关键上下文；进度下使用三级标题已完成、进行中、受阻。已完成使用 `- [x]`，进行中使用 `- [ ]`，关键决策使用 `- **决策**：简要原因`，下一步使用有序列表，其余条目使用无序列表，目标使用段落。没有内容时写“无”。医疗数值、单位、日期及来源关系继续受共用保真要求保护，纳入关键上下文等相关栏目。

已有摘要时使用更新提示词，整合旧摘要和新纳入的历史，更新完成状态、清除失效信息、保留有效限制。上次完整摘要（含其轮次前半段）参与这次历史摘要更新；即使没有新增更早轮次的记录，也要整合旧摘要。轮次前半段使用独立提示词，按二级标题原始请求、早期进展、后续步骤所需背景组织；原始请求使用段落，另两项使用无序列表。没有历史和旧摘要时跳过历史层，没有被切开的轮次前半段时跳过该层。

两层分别生成，以固定一级标题 `历史摘要` 和 `轮次前半段摘要` 拼接成一个 `summary`，不存在的层省略；程序不解析摘要正文判断轮次归属，不新增每层所属轮次的持久字段。连续分块只累计更新所在层，历史首块无旧摘要时使用首次提示词，后续块使用更新提示词；前半段各块始终使用前半段提示词。摘要只记录用户任务进度，不把摘要生成本身记成任务完成，分块边界也不表示原始证据缺失。

系统提示词、技能目录、当前权限允许的工具参数结构及运行时资料在行动请求装配时完整提供并计入预算。技能正文作为 `load_skill` 工具结果参与历史选择；其成功工具结果退出上下文后，技能与相应工具退出可用列表，需要时重新读取。摘要中的名称不能恢复技能正文或工具权限。

### 精确替换与证据保留

摘要以 user 角色的 `<compacted-summary>` checkpoint 进入模型上下文。事件内部的 `source_event_seqs`（JSONL 信封中的 `sourceEventSeqs`）精确列举要替换的原消息、工具消息、工具观测和旧 checkpoint 事件；它是替换依据。`surfaceOp=replace` 的区间只定位覆盖范围，不按区间或 `replaced_turn_ids` 删除整轮，也不把中间未选事件一起遮蔽。连续压缩同时替换被纳入摘要的旧 checkpoint，避免重复摘要和旧内容重新出现；原始 JSONL 事件只追加并继续供审计。

checkpoint 分别保存独立摘要 `summary` 和完整模型消息 `content`。后续连续摘要读取 `summary`；`content` 完整包裹该摘要以及必须精确保留的内容，供行动模型使用。再次压缩时独立处理摘要与精确保留内容，不能把整个 `content` 当成摘要再次生成，导致附件原文或未处置内容被改写、遗漏或重复包裹。字段的必填和关联规则见[会话 JSONL 格式](../运维/会话JSONL格式.md#上下文压缩)。

附件原文在连续压缩后持续完整保留，按资源身份去重；摘要中的附件描述不能替代原文。工具结果中的 `context_retention` 尚未处置内容按原值精确保留，处置判断只依据真实工具结果，不能由摘要自由改写或推断完成。包含无损列式编码的结果先解码再访问结构。每次提交后按仍可见的成功 `load_skill` 工具观测重新计算技能及关联工具可见性；摘要提到技能名称不等于已读取技能正文。

### 摘要、取消与提交

使用账号配置的专用 `compact` 模型，各层按其输入预算分块并逐步形成连续摘要；每次请求包含摘要所需指令和材料，并预留输出预算。不能让压缩模型自身请求溢出。每个实际调用使用 `purpose="context_compaction"` 保存模型请求、结果、状态和真实 usage，并以 `summary_kind="history"/"turn_prefix"` 标记摘要类型。模型记录从请求头取得该标记，详情和 SSE 一致返回，压缩状态展开后显示对应类型和模型结果。

两层全部成功后才重建完整行动请求并验证缩减及 60% 目标。未达标最多执行一轮分层收紧，每个非空层独立收紧后再次组装验证。空白、截断、工具调用或无效停止原因产生的摘要不得提交；任一层、任一分块或收紧阶段失败均不提交部分 checkpoint，按原有硬预算与普通失败规则处理。一个分块或一个层成功不代表整次压缩已完成。

压缩开始取得会话与当前模型表面的快照，模型网络等待不持有会话锁；取消信号贯穿分块调用。提交在同一会话锁内核对取消状态、当前轮次、可见来源及快照版本，以 CAS 追加 checkpoint；取消、快照失效或竞争导致校验失败时不追加有效 checkpoint，迟到结果不能覆盖新状态。压缩状态事件及模型审计事件的追加应纳入预期 revision，不能被误判为外部竞争。

同一次待提交摘要的上下文装配固定使用开始时取得的 clock；候选装配、预算估算和提交核对使用同一时间值，避免单纯时间推进造成快照失效。成员及资源等动态权限仍在使用和提交时重新查询，固定 clock 不冻结授权。Service 提供的上下文发生变化时，丢弃该次待提交摘要，最多基于新上下文重新评估一次；重新评估期间仍持续变化则停止压缩，不继续重试。取消或权限失效按相应边界停止，不能借重新评估继续执行。

模型明确报告上下文溢出时，对该次失败的行动模型请求最多进行一次强制压缩并重试。已经执行的工具及完整结果复用，不重新执行工具；其它错误不触发此路径，重试仍失败时返回真实失败。没有有效可压缩范围时不能无限重试或静默截断。

完整工具结果在判定 `TOOL_RESULT_TOO_LARGE` 前参与下一请求预算估算，并先尝试压缩既有可压缩上下文；压缩后重新装配和估算，仍不能完整容纳才记录超限失败。尚未完成的工具组受保护，不能为了容纳结果拆散调用关系。公网分页结果的完整性规则见[公网研究](../领域/公网研究.md)。

压缩估算只用于状态展示与预算控制。同一轮次全部压缩分块的真实 usage 各计入词元统计一次；输入区占用仍只使用最近一次有效 `purpose="agent_action"` 模型结果和该次窗口快照，不使用压缩估算或压缩模型 usage 替换。

## 事件持久化

会话事件只使用 JSONL 持久化，每个会话对应一个只追加日志。存储能力包括 create、append、load、增量读取、list、delete、revision 与内部 CAS replace；锁、逐行提交、fsync 与断尾恢复边界见[会话 JSONL 格式](../运维/会话JSONL格式.md#写入锁与耐久性)，具体文件与数据库位置只在[本地存储](../运维/本地存储.md)维护。

新会话写入版本 2 header，其中 `accountId` 是不可变账号身份。当前产品执行路径追加事件；`surfaceOp=replace` 只改变投影，原始事件继续保留。用户标识与显示名称从认证账号投影，因此账号资料更新后，header 仍指向同一 `account_id`。

## 独立子会话与资源

`POST /api/conversations/{session_id}/fork` 只在已结束轮次的稳定边界创建新会话。服务复制边界后的下一个 `turn/start` 之前的完整事件前缀作为 seed；开放轮次不可截断。父子会话在列表中同级显示，子会话通过 header 与索引中的 `parent_session_id/seed_event_count` 保留血缘。子会话后续事件只追加到自己的日志，父会话边界后的事件不会进入子会话上下文。

父子 seed 是完整事件前缀复制，保留原事件的 seq、time、turn、message 和 resource ID；这些 ID 必须始终按会话作用域解释。准确 header 表示见[会话 JSONL 格式](../运维/会话JSONL格式.md#分叉替换与删除)，复合主键见[数据库结构](../运维/数据库结构.md#conversationsdb)。附件引用与物理清理规则见[本地存储](../运维/本地存储.md)；删除父会话不级联删除子会话。

`parent_session_id` 只记录血缘，不使用外键：父会话允许先删除，子会话仍可独立存在。轮次中的消息 ID 指向同一会话 JSONL 中的事件，由事件追加和投影代码核对；附件清理队列中的资源 ID 也允许在资源记录删除后继续保留，直到对应文件处理完成。

## 实现边界

模型历史与已读取技能可见性由 `model_history.py` 派生；时间线记录与增量更新统一由 `conversation_timeline.py` 实现；详情和 SSE 的字段呈现共用 `conversation_presenter.py`。`session_activity.py` 归约未结束的步骤、模型请求和工具调用，运行取消与 `storage/session_recovery.py` 分别决定收尾记录，事件格式检查仍归 `session_events.py`。

`ConversationCompaction` 通过 Harness 的 `rebuild_request` 重建当前授权上下文，通过模型网关的 `prepare_transport_request` 估算实际协议请求；预算算法由通用运行时负责。`ModelCallRecorder` 取得一次准备的 `PreparedProviderRequest`，将同源 payload 交给 `ModelRequestAudit` 生成安全审计记录并用于真实发送。网络等待不持有会话锁，提交时继续核对授权、取消和快照。
