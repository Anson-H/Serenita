> 文档层级：当前执行 / 架构入口
>
> 当前版本：v0.2.0
>
> 负责：系统组成、分层职责、跨领域不变量和下位契约导航。
>

## 系统结构

v0.2.0 同时交付报告领域、统一 Harness Agent 和可选联网研究能力。所有用户消息进入同一个通用行动循环；报告能力作为插件提供技能、工具、Service 和资源解析器，Web 插件只提供直接只读工具。两者都不由独立领域智能体、硬编码意图路由或固定业务状态机执行。

```text
HTTP 消息提交
  → 持久化当前轮次、用户消息与资源引用
  → 独立智能体轮次 Worker 领取任务
  → 行动模型读取当前上下文并生成正文或工具调用
  → Harness 校验并执行控制工具、直接工具或技能授权工具
  → 工具结果与独立工具观测回到模型上下文
  → 模型自主继续行动、询问用户或输出终态正文
  → 会话事件持久化；API 与 SSE 使用同一投影
```

架构提供能力、证据和安全边界。会话中的报告导入、解读、查询、更新与删除由模型根据技能和工具观测自主决定，不按页面、附件类型、关键词或特殊 Python 分支固定行动顺序。报告页面只有“上传报告”“开始解读”和“重新解读”进入 Harness；手工录入、查询、字段编辑、原件管理和删除等明确页面操作经 HTTP API → Service → Repository 执行。详细入口范围见[前后端职责边界](../接口/前后端职责边界.md#报告边界)。

## 分层职责

| 层级 | 职责 | 不负责 |
| --- | --- | --- |
| 主行动模型 | 理解用户目标，选择是否规划、读取技能、调用工具、使用工具观测、追问或回答 | 绕过权限、事务或版本控制 |
| Agent Harness | 统一循环、工具参数结构、预算、重复调用保护、事件记录和终态处理 | 报告业务路由或固定流程 |
| 技能 | 描述能力边界、领域知识、证据规则、安全约束、完成结果，以及必要的编号步骤、条件分支和工具顺序 | 自行执行、产生激活/完成状态，或让 Harness 绕过模型运行领域流程 |
| 工具 | 提供一个可验证的只读查询或单一动作 | 编排下一步或隐藏嵌套工作流 |
| 插件 | 注册领域技能、工具、Service 和资源解析器 | 修改通用 Harness 的领域无关性 |
| Service / Repository | 账号授权、Schema 校验、事务、CAS、幂等和持久化 | 代替模型作医学或业务处置判断 |
| HTTP API | 页面 CRUD、消息提交、资源上传和 SSE | 把页面命令伪装为 Agent 工具 |

## 前端应用组合

`frontend/src/app/workspace/` 组合成员、会话、报告、收藏和设置，连接各领域视图与操作，并持有工作台生命周期中的状态。会话列表通过统一入口处理读取与本地更新，设置和聊天共享模型目录；保存队列与请求作用域由各自控制器持有。页面展示后端提供的授权、执行记录和资源状态，后端在实际操作时重新校验。

职责约束见[前后端职责边界](../接口/前后端职责边界.md#前端)，具体模块入口见[前端开发文档](../../../frontend/README.md#状态与操作的所有者)，用户动作和反馈见[前端行为与交互](../前端/行为与交互.md)。

## 进程内能力装配

`application/services.py` 的 `ApplicationServices` 是 HTTP API 与插件的共同装配入口。应用创建时绑定 `AppPaths`，各 Repository、配置加密、成员访问检查和 JSONL 持久化沿用该数据根。成员授权快照不可变，实际读取或写入时仍实时复核；报告服务的账号、数据根与成员授权必须一致。

| 关注点 | 当前实现归属 |
| --- | --- |
| 会话用例、动态 Harness 调用 | `ConversationService` |
| SSE 订阅、标题、轮次线程与输入队列 | `ConversationSSESubscriber`、`ConversationTitleTasks`、`ConversationTurnJobs`、`ConversationQueue` |
| 共享会话锁、线程、取消信号及事件通知 | 按规范化数据根注册的 `ConversationTasks` |
| 请求审计、模型调用事件与压缩协调 | `ModelRequestAudit`、`ModelCallRecorder`、`ConversationCompaction` |
| 会话索引、轮次索引、附件存储 | `ConversationIndex`、`TurnIndex`、`ConversationAttachments`；`ConversationRepository` 协调 JSONL 与索引提交 |
| 模型历史、时间线、响应呈现 | `model_history.py`、`conversation_timeline.py`、`conversation_presenter.py` |
| 报告能力 | `ReportService` 授权入口与独立校验、呈现、缩略图、来源存储组件 |
| 目录与报告事务 | `LabCatalog`、`ReportFacts` 共用 `ReportTransaction.connection` |
| 供应商协议 | `ModelProvider` 组合传输、消息编码、响应解析、错误解析和能力探测组件 |

成员生命周期锁的重入状态、模型能力探测取消状态同样按数据根隔离。会话和收藏分别提供成员引用读取与解除关联接口，成员删除协调器将原连接及附加数据库别名传给对应参与者，全部关联变更在同一跨库事务内提交。

## 跨领域不变量

- 所有会话任务使用同一 Agent Harness。技能提供领域规程，工具提供可组合能力；Harness 不按页面、关键词、附件类型或意图写死业务流程。
- 会话执行以只追加事件为可信源；Provider 请求只装配一次，安全持久化 payload 与真实发送 payload 同源。
- 规范 UUID `account_id` 标识操作者并统一承载账号级内部归属；可修改的 `account` 承担登录、用户标识展示和授权接收方查找，`account_name` 是便于人识别的账号名称。不可变 `member_id` 标识医疗资料所属的人，`member_name` 保存成员名称，报告及来源按 `member_id` 隔离；聊天、附件、收藏和配置属于操作者。
- 认证请求按 API → `AuthService` → `AuthRepository` 流转，并在整条链路共享唯一的 `CurrentUser` 身份模型。认证数据库模块统一拥有账号、登录会话和成员访问元数据的 DDL 与严格结构描述；操作者的启动模式、默认成员和最近选择属于其私有配置库。Repository 负责 SQL 与事务，Service 负责规范化、凭证校验、会话编排和账号目录生命周期，API 负责请求、Cookie 与响应投影。业务域从公共认证依赖取得可信 `account_id`。
- 成员基础资料保存在健康档案所有者账号的独立成员库；报告库与未来身体指标、医疗日志、用药记录等数据库作为同级成员作用域存储，通过 `member_id` 逻辑关联。成员选择或授权变化以认证库锁定全局访问关系，并附加受影响操作者的配置库原子更新偏好与 `access_revision`；成员删除再由显式参与注册表把全部已存在的平级领域库纳入同一事务，不通过目录扫描推断业务数据。
- 会话 Agent 写入通过工具 → Service → Repository；页面明确的传统 CRUD 通过 API → Service → Repository。
- 浏览器使用同源 HttpOnly Cookie。Provider 与 Web 凭证分别密封；凭证、Cookie 和附件二进制不进入会话事件。
- 外部日期时间使用运行环境本地时区。运行时以当前 Schema 和事件格式为唯一读写契约；结构校验失败时返回 `UNSUPPORTED_SCHEMA` 并保持现有数据原样。
