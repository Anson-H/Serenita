# Serenita 当前技术架构总览

> 文档层级：当前执行 / 架构入口
>
> 当前版本：v0.2.0
>
> 负责：系统组成、分层职责、跨领域不变量和下位契约导航。
>
> 不负责：工具参数、事件字段、数据库表、HTTP 路由或页面交互细节。
>
> 产品范围：[产品需求](../产品/产品需求.md)。

## 系统结构

当前交付成员既往史、健康日记、七类医疗报告、用药记录、身体指标、站内提醒、统一 Harness Agent 和可选联网研究能力。所有用户消息进入同一个通用行动循环；医疗报告插件提供四个 Skill、工具、Service 和资源解析器，既往史提供直接工具，健康日记、用药和身体指标通过各自 Skill 及工具接入，Web 插件提供直接只读工具。模型根据当前任务组合这些能力，Observation 持续返回行动循环。站内通知由应用程序自动生成、调度与投递，页面经普通 HTTP API 管理接收设置和已读状态，不向会话智能体提供通知工具。

```text
HTTP 消息提交
  → 持久化当前轮次、用户消息与资源引用
  → 独立智能体轮次 Worker 领取任务
  → 行动模型读取当前上下文并生成正文或工具调用
  → Harness 校验并执行控制工具、直接工具或 Skill 授权工具
  → 工具结果与独立 Observation 回到模型上下文
  → 模型自主继续行动、询问用户或输出终态正文
  → 会话事件持久化；API 与 SSE 使用同一投影
```

架构提供能力、证据和安全边界。会话中的医疗报告导入、解读、查询、更新与删除由模型根据 Skill 和 Observation 自主决定，不按页面、附件类型、关键词或特殊 Python 分支固定行动顺序。医疗报告页面只有“上传医疗报告”“开始解读”和“重新解读”进入 Harness；手工录入、查询、字段编辑、原件管理和删除等明确页面操作经 HTTP API → Service → Repository 执行。详细入口范围见[前后端职责边界](../接口/前后端职责边界.md#医疗报告边界)。

## 分层职责

| 层级 | 职责 | 不负责 |
| --- | --- | --- |
| 主行动模型 | 理解用户目标，选择是否规划、读取 Skill、调用工具、使用 Observation、追问或回答 | 绕过权限、事务或版本控制 |
| Agent Harness | 统一循环、工具参数 Schema、预算、重复调用保护、事件记录和终态处理 | 医疗报告业务路由或固定流程 |
| Skill | 描述能力边界、领域知识、证据规则、安全约束、完成结果，以及必要的编号步骤、条件分支和工具顺序 | 自行执行、产生激活/完成状态，或让 Harness 绕过模型运行领域流程 |
| 工具 | 提供一个可验证的只读查询或单一动作 | 编排下一步或隐藏嵌套工作流 |
| 插件 | 注册领域 Skill、工具、Service 和资源解析器 | 更新通用 Harness 的领域无关性 |
| Service | 实时授权、领域操作、结构与业务约束 | 代替模型作医学处置判断 |
| 纯领域模块 | 共享事件与能力契约、纯投影，以及时间、统计、身份和提醒计算 | I/O、授权与执行编排 |
| Repository | 查询、事务、幂等和持久化 | 处理页面行为或领域授权 |
| HTTP API | 页面 CRUD、消息提交、资源上传和 SSE | 把页面命令伪装为 Agent 工具 |

## 智能体插件目录

各插件统一使用以下职责划分：

| 路径 | 职责 |
| --- | --- |
| `plugins/<plugin>/registry.py` | 声明插件身份，发现 Skill，装配工具并公开资源解析入口 |
| `plugins/<plugin>/tools/` | 实现工具、定义工具参数 Schema；`__init__.py` 提供工具类或构造函数的公开入口 |
| `plugins/<plugin>/resources.py` | 按需要解析资源引用、原件内容和资源状态 |
| `plugins/<plugin>/skills/<skill>/SKILL.md` | Skill 目录描述与完整 Skill 正文 |
| `plugins/<plugin>/skills/<skill>/runtime/serenita.yaml` | 声明 Skill 关联的工具及必需参考文件 |

工具目录内部按能力拆分；共用的参数构造集中在 `parameters.py`，动态工具定义集中在 `definitions.py`。`registry.py` 只承担注册与装配，工具的参数定义和执行代码由 `tools/` 持有。只有直接工具的插件不创建空 Skill 目录，没有资源解析职责的插件不创建空资源模块。

Skill 读取成功后，Harness 根据 Skill 关联和工具公开方式，将可用工具及工具参数 Schema 加入后续模型请求；模型自主选择工具调用。工具通过 Service 执行业务操作，Observation 返回动态行动循环。通知由应用层直接装配，职责见[站内通知](../领域/站内通知.md)。

## 前端应用组合

`frontend/src/app/workspace/` 按当前领域组合成员、会话、医疗报告、日志、用药、身体指标、收藏和设置，连接各领域视图与操作。会话控制器持有内部状态和可变引用，向组合层提供快照、动作与视图入口；草稿持有实际上传任务及其会话身份。会话列表通过统一入口处理读取与本地更新，设置和聊天共享模型目录；保存队列与请求作用域由各自控制器持有。身体指标分别管理数据请求、筛选和详情导航。页面展示后端提供的授权、执行记录和资源状态，后端在实际操作时重新校验。

职责约束见[前后端职责边界](../接口/前后端职责边界.md#前端)，具体模块入口见[前端开发文档](../../../frontend/README.md#模块入口)，用户动作和反馈见[前端行为与交互](../前端/行为与交互.md)。

## 进程内能力装配

`application/services.py` 的 `ApplicationServices` 是 HTTP API 与插件的共同装配入口。应用创建时绑定 `AppPaths`，各 Repository、配置加密、成员访问检查和 JSONL 持久化沿用该数据根。成员授权快照不可变，实际读取或写入时仍实时复核；医疗报告服务的账号、数据根与成员授权必须一致。

`app/` 根目录只保留应用入口与包声明。会话操作和协作者集中在 `application/conversations/`，由 `service.py` 的 `ConversationService` 公开操作并连接组件；共享事件契约与纯投影集中在 `domain/conversations/`。Repository 和存储恢复逻辑直接消费领域模块，应用层负责授权、任务执行和响应呈现。`domain/model_capabilities.py` 统一生成与嵌入模型的能力规则，`schemas/` 维护输入字段结构与校验，`core/` 提供基础能力和进程内协调。逐文件职责与真实调用链见[后端模块入口](../../../backend/README.md#模块入口)。

| 关注点 | 当前实现归属 |
| --- | --- |
| 会话公开操作与装配 | `ConversationService` |
| 输入提交、编辑与重新生成 | `ConversationSubmissions` |
| 当前轮次结束、恢复与执行生命周期 | `ConversationTurnLifecycle`、`ConversationTurnJobs` |
| 会话读取、呈现与管理 | `ConversationQueries`、`ConversationSessionCommands` |
| 动态 Harness 与工具结果准备 | `ConversationExecution`、`ConversationModelResources` |
| 实时取消检查与工具结果提交 | `ConversationExecutionGuard`、`ConversationToolResults` |
| 输入与资源、共享事件快照与 Observation 定位 | `ConversationInputs`、`ConversationEvents` |
| 健康日记、用药、身体指标与通知 | 对应 Service、纯领域计算模块及 Repository |
| SSE 订阅、标题、轮次线程与输入队列 | `ConversationSSESubscriber`、`ConversationTitleTasks`、`ConversationTurnJobs`、`ConversationQueue` |
| 共享会话锁、线程、取消信号及事件通知 | 按规范化数据根注册的 `ConversationTasks` |
| 请求审计、模型调用事件与压缩协调 | `ModelRequestAudit`、`ModelCallRecorder`、`ConversationCompaction` |
| 会话索引、轮次索引、附件存储 | `ConversationIndex`、`TurnIndex`、`ConversationAttachments`；`ConversationRepository` 协调 JSONL 与索引提交 |
| 模型历史、时间线、响应呈现 | `domain/conversations/model_history.py`、`domain/conversations/timeline.py`、`application/conversations/presenter.py` |
| 医疗报告能力 | `ReportService` 授权入口与独立校验、呈现、缩略图组件；`ReportSources` 管理来源生命周期，`ReportQueries` 管理查询 |
| 目录与医疗报告事务 | `LabCatalogService` 提供目录授权入口；`LabCatalog`、`ReportFacts` 共用 `ReportTransaction.connection` |
| 供应商协议 | `ModelProvider` 组合传输、消息编码、响应解析、错误解析和能力探测组件 |

成员生命周期锁的重入状态、模型能力探测取消状态同样按数据根隔离。会话和收藏分别提供成员引用读取与解除关联接口，成员删除协调器将原连接及附加数据库别名传给对应参与者，全部关联变更在同一跨库事务内提交。成员删除和撤权还在该事务中登记持久收尾任务，应用层逐项中断受影响的旧会话任务并清理原件，失败保留重试。通知重新校验由应用层显式传递受影响成员和账号，基础通知模块仅管理通用唤醒信号。

`core/conversation_tasks.py` 的事件唤醒与线程、锁共用同一数据根作用域。标题长度和清理词表归 `domain/conversations/titles.py`，标题模型请求与后台任务归 `application/conversations/titles.py`；会话索引只依赖标题契约。

## 跨领域不变量

- 所有会话任务使用同一 Agent Harness。Skill 提供领域规程，工具提供可组合能力；Harness 不按页面、关键词、附件类型或意图写死业务流程。
- 会话执行以只追加事件为可信源；Provider 请求只装配一次，安全持久化 payload 与真实发送 payload 同源。
- 规范 UUID `account_id` 标识操作者并统一承载账号级内部归属；可更新的 `account` 承担登录、用户标识展示和授权接收方查询，`account_name` 是便于人识别的账号名称。不可变 `member_id` 标识医疗资料所属的人，`member_name` 保存成员名称，医疗报告及来源按 `member_id` 隔离；聊天、附件、收藏和配置属于操作者。
- 认证请求按 API → `AuthService` → `AuthRepository` 流转，并在整条链路共享唯一的 `CurrentUser` 身份模型。认证数据库模块统一拥有账号、登录会话和成员访问元数据的 DDL 与严格结构描述；操作者的启动模式、默认成员和最近选择属于其私有配置库。Repository 负责 SQL 与事务，Service 负责规范化、凭证校验、会话编排和账号目录生命周期，API 负责请求、Cookie 与响应投影。业务域从公共认证依赖读取可信 `account_id`。
- 成员基础资料与八项既往史保存在健康档案所有者账号的独立成员库；医疗报告库与健康日记、用药记录及身体指标等数据库作为同级成员作用域存储，通过 `member_id` 逻辑关联。成员选择或授权变化以认证库锁定全局访问关系，并附加受影响操作者的配置库原子更新偏好与 `access_revision`；成员删除再由显式参与注册表把全部已存在的平级领域库纳入同一事务，不通过目录扫描推断业务数据。
- 会话 Agent 写入通过工具 → Service → Repository；页面明确的传统 CRUD 通过 API → Service → Repository。
- 浏览器使用同源 HttpOnly Cookie。Provider 与 Web 凭证分别密封；凭证、Cookie 和附件二进制不进入会话事件。
- 页面时间和统计日期边界使用浏览器本地时区；转换及存储规则见[职责边界](../接口/前后端职责边界.md)。运行时以当前 Schema 和事件格式为唯一读写契约；结构校验失败时返回 `UNSUPPORTED_SCHEMA` 并保持现有数据原样。

## 查询与执行边界

会话列表在数据库中分页。事件快照和 Observation 索引按需建立，受缓存容量限制，追加、分支变化和文件替换后失效；应用启动不遍历历史会话。一次请求的记录、资源解析和投影共享有效快照，Observation 按调用标识定位。

身体指标列表由数据库筛选、排序和分页；完整统计与序列数据分别读取，缓存按成员、筛选及存储变化失效。药品目录使用轻量投影，完整文件与关联按需读取；仅维护医疗报告关联时加入医疗报告事务，沿用统一锁顺序。通知周期处理由后台任务负责，读取和操作使用有界批量查询复核当前授权与有效性。异步上传完成有界读取后，同步验证、文件和数据库操作在线程池执行。

工具参数通过共享 Draft 2020-12 结构校验，引用旁约束完整保留；Pydantic 与 Service 继续校验领域关系。失败沿用标准工具失败格式并返回行动循环。
