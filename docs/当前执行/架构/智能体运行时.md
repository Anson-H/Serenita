## 主系统提示词

主系统提示词用正文说明 Serenita 的产品定位、全局授权与安全边界、证据原则、行动循环和固定术语。它可以告诉模型有哪些场景和限制，但不能写成固定阶段、静态 intent 表、预生成步骤或工具调用顺序。

报告附件、导入、解读和修正原则由[报告领域](../领域/医疗报告.md)负责；联网时机、权威证据和引用原则由[公网研究领域](../领域/公网研究.md)负责。系统提示词引用这些同一产品边界，不在本文复制完整领域规程。


## 行动循环、计划与能力加载

Harness 直接注册的控制工具使用以下固定顶层描述；参数与行为分别在后续小节说明。

| 工具 | 固定顶层描述 |
| --- | --- |
| `load_skill` | 读取一个技能的完整技能正文并返回实际指令文本。 |
| `update_plan` | 创建或调整当前轮次的非强制任务计划，并返回计划内容。 |

### 可选任务计划

行动模型仅在当前任务确实需要整理多个关注点、未决问题或完成标准时调用 `update_plan`。简单回答、单一追问和单一明确工具操作不需要形式化计划。

```json
{
  "goal": "...",
  "open_questions": [],
  "milestones": [],
  "completion_criteria": []
}
```

计划只在当前轮次内作为轻量参考，不选择技能、工具或执行顺序，不是独立 Plan Mode、审批、操作授权、强制状态机或成功判定。模型可以根据新工具观测更新计划，也可以自然偏离不可行计划。

`update_plan` 按普通工具执行，只产生标准的模型工具调用请求、`tool/call` 和 `tool/result`。Runtime 不维护或恢复独立计划状态，不生成计划专用事件、上下文或阶段，前端也不投影计划记录或卡片。

### `load_skill`

每个新轮次及当前轮次每次上下文压缩提交后，都从当前会话线性视图重新确定已经成功读取、且 `load_skill` 工具观测仍保留在当前模型上下文里的技能，其业务工具出现在后续请求中；首个轮次、被压缩的历史或不在 fork seed 中的历史不会自动恢复，需要重新读取。摘要提到技能不恢复技能可见性。`load_skill({"name": ...})` 是真实只读 Harness 工具，其输出只能是从对应目录读取到的完整 `SKILL.md` 指令文本。

- 技能没有调用、输入、输出、激活、完成或完结状态。
- 完整技能目录和 `load_skill` 的名称枚举在当前轮次每次模型请求中保持不变。
- Harness 不因已经读取某个技能而隐藏目录、缩减枚举或拒绝再次读取。
- `model_exposure="skill"` 的业务工具只在相应技能指令已经进入当前模型上下文后对模型可见，服务端仍再次校验授权；`model_exposure="direct"` 的工具从首步可见。
- 一个任务可以按最新工具观测动态读取并组合多个技能。

`load_skill` 工具观测在后续模型请求中作为普通历史消息存在。只有当该消息实际进入后续 `provider_payload.messages` 时，页面才从同一消息投影普通“历史工具调用结果”上下文；不得另设技能专用输入追溯分类，也不得再注入或复制一份技能文本。

### 工具与工具观测

工具参数严格按 JSON Schema 校验，不把嵌套 JSON 字符串、数字字符串或布尔字符串自动纠正为目标类型。每个模型请求工具调用保留完整参数，并通过 `tool_call_id` 与真实 `tool/call`、`tool/result` 和 `harness/observation` 对应。

工具成功、参数错误、协议错误、权限拒绝、版本冲突和执行异常都形成真实工具结果与独立工具观测。工具观测回到行动循环，由模型决定修正参数、重新取证、调用其它能力、询问用户或停止；Runtime 始终沿用同一动态行动循环。

工具业务 output 在写入结果事件和流式返回前使用统一无损编码；时间线和后续模型请求共享同一形态，不维护未编码的第二份持久化结果。精确编码、调用关联与投影只在[会话事件](会话事件与投影.md#信封与类型)维护。

`AgentContext`、`PluginRuntimeContext` 和工具服务端绑定统一携带可信 `account_id`。模型可见工具参数结构聚焦业务参数，账号身份由 Runtime 在服务端绑定；会话通知、后台轮次、并发锁、探测取消和插件 Service 都使用同一不可变账号身份。

`Tool.model_exposure` 只允许 `direct|skill`，默认 `skill`。Harness 每一步用相同元数据规则暴露全部 `direct` 工具与当前已读技能允许的工具；它不检查工具名称、页面、用户关键词或意图。原生工具调用与文本工具协议消费同一逻辑 Schema，直接工具也进入现有工具目录、事件记录、列式编码和后续模型上下文。

### Provider 边界

支持原生工具调用的 Provider 直接接收逻辑工具参数结构。没有原生工具调用的文本模型由 Provider 适配器把同一组 Schema 序列化为严格文本协议，并把模型输出解析为统一 `ToolCall`。

适配器只负责 wire 序列化、增量解析、原始文本保留和统一类型转换，不包含报告路由、业务状态机或第二套行动循环。文本协议解析失败时保存真实 `raw_content` 和错误，不启动修复模型。

### 自动上下文压缩

运行时保留历史摘要、轮次前半段摘要和近期原文三层聊天内容。当前用户请求原文独立保护；首次历史、更新历史、轮次前半段采用三套提示词，分层生成完成后提交同一个检查点。每次实际摘要调用携带 `summary_kind` 供执行记录展示，其实际用量分别统计。

Harness 在请求预算检查和完整工具结果超限判定前执行通用压缩能力；专用 `compact` 模型按自身预算分块生成摘要，成功提交后重新装配请求。取消、快照核对、CAS 提交及模型明确上下文溢出的一次强制压缩重试都属于资源和一致性边界，不选择业务下一步，也不重执行已经完成的工具。状态和摘要分别持久化，前端从真实状态记录展示同一次操作；不增加手工入口、HTTP 命令或模型可见工具。完整选择、保留、预算和失败规则唯一维护在[上下文压缩](会话事件与投影.md#上下文压缩)。


## 轮次 Worker 与等候队列

`POST /api/conversations/messages` 返回联合响应：空闲会话以 `disposition="started"` 返回轮次与流信息，写入 `turn/start`、`user/message` 并启动独立 Worker；执行中会话以 `disposition="queued"` 返回固化正文、模型、思考档位与资源的新队列项及完整队列。队列事件不进入正文或模型上下文，只有提升时才追加用户消息。同一会话最多有一个 queued/streaming 轮次，准确 SQLite 约束见[数据库结构](../运维/数据库结构.md#conversation_turns)；跨会话不设账号级串行锁或固定 Worker 数量上限。Worker 条件领取并周期更新心跳，所有终态自动提升队首。删除会话禁止继续提升。

等候输入可以排序、删除、原样取回和立即提升。缺失或已提升的输入返回冲突；取回后重新提交会创建新的队尾项。删除只清理未被其它队列项或已执行消息引用的附件，取回附件继续由草稿持有。完整路由只在 [HTTP API](../接口/HTTP接口.md#会话与附件)维护。

取消接口不接受浏览器部分正文，保留内容来自持久化模型正文或助手消息。`steered` 属于取消终态而非失败。模型事件写入与取消快照以会话级锁建立截点，模型网络等待不持锁。`record_delta.offset` 是文本字段的绝对 UTF-16 偏移，前端幂等应用重放；同一可见流仅保留一个订阅实例，以实例身份隔离过期回调。

取消发生在工具已经执行之后时，必须先收尾持久化该次工具的真实结果，再关闭当前轮次；预算检查或压缩等待期间收到取消也遵守这一顺序。已取得的完整结果按事件审计契约保留，不能因取消丢弃、把已知结果改为结果未知或重新执行工具。收尾只完成结果与终态持久化，不追加新的业务动作，不启动尚未执行的工具，也不继续行动模型请求。预算失败的完整结果与模型可读错误边界见[事件角色与类型](会话事件与投影.md#事件角色与类型)。

如果取消或恢复已经持久化同一调用的未知结果，原调用完成后的收尾按[投影与展示](会话事件与投影.md#投影与展示)追加精确替换结果。未知期间的整组压缩保护遵循[预算与选择范围](会话事件与投影.md#预算与选择范围)；收尾不重新执行工具。

SSE 端点不执行模型或业务逻辑，只按 `(session_id, stream_id)` 跟随和重放已持久化事件。没有 SSE 订阅者时 Worker 仍继续运行。租约过期的 streaming 轮次标记为 `TURN_INTERRUPTED`；开放工具产生带原 `tool_call_id` 的 `TOOL_OUTCOME_UNKNOWN`，可能已产生副作用的调用不自动重试。

事件信封、追加顺序、Provider payload 的唯一来源、线性投影、替代轮次、压缩和独立子会话的精确契约统一见[会话事件](会话事件与投影.md)。本节只定义运行职责，不复制事件类型或展示规则。

## 会话标题

首次消息立即生成临时标题；只有附件时使用附件名作为标题种子。标题模型属于会话索引元数据任务，不是用户任务的 Agent 执行步骤。

标题请求、系统提示词、thinking/reasoning 和原始输出不写入会话详情事件。前端只接收最终标题更新。标题模型能读取附件时可以使用附件内容，否则使用安全标题种子。

标题任务按 `(account_id, session_id)` 登记 Worker 与 `CancellationToken`。`PATCH /api/conversations/{session_id}` 包含标题时，Service 先发出取消信号并主动关闭仍阻塞的 Provider HTTP client/response，再在会话索引事务中保存标题并设置 `is_title_manual = 1`；只修改 `is_pinned` 不触碰标题任务。任务在请求前、请求后和写入前检查取消信号，自动标题的 CAS 写入额外要求 `is_title_manual = 0`。因此取消与模型返回、线程调度或数据库写入发生竞争时，迟到结果都不能覆盖手工标题；取消本身不产生会话事件或执行记录。

## 架构验收

- 压缩覆盖首次／更新历史与轮次间／轮次内切分四种组合，以及只有旧摘要、只有前半段、同轮次连续三次压缩；重启、分叉和恢复后的投影一致。
- 当前请求逐字保留且不进入替换来源；医疗数值、单位、日期、来源、未处置结构化内容和附件继续保留，技能工具权限随可见读取结果变化。
- 任一层失败、取消或并发变化不提交半成品；各层分块与收紧请求满足预算，全部成功后完整行动请求达到目标且可以继续执行。
- 真实开发环境用临时小窗口和无业务写入任务触发两类摘要，保留聊天和执行记录，验收后恢复模型配置。

- 简单任务不被强制规划；需要计划时，`update_plan` 仍只是普通工具调用。
- 完整技能目录在当前轮次内保持稳定；`load_skill` 只返回真实技能正文，重复读取不会被 Harness 拦截。
- 工具成功和失败都形成真实工具结果与工具观测，并回到行动循环。
- 原生工具调用和文本工具协议共用同一工具参数结构；Provider 适配器不含业务路由。
- 不同会话可独立运行，同一会话只有一个活动轮次，等候输入只在提升后进入模型上下文。
- SSE 只重放和跟随事件；无订阅者时 Worker 继续运行。
- 标题任务只更新会话索引，不能写入执行时间线或覆盖手工标题。
