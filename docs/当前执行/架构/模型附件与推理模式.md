## 附件与模型选择

### 上传与授权

附件通过 `POST /api/conversations/context-resources` 上传。服务端完整接收并校验后先登记 `writing + pending` 写入意图，再排他写入最终路径并刷新文件；只有随后转为 `ready + pending` 的资源才会作为成功响应返回、允许预览、发送或进入模型输入。未发送的 `ready + pending` 从就绪时间起 24 小时后过期；发送或进入等候队列后改为 `ready + attached` 并清空过期时间。客户端文件名和资源 ID 都不是权限凭证；后端重新解析真实存储记录。fork 为子会话确定性建立 `ready + attached` 引用并复用不可变原文件，只有最后一个有效会话引用消失后才清理二进制。

附件维护先恢复进程强杀遗留的 `writing` 意图：文件大小和 SHA-256 正确时转为 `ready` 并从恢复时重新计算 24 小时；缺失或不完整且不超过五分钟时不干扰，超过五分钟仍不完整时删除记录并将精确路径交给清理队列。正常写盘失败立即删除写入意图并走同一清理队列，不保存 `failed` 状态。上传协议没有上传标识、任务表、查询接口或统一临时目录；网络错误由浏览器即时提示并允许重新选择。若服务端已成功但响应丢失，客户端不尝试判别，该不可见 `pending` 资源由 24 小时清理回收。

单轮限制：

- 最多 20 个文件。
- 单文件最大 20MB。
- 总大小最大 100MB。
- 报告工作区允许 PDF、JPEG、PNG 和 HEIC，并验证真实文件签名。

### 模型可读能力

模型设置把能力拆成只读汇总视图与 `non_thinking`、`thinking` 两个可编辑/探测 profile。每个 profile 独立记录 `availability`、文本、原生工具调用和附件 MIME；模型行另保存思考档位、上下文窗口与最大输出 Token。Provider 自己的 `native_attachment_mime_types` 是上限，模型设置或探测不能声明 Provider 无法传输的附件类型。设置页添加远端模型后自动执行能力识别；手动刷新先尝试更新远端元数据，再实际探测不同思考状态的文本、工具和附件能力，结果回写当前模型行。每个 `account_id` 分别保存 `chat`、`title`、`vision_parse`、`compact` 四种默认用途；输入区选择模型会更新 `chat` 默认值，而不是建立只在浏览器内有效的会话模型状态。

首页和报告场景的附件选择来自当前会话模型与 `vision_parse` 默认模型的可读 MIME 并集。只有视觉解析模型具备图像输入时，前端才额外开放报告可路由的 JPEG、PNG、HEIC 和 PDF；后端仍根据当前 `account_id` 的模型配置、Provider 原生传输能力和文件记录重新校验，不能把前端 `accept` 当作授权。

当前会话模型能够处理当前轮次全部附件时保持为行动模型；否则整轮选择一个能处理全部附件的 `vision_parse` 默认模型。系统不会按附件逐个混用不同主行动模型，也不会把只支持其中一部分文件的模型视为成功后备。

PDF 在 Provider 支持时原生传输；否则完整渲染全部已验证页面为图片。当前渲染上限为 30 页，超限或页面验证失败明确返回错误，不能静默只发送部分页面。

附件二进制可以进入真实 Provider 请求，但从持久化 `provider_payload` 和会话事件中排除。资源元数据、授权引用和由模型实际读取的文本仍可按安全契约记录。

### 当前轮次推理模式调整

用户选择的推理强度是持续偏好。轮次开始时，Harness 结合实际行动模型、当前轮次是否包含工具参数结构和附件 MIME 检查所选 `non_thinking|thinking` profile；只有所选状态缺少文本、原生工具调用或所需附件能力、且另一状态完整满足要求时，才临时切换当前轮次有效模式。真实切换追加 `turn/thinking_mode_changed`，保存请求模式、有效模式与 `text|tool_calling|image_input|audio_input|video_input|file_input` 原因，并通过 `thinking_mode_changed` SSE 事件让输入区显示“当前轮次”状态。轮次完成、失败或取消后前端恢复原偏好；两种 profile 都不能满足原生工具调用时仍使用统一文本工具协议，其它无法满足的文本或附件要求按普通失败契约返回。

## 模型配置语义

普通 Provider 响应和保存/测试结果提供 `has_api_key`，显式 reveal 接口向认证用户返回密钥。模型写入契约由分状态 `capability_profiles`、`thinking_modes`、`context_window_tokens` 和 `max_output_tokens` 组成。远程候选在供应商未声明上下文长度时返回 `null`；模型正式添加到 Serenita 时，缺失或空的 `context_window_tokens` 统一保存为 128K（`131072` Token），已保存模型始终返回正整数。供应商或用户提供的有效正整数优先，后续刷新取得真实值时替换默认值，未取得时保留 `131072`；编辑留空恢复默认值。`max_output_tokens` 同时用于上下文输入预算和 Provider `max_tokens` 输出限制，并保持独立的可空配置。准确列类型与默认值见[数据库结构](../运维/数据库结构.md#models)；Harness 对意外缺失值使用同一常量保护上下文。

Provider API key 使用模型 Provider 专用 AES-GCM v3 密封格式和 `provider_master.key`，AAD 由 `account_id + provider_id` 组成。普通配置接口显示是否已经配置；认证用户主动读取时由禁止缓存的专用接口返回明文。附件元数据、会话事件与安全 Provider payload 始终保持凭证隔离。用户标识更新后，同一 `account_id` 继续直接读取原凭证与模型配置。

## 架构验收

- 能力按汇总、非思考和思考 profile 返回，探测结果和四类默认用途持久化。
- 单个行动模型必须能够读取当前轮次全部附件；无法满足时明确失败，不静默只传部分内容。
- 所选推理状态能力不足、另一状态完整可用时，只临时调整当前轮次并记录真实原因。
- 两种状态都没有原生工具调用时使用统一文本工具协议，不创建第二套行动循环。
- 附件二进制可以进入真实 Provider 请求，但不得写入持久化 Provider payload 或会话事件。

## 附件入口能力查询

前端通过 `/api/conversations/attachment-capabilities` 获取当前可接收的附件类型。后端使用与上传和发送相同的能力检查，结合所选模型、视觉解析模型及 Provider 原生附件支持生成列表。视觉解析模型仅支持 JPEG/PNG 时，不因此宣称支持 HEIC；PDF 渲染仍要求目标视觉解析模型可接收 JPEG。单文件能力列表不代替整轮附件组合、文件大小和后续模型请求检查。
