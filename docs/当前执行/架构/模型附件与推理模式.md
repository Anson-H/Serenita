## 附件与模型选择

### 上传与授权

附件通过 `POST /api/conversations/context-resources` 上传。服务端完整接收并校验后先登记 `writing + pending` 写入意图，再排他写入最终路径并刷新文件；只有随后转为 `ready + pending` 的资源才会作为成功响应返回、允许预览、发送或进入模型输入。未发送的 `ready + pending` 从就绪时间起 24 小时后过期；发送或进入等候队列后改为 `ready + attached` 并清空过期时间。客户端文件名和资源 ID 都不是权限凭证；后端重新解析真实存储记录。fork 为子会话确定性建立 `ready + attached` 引用并复用不可变原文件，只有最后一个有效会话引用消失后才清理二进制。

附件维护先恢复进程强杀遗留的 `writing` 意图：文件大小和 SHA-256 正确时转为 `ready` 并从恢复时重新计算 24 小时；缺失或不完整且不超过五分钟时不干扰，超过五分钟仍不完整时删除记录并将精确路径交给清理队列。正常写盘失败立即删除写入意图并走同一清理队列，不保存 `failed` 状态。上传协议没有上传标识、任务表、查询接口或统一临时目录；网络错误由浏览器即时提示并允许重新选择。若服务端已成功但响应丢失，客户端不尝试判别，该不可见 `pending` 资源由 24 小时清理回收。

单轮限制：

- 最多 20 个文件。
- 单文件最大 20MB。
- 总大小最大 100MB。
- 医疗报告工作区允许 PDF、JPEG、PNG 和 HEIC，并验证真实文件签名。

### 模型可读能力

生成模型的能力由只读汇总视图与 non_thinking、thinking 两个可编辑、可检测 profile 组成。每个 profile 独立记录 availability、文本、原生工具调用和附件 MIME；模型行另保存思考档位、上下文窗口与最大输出词元。Provider 的 native_attachment_mime_types 是生成附件传输上限。向量模型使用独立的能力结构与调用方法。

添加模型先保存 unknown，页面随后自动检测。先实际请求生成接口和适用的向量接口，文本失败仍继续图片等适用输入与百炼原生多模态接口。实测未确认时，再采用提供方目录中明确的类型信息；名称不作为成功证据，仍未知时由用户选择。两个接口均成功时保留各项结果，未确认配置由用户选择类型。已手工确认类型在实测无结论时继续使用用户选择。超时、认证、限流和接口不存在保留独立失败说明，不能推断另一类成功。

确认生成类型后继续检测思考档位及两种状态下的文本、附件和工具调用。向量检测分别记录文本、图片、音频、视频与适用文档；只有成功样例的格式进入 file_mime_types。不适用的接口结构不发起虚构请求。独立向量使用单个已验证输入检测；融合向量仅在当前接口协议下至少两种不同输入模态验证通过且默认维度一致时，取前两种模态组合检测。只有一种模态通过时，融合标记为 not_applicable；没有模态通过时保留 unverified。单输入融合请求可以用于确认原生接口的输入能力，但不能证明多模态融合能力。独立与融合方式分别检查数量，批量检查索引，所有向量校验非空、有限数值、统一维度与输入对应关系。输出维度统一保存在 embedding_dimensions，可手工更新；成功检测以未指定维度请求的实际返回值覆盖，失败保留原值。提供方声明的维度和用户配置维度逐一请求，实际长度必须等于请求维度。批量配置只使用 max_batch_size：检测明确不支持批量时写入 1；支持时不推测上限，原值为 1 时清空，已有大于 1 的手工值保留；未验证时保留原值。批量检测状态仅保留在检测结果中。调用按当前批量输入上限校验，融合内容作为一条输入计算。单条输入词元上限与未知的批量输入上限允许手工填写或留空，不进行压力测试。

向量输入配置与生成模型共用 supports_text 布尔开关和 file_mime_types 精确格式列表；编辑页只呈现启用与未启用，可手工调整或详细自定义。默认用途与调用校验由这两项配置推导输入模态。

检测沿用 supported、unsupported、unverified、not_applicable 四态，最近完成的 checks、errors、metadata 存入 capability_detection；编辑页展示当前能力与参数，不展示历史检测明细。检测拥有取消令牌和可选 probe_id，指定标识的取消不会影响其它检测；写入前在事务内核对模型与提供方配置快照，取消、删除或更新期间产生的旧结果不覆盖新配置。

首页和医疗报告场景的附件选择来自当前会话模型与 `vision_parse` 默认模型的可读 MIME 并集。只有视觉解析模型具备图像输入时，前端才额外开放医疗报告可路由的 JPEG、PNG、HEIC 和 PDF；后端仍根据当前 `account_id` 的模型配置、Provider 原生传输能力和文件记录重新校验，不能把前端 `accept` 当作授权。

当前会话模型能够处理当前轮次全部附件时保持为行动模型；否则整轮选择一个能处理全部附件的 `vision_parse` 默认模型。系统不会按附件逐个混用不同主行动模型，也不会把只支持其中一部分文件的模型视为成功后备。

PDF 在 Provider 支持时原生传输；否则完整渲染全部已验证页面为图片。当前渲染上限为 30 页，超限或页面验证失败明确返回错误，不能静默只发送部分页面。

附件二进制可以进入真实 Provider 请求，但从持久化 `provider_payload` 和会话事件中排除。资源元数据、授权引用和由模型实际读取的文本仍可按安全契约记录。

### 当前轮次推理模式调整

用户选择的推理强度是持续偏好。轮次开始时，Harness 结合实际行动模型、当前轮次是否包含工具参数 Schema 和附件 MIME 检查所选 `non_thinking|thinking` profile；只有所选状态缺少文本、原生工具调用或所需附件能力、且另一状态完整满足要求时，才临时切换当前轮次有效模式。真实切换追加 `turn/thinking_mode_changed`，保存请求模式、有效模式与 `text|tool_calling|image_input|audio_input|video_input|file_input` 原因，并通过 `thinking_mode_changed` SSE 事件让输入区显示“当前轮次”状态。轮次完成、失败或取消后前端恢复原偏好；两种 profile 都不能满足原生工具调用时仍使用统一文本工具协议，其它无法满足的文本或附件要求按普通失败契约返回。

## 模型配置语义

普通 Provider 响应和保存、测试结果提供 has_api_key，显式 reveal 接口向认证用户返回密钥。model_type 为 generation、embedding 或 unknown。生成类型使用 capability_profiles、thinking_modes、context_window_tokens、max_output_tokens；向量类型使用 embedding_capabilities、embedding_dimensions、max_input_tokens、max_batch_size。切换类型清空不适用参数，未确认类型不保存专属参数。上下文及输入、输出限制均可留空，填写时为正整数；检测保留已有手工限制。max_output_tokens 继续用于生成输入预算和 Provider 输出限制。Harness 对未配置窗口使用内部资源保护常量，配置库不将该常量当作已确认上限。准确字段与约束见[数据库结构](../运维/数据库结构.md#models)。

默认生成用途为 chat、title、vision_parse、compact，要求生成类型且支持文本，vision_parse 还要求图片输入。向量用途为 text_embedding、multimodal_embedding，分别要求文本输入已确认、至少两种模态已确认；同一模型可用于两种用途。向量默认值初始为空并由用户选择，未确认模型不可设为默认。确认可用生成类型且聊天默认仍为空时设为聊天默认，添加向量模型不触发此行为。类型或能力变更清空失效引用并提示，不选择替代模型。输入区选择模型更新 chat 默认值；聊天与向量调用入口分别校验类型。

百炼使用兼容文本接口及原生多模态接口，适配器负责已知官方地址映射与各模型协议的独立、融合结构。自定义地址无法确定原生协议时返回未确认，不切换地址。OpenRouter 合并 /models 与 /embeddings/models 并去重，通过 /embeddings 接收文本或 content 多模态结构，音频、视频与文档分别使用 input_audio、input_video、input_file。DeepSeek 参与实际接口检测，没有成功向量结果时不声明支持。目录未收录的模型可手工输入 ID。

ModelProviderService.complete_embedding_for_account 使用账号配置、凭证、超时和取消机制，校验类型、输入能力与批量限制，返回实际模型、向量、维度、生成方式及使用量。当前没有向量索引、医疗报告切分、搜索或重建任务。

接口参考：[百炼多模态向量](https://help.aliyun.com/zh/model-studio/multimodal-embedding-api-reference)、[OpenRouter 向量目录](https://openrouter.ai/docs/api/api-reference/embeddings/list-all-embeddings-models)、[向量调用](https://openrouter.ai/docs/api/api-reference/embeddings/submit-an-embedding-request)和 [OpenAPI 输入结构](https://openrouter.ai/openapi.json)。

Provider API key 使用模型 Provider 专用 AES-GCM v3 密封格式和 `provider_master.key`，AAD 由 `account_id + provider_id` 组成。普通配置接口显示是否已经配置；认证用户主动读取时由禁止缓存的专用接口返回明文。附件元数据、会话事件与安全 Provider payload 始终保持凭证隔离。用户标识更新后，同一 `account_id` 继续直接读取原凭证与模型配置。

## 架构验收

- 生成与向量能力按各自契约保存，类型实测优先于元数据，六类默认用途与失效清理规则保持一致。
- 单个行动模型必须能够读取当前轮次全部附件；无法满足时明确失败，不静默只传部分内容。
- 所选推理状态能力不足、另一状态完整可用时，只临时调整当前轮次并记录真实原因。
- 两种状态都没有原生工具调用时使用统一文本工具协议，不创建第二套行动循环。
- 附件二进制可以进入真实 Provider 请求，但不得写入持久化 Provider payload 或会话事件。

## 附件入口能力查询

前端通过 `/api/conversations/attachment-capabilities` 获取当前可接收的附件类型。后端使用与上传和发送相同的能力检查，结合所选模型、视觉解析模型及 Provider 原生附件支持生成列表。视觉解析模型仅支持 JPEG/PNG 时，不因此宣称支持 HEIC；PDF 渲染仍要求目标视觉解析模型可接收 JPEG。单文件能力列表不代替整轮附件组合、文件大小和后续模型请求检查。

## 能力证据与配置事务

生成能力分别维护 non_thinking 与 thinking 状态。供应商目录未声明的字段沿用该状态自己的已知能力；不把汇总能力复制到另一状态。图片探测要求回答匹配合成图片的颜色，PDF 探测要求读出样本文字；拒读、无关正文和仅返回工具调用均不证明读取成功。实测成功只添加实际使用样本的 MIME，供应商明确声明和已有已确认格式分别保留。

默认模型资格检查与默认值写入使用同一写事务；模型类型、能力及其失效默认引用也在同一事务更新。网络探测在事务外执行，提交时重新检查模型与 Provider 配置是否仍与开始时相同。
