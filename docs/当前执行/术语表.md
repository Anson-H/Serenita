# 当前术语表

> 文档层级：当前执行 / 术语契约
>
> 负责：跨产品、架构、领域、接口和前端文档共用术语的唯一含义。
>
> 不负责：业务流程、字段结构、HTTP 路由或页面行为。
>
> 使用规则：技术专用名词采用本表固定英文名称，医疗业务名称与普通动作使用中文；代码标识、事件类型和接口字段保持代码原名。

## 英文专用名词

文档正文、标题和图示统一使用 `Skill`、`Observation`、`Schema`，大小写按本表书写。中文释义用于解释含义；准确引用的模型提示词、工具描述、界面文案和外部原文保留原文。

| 固定写法 | 中文释义与使用范围 |
| --- | --- |
| Skill | 技能；模型按需读取的领域规程，具体使用“Skill 目录描述”“Skill 正文”“读取 Skill” |
| Observation | 工具观测；工具执行信息返回行动循环后，供模型读取并决定下一步，不泛指医学观察或记忆中的归纳 |
| Schema | 数据结构及其约束定义；按对象使用“工具参数 Schema”“数据库 Schema”“JSON Schema”，普通内容组织仍称“结构” |

Agent、Harness、Provider、Service、Repository、API 等已有英文名称继续沿用。长期记忆文档中表达架构对象、层级和状态的关键术语采用固定英文名称，正文、图示和算法说明同步使用，术语表提供中文释义；模块名称保留中文，研究对象沿用英文原名，具体见[长期记忆固定术语](../未来愿景/长期记忆与认知架构.md#固定术语)，中文解释、医疗业务名称及普通动作按各自语义表达。

## 身份与资料

| 术语 | 含义 | 相邻概念 |
| --- | --- | --- |
| 账号 | 登录、操作和账号级配置的主体，由服务端生成的规范 UUID `account_id` 标识 | 医疗资料所属的人由成员表示 |
| 用户标识 | `account` 字段承载的登录标识，可更新、大小写不敏感且全局唯一，也用于界面标识和授权接收方查询 | 内部归属与目录使用 `account_id` |
| 账号名称 | `account_name` 字段承载、便于人识别的账号界面称呼，可更新；去除首尾空白后为 1–50 个 Unicode 码点，并允许内部空格 | 登录使用用户标识；成员名称由 `member_name` 保存 |
| 成员 | 一名医疗资料所属人的领域对象，由不可变 `member_id` 标识；字段和接口中的 `member_id` 统一表述为“成员 ID”或“所属成员” | 操作主体由账号表示 |
| 健康档案 | 一名成员的基础资料、医疗报告、解读结果及来源共同构成的数据范围；不设独立“档案 ID”，数据通过 `member_id` 关联所属成员；前端同名工作区用于查看这些内容 | 成员身份或账号 |
| 健康档案所有者账号 | 创建成员并保存该成员医疗资料、管理健康档案授权的账号，由 `account_id` 标识 | 医疗资料所属的成员或当前操作账号 |
| 默认成员 | 操作账号启动时可以选择的唯一成员偏好目标 | “本人”身份、所有权或更高权限 |
| 医疗报告档案库 | 一名成员名下正式保存医疗报告、解读结果与来源关联的领域集合 | 聊天附件目录或候选状态机 |

## 会话与执行

| 术语 | 含义 | 相邻概念 |
| --- | --- | --- |
| 会话 | 操作账号拥有的一段聊天，创建后固定绑定一名成员或永久不关联成员 | 可以随界面选择改绑的容器 |
| 当前轮次 | 当前用户输入触发的一次 Agent 执行，从输入提升到终态 | 整个会话或规划阶段 |
| 会话事件日志 | 会话事实的只追加事件序列及其 header，是详情、模型上下文和 SSE 的共同可信源；每个会话对应一个 JSONL | `conversations.db` 中的会话索引或用户可见页面本身 |
| 执行记录 | 前端从会话事件投影出的上下文、模型、工具和错误记录 | 另一套持久化日志 |
| 工具调用 | 模型请求执行一个工具及其参数 | Skill 激活或业务阶段 |
| 工具结果 | 工具执行后持久化的结构化成功或失败结果 | 模型对结果的解释 |
| Observation | 回到行动循环、供模型读取并决定下一步的工具执行信息 | 后端替模型决定的下一步 |
| Skill | 模型按需读取的领域规程正文 | 可自行执行的工作流或状态机 |

## 医疗报告与证据

| 术语 | 含义 | 相邻概念 |
| --- | --- | --- |
| 医疗报告 | 医疗报告档案库中的正式结构化医疗报告对象 | 尚未写入的解析候选 |
| 医疗报告事实 | 医疗报告的基础信息和结构化内容 | 解读结果 |
| 医疗报告解读 | 读取原始证据、生成或更新解读结果的任务、能力或过程 | 一个字段名 |
| 解读结果 | 医疗报告解读生成或更新的正文、状态、更新时间和过期状态 | 医疗报告事实或来源原文 |
| 来源 | 与医疗报告关联、可追溯的原件 | 来源元数据、来源原文或医学结论 |
| 来源元数据 | 来源的身份、类型、顺序与关联状态 | 实际原件内容 |
| 来源原文 | 实际读取的原件内容 | 从解读结果反推的内容 |
| 原始证据 | 当前医学判断实际使用的来源原文 | 既有解读结果 |
| 检验指标分类目录 | 健康档案所有者账号维护并在其自有成员间共用的指标、别名与分类口径 | 操作账号查看共享健康档案时自己的目录 |

## 健康日记

| 术语 | 含义 | 使用范围 |
| --- | --- | --- |
| 健康日记 | 一条包含记录日期、日记标题和日记内容的完整记录 | 描述 Skill 能力和创建、查询、更新、删除的对象时使用 |
| 日记标题 | 健康日记的标题，对应 `title` | 不与日记内容混用 |
| 日记内容 | 健康日记保存的文字，对应 `content` | 描述写法、读取全文、补充或修正文字时使用 |
| 记录日期 | 健康日记采用的日期，对应 `recorded_on` | 可能与日记内容中的事情发生日期不同 |
| 经历 | 成员实际发生的事情及其过程 | 只描述日记内容涉及的事实，不作为健康日记或日记内容的别称 |

## 动词使用规则

项目自有的 Skill、系统提示词、工具说明、界面文案、代码注释、测试和文档按下表描述实际动作。同一动作使用同一动词，不因模块不同更换近义词。合并后的动作名称在全项目统一使用，规则说明、示例、数量描述和技术说明也必须同步，不保留被合并的近义表达。用户原话、原始资料及代码标识保留原名；SQL 查询、URL 查询参数、CSS 定位等技术术语保留其准确含义。

### 查询与阅读

| 动词 | 使用条件 | 示例 |
| --- | --- | --- |
| 查询 | 按条件寻找已保存数据中的匹配项、数量或统计；也用于概括对应的只读任务 | 查询某日期范围的健康日记；查询药品库存 |
| 定位 | 根据标识、目录或线索确定具体对象或内容位置 | 定位目标医疗报告；定位到来源消息 |
| 读取 | 工具、程序或模型访问具体数据或文字内容；指定标识和查询条件都可限定读取范围 | 读取医疗报告事实；读取网页正文；读取下一页 |
| 查看 | 用户在界面中阅读已经展示或可打开的内容 | 查看详情；查看通知；用户要求“只查看” |
| 打开 | 进入页面、详情、文件或弹窗 | 打开健康日记详情；打开来源文件 |
| 搜索 | 使用关键词、全文索引或向量等方式寻找相关内容；界面搜索框、联网能力和技术机制统一使用此词 | 搜索标题；搜索公开互联网；全文搜索；向量搜索 |
| 筛选 | 以日期、类型、状态、关键词等条件限定结果范围，可与搜索共同生效 | 筛选检验报告；筛选进行中的计划 |

Skill 目录描述用“查询”概括只读任务；正文用“查询”表达寻找已保存资料，用“定位”表达目标确定，用“读取”描述访问证据内容。界面阅读用“查看”，进入页面用“打开”。联网使用“搜索”和“读取网页正文”。接收请求或 Observation 用“接收”，向调用方提供结果用“返回”；对象标识按来源表达为取自目录、工具结果或会话附件元数据。这些词不规定工具调用顺序。

例如：查询指定月份的医疗报告目录，从结果中定位目标医疗报告，再读取医疗报告事实。用户打开详情后可以查看这些内容；仅定位目标不表示已读取完整内容。

### 创建与变更

| 动词 | 使用条件 | 示例 |
| --- | --- | --- |
| 创建 | 使一项此前不存在的独立对象成立 | 创建健康日记、医疗报告或用药计划 |
| 添加 | 向目录、集合或父对象加入一项，可加入已有对象或同时创建新项 | 向药品目录添加药品；添加检验指标、标签或附件 |
| 编辑 | 用户在表单或编辑器中调整输入，尚不表示已保存 | 编辑日记内容；编辑权限 |
| 更新 | 将既有对象、字段、设置或状态变为新值；Skill 和工具概括已有对象的变更时使用 | 更新健康日记；更新记录日期；更新接收设置；更新列表状态 |
| 修正 | 已确认原内容有误，按依据纠正 | 修正录错的数值或日期 |
| 补充 | 保留仍有效的原内容，加入缺少的信息或后续情况 | 补充日记内容；补充原件 |
| 替换 | 用提交的新值取代指定字段或范围的原值 | 提交日记内容会替换全文 |
| 保存 | 将内容持久保留；只有保存成功才能说明已保存 | 保存草稿；自动保存；保存解读结果 |
| 写入 | 描述工具或程序向明确存储目标提交数据的动作 | 写入医疗报告档案库；写入数据库 |
| 提交 | 发送请求或交付待处理内容，尚不表示操作成功 | 提交更新请求；提交完整日记内容 |
| 导入 | 从附件、文字或外部数据形成应用中的资料，可涉及创建、关联或合并 | 导入医疗报告；导入身体指标 |
| 上传 | 将文件从客户端传给服务端，尚不表示已导入业务资料 | 上传医疗报告附件 |
| 删除 | 移除目标对象或记录 | 删除健康日记；删除药品批次 |
| 清空 | 保留对象，移除某字段或集合中的值，仍受必填约束限制 | 清空可选备注；清空选择 |
| 关联／解除关联 | 建立或解除对象之间的关系 | 关联来源；解除图片关联 |
| 合并 | 将多个来源或补充的事实整合到同一既有对象 | 合并医疗报告事实与来源 |

产生独立对象使用“创建”；向集合加入一项使用“添加”。数量和结果描述同样使用对应动作，例如“创建 3 条记录”“添加 2 个标签”“补充的事实”“补充的原件”。“编辑”“更新”“修正”“补充”分别表达输入过程、既有内容变更、纠错和增加信息，不能单凭这些动作宣称已经保存。“维护”概括一组管理能力；具体操作与结果应写明创建、更新、删除等动作。

### 证据处理

| 动词 | 使用条件 | 示例 |
| --- | --- | --- |
| 核对 | 对照标识、资料或多个数值，确认是否一致 | 核对药品名称与规格 |
| 检查 | 确认状态、覆盖范围、遗漏或条件是否满足 | 检查权限；检查记录是否完整 |
| 校验 | 程序依据明确结构、格式或约束判断是否有效 | 校验工具参数；校验数据库结构 |
| 整理 | 按已有事实组织文字、结构或既有资料，保留含义；涉及经历和变化时明确时间顺序 | 整理日记内容；按时间整理症状变化；按时间整理指标趋势 |
| 解读 | 结合证据解释医疗报告的医学含义 | 进行医疗报告解读 |
