# 成员既往史

> 当前执行 / 领域契约。负责八项健康经历、授权与保存语义。
> 上位文档：[产品需求](../产品/产品需求.md)。页面行为见[前端交互](../前端/行为与交互.md#既往史与病历交互)，传输与存储见 [HTTP 接口](../接口/HTTP接口.md)和[数据库结构](../运维/数据库结构.md)。

每位成员维护一份既往史，平素健康状况并入既往病史。页面和会话访问同一份资料，均使用成员实时权限；只读账号可以读取，具有编辑权限的账号可以维护。

## 项目

| 项目 | 唯一字段名 | 内容 |
| --- | --- | --- |
| 既往疾病史 | `past_medical_history` | 以前得过什么病，做过什么治疗 |
| 手术外伤史 | `surgical_trauma_history` | 做过的手术或受过的外伤 |
| 过敏史 | `allergy_history` | 药物、食物或其它物质引起的过敏、不耐受或其它不良反应 |
| 输血接种史 | `transfusion_vaccination_history` | 输血或预防接种经历 |
| 出生与职业史 | `birth_occupational_history` | 出生、居住和工作经历 |
| 生活史 | `lifestyle_history` | 作息、运动、吸烟饮酒和饮食情况 |
| 家族病史 | `family_history` | 患病亲属与本人的关系、所患疾病和发病年龄 |
| 特殊史 | `special_history` | 需要补充的其它健康经历 |

页面按以上八个栏目展示，每个栏目直接填写一段文字。

药物或食物相关情况统一记录在 `allergy_history`，建议写明对象和具体反应，并区分过敏、不耐受、药物副作用和尚未确认的情况。

## 保存与证据

每项独立保存可空文本及对应的 `*_updated_at`。未记录内容与初始时间为 `null`；实际内容变化时更新该项时间，清空仍记录此次更新时间；同次更新使用同一时间。未提交项保持原值，提交文本替换原值，`null`、空字符串、纯空白清空。整次更新在同一事务中完成，未知字段与空更新明确失败；普通更新采用最后有效写入优先。

可编辑的空白输入框显示该栏可填写的内容提示；只读状态的空白显示“未记录”。用户明确提供“无”“否认……”或“不详”时保留原意与范围，不扩大否认范围，不补造事实，不根据时间自动推算亲属年龄。资料更新时间仅表示保存时间，不能据此推定健康经历发生时间。医疗报告原件记载的既往情况保留于原件；导入医疗报告本身不授权更新成员既往史。仅更新既往史不触发既有医疗报告解读结果自动过期。

## 访问能力

既往史读取与更新工具直接可用，不增加独立 Skill；服务端绑定当前成员并检查实时授权。准确参数及返回结构以[读取工具参数 Schema](../../../backend/app/plugins/medical_history/tools/query_tools.py)和[更新工具参数 Schema](../../../backend/app/plugins/medical_history/tools/mutation_tools.py)为准，顶层描述遵循项目开发规则。

页面通过 API → Service → Repository，会话通过工具 → Service → Repository。成员删除时既往史随成员资料在事务中删除，目标失效后明确失败。用户直接提供当前成员实际既往史时，按[产品默认导入授权](../产品/产品需求.md#fr-014-成员医疗资料)主动读取并维护，保留无关内容。医疗报告导入本身不授权更新既往史；模型根据用户请求与 Observation 自主组合能力。
