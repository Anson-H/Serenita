# 成员与健康档案授权

> 文档层级：当前执行 / 领域契约
>
> 负责：账号与成员的身份关系、健康档案数据归属、默认成员、逐名成员的健康档案授权、固定会话绑定、撤权和删除语义。
>
> 不负责：HTTP 路由、SQLite 表结构、物理目录、页面尺寸与交互细节、会话事件格式或医疗报告表结构。
>
> 上位文档：[产品需求](../产品/产品需求.md)；相关契约：[HTTP API](../接口/HTTP接口.md)、[前端行为](../前端/行为与交互.md)、[本地存储](../运维/本地存储.md)、[数据库结构](../运维/数据库结构.md)、[医疗报告领域](医疗报告.md)。

## 身份与范围

登录账号与医疗资料所属的人分别建模，各类标识承担清晰且稳定的职责：

| 标识 | 职责 |
| --- | --- |
| `account_id` | 服务端生成的规范 UUID；作为账号主键、操作者身份、账号私有目录和全部账号级内部归属 |
| `account` | 可更新、大小写不敏感且全局唯一的用户标识；用于登录、界面标识和授权接收方查询 |
| `account_name` | 可更新、便于人识别的账号名称；用于界面称呼 |
| `member_id` | 医疗资料所属人的不可变成员身份；用于成员、医疗报告、来源和授权的成员作用域；健康档案不另设 ID |

账号可以从零位可访问成员开始。存在可访问成员时有且只有一个默认成员；零成员时默认成员为空。默认选择属于操作者账号，可以指向自建成员或已获健康档案只读、编辑权限的成员，并独立于医疗权限和其他账号的选择。

注册创建账号、账号私有配置库与其中的空成员选择偏好。第一位创建成员，或首次获授健康档案访问权的成员，自动成为默认成员；之后可明确替换默认成员。成员可以代表没有账号的家人，每位成员都由独立 `member_id` 确定身份。成员名称统一保存为必填的 `member_name`，不另存完整姓名或成员与操作者的关系描述；性别、出生日期和血型可空，血型取值为 `a`、`b`、`ab`、`o`、`other` 或空值。

当前业务数据包括成员基础资料、[八项既往史](成员既往史.md)、医疗报告、[健康日记](健康日记.md)与[用药记录](用药记录.md)。健康档案所有者账号在创建成员时固定，当前分享方式为认证账号之间按成员授权；健康档案所有者账号可以删除任意自建成员，包括最后一位。

## 数据归属

| 内容 | 健康档案所有者账号与作用域 |
| --- | --- |
| 账号身份、成员归属索引、逐名成员的健康档案授权、授权修订号 | 全局账号与访问控制库；不保存操作者设置、成员基础资料或医疗内容 |
| 成员基础资料 | 健康档案所有者账号的成员库；与全局成员归属索引按 `member_id` 一一对应 |
| 医疗报告事实、解读结果、来源关联 | 健康档案所有者账号的医疗报告库；通过 `member_id` 定位成员，并在每次操作时检查实时授权 |
| 医疗报告原件 | 健康档案所有者账号；共享授权只授予访问，不复制整份健康档案 |
| 检验指标分类目录 | 健康档案所有者账号；在该账号拥有的成员间共用 |
| 聊天、执行事件、上传附件、收藏快照 | 操作账号；固定记录目标成员或不关联成员状态，不随健康档案共享 |
| 成员启动模式、默认与最近选择、模型、联网配置与凭证、显示偏好 | 操作账号的配置库；查看共享健康档案时仍使用自己的配置与成员选择 |

受邀编辑上传文件时，聊天附件仍属于操作者；写入医疗报告档案库后，医疗原件归档到健康档案所有者账号目录。查询、判重、关联、合并、更新、删除和文件清理都限定在当前成员作用域。文件与文本来源身份包含成员标识，相同内容不能导致跨成员关联。

`MemberRepository` 的操作者入口接收 `actor_account_id`，授权接收方查询则解析用户输入的 `account`。`MemberAccess` 以操作者 `account_id`、健康档案所有者账号 `account_id` 和 `member_id` 执行权限判断，同时携带双方当前用户标识供界面展示。成员与授权查询每次连接 `accounts`，自然读取账号资料的当前值。成员选择偏好从操作者自己的配置库读取；偏好写入以认证库为主事务附加该配置库，并在同一事务推进认证库中的 `access_revision`，供相应账号刷新。

全局成员归属、健康档案所有者账号的成员资料、操作者成员选择和成员作用域业务数据分布在不同数据库中，SQLite 不能直接建立跨库外键。成员创建、授权、撤权、选择和删除都由同一个成员事务按需附加这些数据库；任一必需数据库或记录不符合当前契约时，整个事务失败，不猜测替代成员，也不创建原本不存在的延迟数据库。

账号资料由认证库中的单行原子更新保存，数据库按大小写不敏感规则检查用户标识唯一性；唯一性冲突时整项资料保持原值。更新响应与注册、登录和认证恢复共享完整认证会话结构，并保持原 `account_id`、登录会话和到期时间。其它账号在下一次成员或授权读取中读取最新用户标识与显示名称。账号目录、聊天、收藏、凭证及授权关系持续锚定 `account_id`，医疗资料的成员归属持续锚定 `member_id`；账号资料保存保持双方 `access_revision` 当前值。

## 权限

健康档案所有者账号按接收方用户标识选择一位或多位自有成员，并按成员的健康档案授予只读或编辑权限。整批操作先验证归属、接收方和参数，再事务提交。授权集合精确覆盖本次选中的成员；每位成员创建后仅健康档案所有者账号拥有访问权，授权管理权始终属于该账号。

| 能力 | 健康档案所有者账号 | 只读接收方 | 编辑接收方 |
| --- | --- | --- | --- |
| 读取基础资料、既往史、医疗报告事实、原件、既有解读结果 | 允许 | 允许 | 允许 |
| 在自己的聊天中提问、保存自己的收藏快照 | 允许 | 允许 | 允许 |
| 更新基础资料、既往史、医疗报告导入、增删改、保存解读结果 | 允许 | 禁止 | 允许 |
| 通过导入补充新指标及别名 | 允许 | 禁止 | 允许 |
| 管理健康档案所有者账号目录、改变已有分类口径或操作其账号设置 | 允许 | 禁止 | 禁止 |
| 管理该成员的健康档案授权 | 允许 | 禁止 | 禁止 |

只读用户可以生成只保留在自己聊天中的回答，但不能把解读结果或其它变更写入共享健康档案。受邀编辑不能通过检验指标分类目录操作影响健康档案所有者账号的其他成员；目录管理始终作用于操作者自己的目录。

每次医疗报告读取、写入和后续模型请求都重新检查授权。服务端从认证身份解析操作者、健康档案所有者账号、目标成员和有效健康档案权限；客户端和模型不能指定健康档案所有者账号目录。短数据操作与撤权提交通过认证库事务锁确定先后，不跨模型调用持锁。撤权提交后，原权限不能用于新写入，失败操作也不能改写到默认成员。

## 成员选择、默认成员与会话绑定

成员集合的 `default_member_id`、`last_member_id` 和 `initial_member_id` 都可以为空。存在可访问成员时，`default_member_id` 必须指向唯一默认成员；`last_member_id: null` 表示最近选择了“不关联成员”。启动模式 `last_used` 恢复最近选择，`default` 使用当前默认成员；没有可访问成员时两种模式都保持不关联成员。

第一位可访问成员无条件成为默认成员。后续创建或偏好更新只有在明确要求时替换默认成员。更新默认成员不改变最近选择或当前聊天归属；只读共享健康档案对应的成员也可以成为操作者自己的默认成员。

新聊天创建时固定为一位成员或“未关联成员”；成员删除事务会清空既有聊天关联。客户端或模型不能改绑既有聊天。不关联成员的聊天可以文字问答、读取临时附件、排队、编辑、重新生成、分叉和收藏，但运行时不提供医疗报告及既往史工具，也不能读写医疗报告档案库；完整 Skill 目录保持可见。

绑定成员的聊天使用该成员健康档案的实时权限。授权修订、SSE 重连、窗口聚焦或恢复可见时重新检查权限。当前成员的健康档案访问失效后，工作区静默进入替代默认成员的新聊天；没有替代成员时进入不关联成员的新聊天。撤权后的旧聊天保留关联，只可查看历史，仍显示成员当前名称，不能发送、重新生成或分叉；重新授权后恢复执行。成员删除后，聊天与收藏的 `member_id` 清空，显示“未关联成员”；聊天按普通未关联成员聊天继续使用，不保存删除标记。既有聊天和收藏快照保留，来源访问继续检查实时授权，不改挂到其它成员。

聊天与收藏的成员名称只根据操作者已保存的关联读取当前 `member_name`，撤权后仅允许这项名称展示，不授予其他成员资料访问权；无关联时返回空值。JSONL header 不保存成员身份，历史事件中已有的成员 ID、名称与医疗报告引用保持原样，不作为当前关联或授权依据。医疗报告引用按自身来源成员检查状态；删除显示“已删除”，撤权显示“无权访问”，均不可点击。

具体选择菜单、健康档案入口、资料自动保存和撤权后的页面反馈只在[前端行为](../前端/行为与交互.md)维护。

## 删除成员与默认回退

默认成员被删除或其健康档案权限被撤销时，在同一事务中按自建优先、创建时间和 `member_id` 选择其余可访问成员；没有替代成员则把默认选择置空。最近选择指向失效成员时改为替代默认成员或置空，其它有效偏好保持不变。重新授权不恢复旧偏好；如果账号当时没有任何可访问成员，首次重新获授健康档案访问权的成员自动成为默认成员。

删除成员及其健康档案只允许健康档案所有者账号执行。删除事务以全局账号与访问控制库为主库，附加所有受影响操作者的配置库、健康档案所有者账号的成员库及全部已存在、已注册的平级领域库，移除成员基础资料、既往史、医疗报告及结构化内容、解读结果、来源关联、来源元数据和共享授权，并更新各自配置库中的选择及认证库中的授权修订号。未来添加成员作用域数据库必须注册自己的事务内删除逻辑；缺失的可选平级库不为删除而创建，任一必需配置库或已有领域库 Schema 不匹配时整项操作失败。并发删除可以删空自建成员，但默认与最近选择必须原子归零。提交后，后续读取、写入、上传和模型请求都明确失败，不恢复对象或改挂目标；账号共用的检验指标分类目录不随单个成员删除。

原件清理任务与删除事务一起提交，覆盖尚无医疗报告关联的成员医疗报告原件。物理删除失败时保留可重试任务，已经提交的领域删除维持终态。聊天、执行记录、聊天附件与收藏正文继续归操作者所有并保留。删除事务同时查询全部账号已有聊天与收藏库中的关联，包括曾被撤权的操作者，清空 `member_id`；不保留名称快照或另存原成员 ID。只检查已有库，结构异常或附加数据库资源超限时整项事务回滚。删除和撤权终止针对原成员的在途执行并清空等候队列，不自动把旧任务改为未关联成员任务。

## 领域验收

- 账号可以从零成员开始，也可以删除最后一位自建成员。
- 第一位创建成员，或首次获授健康档案访问权的成员，自动成为唯一默认成员；删除和撤权能原子替换或清空默认与最近选择。
- 同一内容在不同成员的健康档案间严格隔离，不发生跨成员判重、合并、关联或来源复用。
- 所有 HTTP 和工具入口都执行相同的实时权限检查；只读权限不能通过任何入口写入。
- 不关联成员的聊天保持完整的普通问答能力，但没有医疗报告及既往史工具；既有聊天不能改绑成员。
- 删除、撤权与在途短数据操作有确定顺序；失效目标不会被恢复或静默替换。

## 健康日记

健康日记归健康档案所有者账号，按 `member_id` 检查实时权限。所有者和编辑接收方可维护，只读接收方可读取。不关联成员的聊天不提供日记工具。日记库显式注册成员删除参与机制，事务内清除日记。
