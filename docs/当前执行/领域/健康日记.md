## 日记内容与记录日期

每条健康日记使用系统生成的稳定 UUID `medical_log_id`，创建后固定归属 `member_id`。保存必填的记录日期 `recorded_on`、必填非空白日记标题 `title` 与日记内容 `content`、创建时间 `created_at` 和最近有效更新时间 `updated_at`。摘要从日记内容生成，不独立保存。记录日期使用合法 YYYY-MM-DD，不能为空；数据库通过 NOT NULL 和非空白检查约束记录日期、日记标题与日记内容。优先使用事情发生的日期；无法确定到日时，使用用户明确给出的记录日期，否则使用当前本地日期，并在日记内容保留实际发生时间不明确的说明。整理时区分事情发生日与补记日。日记内容可记录日常生活、身体感受、症状变化、就医经过和恢复情况，保留“家属描述”“用户转述”“可能”等限定，不把模型推测保存成经历。不增加记录者、更新者、录入方式、独立的信息来源字段或来源聊天标识。

医院出具的门急诊病历归入医疗报告档案；日记内容可包含就医经过。记录日期、日记标题或日记内容实际变化时更新健康日记的更新时间，重复提交相同值不推进时间。

## 日记写作规范

日记标题、日记内容的组织、叙述视角、信息取舍、时间表达及补充修正的写法统一由 [健康日记写作规范](../../../backend/app/plugins/medical_log/skills/log/references/log-writing.md) 定义。该文档作为健康日记 Skill 的必需参考文件随 Skill 加载，Skill 正文只保留能力边界、取证和执行要求。

未指定记录日期时使用日记内容中主要经历开始的日期，无法确定到日时按上节规则处理；后续补充不自动改变记录日期。

## 与身体指标、用药记录及医疗报告的关系

饮食、饮水、排泄、运动、睡眠和体重等明细可以保存在健康日记中；[身体指标](身体指标.md)分类目录支持的内容也可以保存为对应记录。同一份明细允许两处保存，按用户目标与上下文决定范围。日记内容保留完整生活记录，身体指标提供结构化查询与趋势统计。两处保存分别经工具执行并报告结果，后续更新遵循用户指定的对象和范围，不自动同步。当前目录没有对应类型或必要信息不足时，日记内容可以保留原意，身体指标不能补造类型、单位或时间边界。

健康日记不维护药物清单、规格剂量表、固定服药时间表、常规服药逐次明细或库存。整理混合资料时不将这些内容纳入日记内容；[用药记录](用药记录.md)按其能力和用户授权另行处理，不能把某次实际服药写成长期计划，也不能把从日记内容中省略等同于已保存到用药记录。与症状或恢复直接相关的用药经过可以保留必要背景，按需注明相关药名，不展开整套清单，不推定因果。

医疗报告事实与解读结果由[医疗报告档案库](医疗报告.md)承载；日记内容可保留检查、住院、手术和恢复经历，不复制整份报告、病历查体或大段医学解释。混合资料中已有的医学推测与建议不能整理成实际发生的经历。

## 创建、更新与查询

创建健康日记时必须提交记录日期、日记标题和日记内容。更新仅处理已提交字段；省略记录日期保持原值，拒绝 null、空字符串及无效日期。日记标题和日记内容不能清空。空更新和未知字段明确失败。普通更新采用最后有效写入优先，目标失效时明确失败。

目录支持日期范围与关键词，并以 `cursor`、`limit` 逐页读取，默认 24 条、上限 100 条，返回 `next_cursor` 和完整匹配数量。日期边界含当天，关键词按字面匹配日记标题或日记内容；条件共同生效。按记录日期、创建时间倒序，再按稳定标识排序。没有日期未知分组或对应筛选选项。

每次操作检查成员实时授权。只读账号只允许读取，不关联成员的聊天不提供日记工具。日记内容在独立日记库的事务内保存。成员删除通过已注册的平级领域库参与机制同一事务清除日记。

## 会话能力

用户讲述当前成员的实际生活或身体感受时，按[产品默认导入授权](../产品/产品需求.md#fr-014-成员医疗资料)主动整理并保存，无需额外说“记录”或确认保存意愿。一句话也可作为日记内容，不为补齐未提及的细节阻塞保存；实际内容的归属或含义有歧义时再询问。

[健康日记 Skill](../../../backend/app/plugins/medical_log/skills/log/SKILL.md)负责创建、查询、更新、删除和按时间整理健康日记的执行要求；准确参数由[查询工具参数 Schema](../../../backend/app/plugins/medical_log/tools/query_tools.py)和[维护工具参数 Schema](../../../backend/app/plugins/medical_log/tools/mutation_tools.py)提供。工具绑定当前成员，每次 Observation 回到通用行动循环。

会话查询统一使用 `read_log`。省略全部参数由 Harness 自动读取当前成员的全部健康日记；可按 `medical_log_ids`、记录日期范围及字面关键词共同筛选。标识数组接受 1 至 100 个非空且不重复的标识，任一目标失效或不属于当前成员时整次失败；省略标识表示不按标识限定。可选条件应省略，不能显式提交 null，关键词允许空白表示不限。

每页工具结果返回 `member_id`、`medical_logs`、`total` 和 `pagination`，每条健康日记包含完整日记内容及标识、成员、记录日期、日记标题和审计时间，不返回摘要。所有查询均按记录日期、创建时间、健康日记标识倒序排列；内部每页 24 条，按标识读取同样分页。模型仅提交筛选条件；Harness 保持成员、标识集合、日期和关键词自动续读，内部游标不进入模型参数。`total` 为全部匹配数量，`pagination.page` 表示当前页，`pagination.complete` 为 true 表示读取完毕，没有匹配时返回空数组。页面列表通过普通 HTTP API 读取摘要目录，详情通过普通 HTTP API 读取完整内容。

会话创建、更新和删除健康日记成功后，工具结果提供资源引用及变更信息，在最终回答的“相关内容”中展示记录日期、日记标题与操作，打开当前日记详情。删除结果保留删除前的引用信息；资源可用性与更新状态在查询会话时按实时授权读取。
