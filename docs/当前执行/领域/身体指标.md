# 身体指标

> 文档层级：当前执行 / 领域
>
> 负责：记录身份、时间、业务结构、导入及统计规则。
> 不负责：HTTP 端点、物理表定义与像素规格。
> 上位文档：[产品需求](../产品/产品需求.md)。相关契约：[HTTP 接口](../接口/HTTP接口.md)、[数据库结构](../运维/数据库结构.md)、[前端行为](../前端/行为与交互.md)。

## 成员、来源与身份

所有记录属于成员，由成员档案所有者账号存储；每次读写实时检查成员授权。成员删除纳入现有领域参与事务，连同导入任务、排除身份和图片一并清理。普通编辑采用最后有效写入优先。

记录共有字段为 `record_id`、`member_id`、`kind`、`metric`、`starts_at`、`ends_at`、`timezone`、`precision`、`source`、`device`、`origin`、`external_id`、`notes`、`data`、`import_managed`、`edited`、`created_at`、`updated_at`。详情附带 `files` 图片元数据。`record_id` 永不随数值或日期更新；`source`、`device`、`origin`、`external_id` 构成来源身份，编辑不更改这些字段。导入身份优先使用来源提供的稳定标识；苹果适配器按类型、设备及原始时间区间生成标识。缺少外部标识的记录使用首次规范化内容摘要，用户后续编辑不改变该摘要。

`origin` 为 manual、apple_health、standard、image 或 demo。保留来源内容及数值依据；当前可编辑内容独立保存。重导复用已存在身份并保留用户修正。主动删除来源记录保留排除身份，重导不会将其恢复。

## 时间与业务内容

日期时间输入必须含时区偏移；现有时刻字段统一保存为六位小数精度的 UTC ISO 文本，来源内容保留原始输入，IANA 来源时区单独保存。页面显示与编辑采用浏览器本地时区，统计日期边界采用页面提交的同一时区。纯日期按日历日期处理。`precision` 为 instant、interval 或 day；单次测量保存实际时间，区间与日汇总保存开始和结束，不能以导入时刻代替发生时刻。单条区间最多 366 天。只有日汇总时不伪造分钟级采样。

`kind` 决定 `data` 的严格结构，定义位于 `schemas/body_metric.py`：

| kind | data |
| --- | --- |
| measurement | value、unit、secondary_value、pulse、method、context、basis |
| meal | energy、carbohydrate、protein、fat、meal_type、foods、estimated、basis |
| sleep | score、score_max、score_basis、score_stale、duration_minutes、stages |
| workout | activity、duration_minutes、distance_km、energy |

体格包含身高、体重、BMI、腰围、体脂率、脂肪量、骨量、体水分量、蛋白质量、皮下脂肪、内脏脂肪；循环指标包含心率、静息心率、夜间心率、HRV、成组血压、血氧、血糖、体温；活动包含步数、运动记录、活动能量、站立小时数与锻炼时长。全部分类、单位及统计方式由分类目录提供。

血压在同一条记录内保存收缩压和舒张压，可附脉搏。血糖可附空腹、餐后等背景。HRV 保留计算方法，未知为 unknown。皮下脂肪及内脏脂肪的质量、比例、等级和面积分别保留单位。已支持单位换算在入库校验时完成；未知单位明确拒绝。

`meal_type` 支持 breakfast、morning_snack、lunch、afternoon_snack、dinner、evening_snack，缺少来源信息时为空。每次进食独立保存，一餐可有多次进食。食物包含稳定的 `food_id`、name、amount、amount_unit、四项营养值与 basis，营养值代表该实际份量；调整份量时页面按比例调整已有营养值，仍可逐项修正。有 foods 时整餐营养按明细重算；任一明细某项未知时该项整餐总量未知，不重复累加整餐与明细。

睡眠包含每段 `stage_id`、stage、starts_at、ends_at、original_stage。stage 为 awake、rem、light、deep、unknown、in_bed。阶段必须在主睡眠区间内且不重叠；睡眠时长从有效睡眠阶段计算，排除清醒与卧床。没有阶段时允许保存来源时长，界面明确阶段缺失。评分必须含量表满分和来源依据；编辑已有评分的睡眠区间或阶段后标记 score_stale，不能自动虚构新评分。睡眠按醒来日期归属。

## 统计

按指标、来源、设备、测量方法、单位及睡眠评分满分分别形成稳定序列。页面可选来源与序列，不跨设备自动相加。测量按目录选择最近值、均值或范围；步数、活动能量、站立小时数、锻炼时长、饮食和运动时长按各自记录累计。睡眠提供期间累计及有记录日均。未知值不作为零填充。

睡眠区间、阶段或时长发生有效变化后，已有评分标记过期，保留用于追溯并退出有效评分统计。新的评分与明确依据可更新评分状态；普通备注更新不影响评分状态。

同源累计指标优先使用日汇总；没有日汇总时按起始时间接受不重叠区间，冲突区间保留在明细中但不重复统计，并返回 omitted_overlaps。跨日累计测量按区间时长分摊至各自然日，返回 allocated_intervals，页面明确这是日内分布估算。睡眠按完整会话归属醒来日；运动事件归属开始日。运动能量与活动能量分别保存，运动时长与锻炼时长分别统计。

统计覆盖全部匹配记录，并返回记录数量、覆盖日期、缺失值及过期评分排除数量。汇总仅提供有界预览；序列数据按完整身份产生的稳定 `series_id`、时间范围和游标单独读取，默认 100 条、上限 1000 条。原始测量与按日统计桶分别查询，分页不改变完整统计口径。会话中的记录目录和指定序列由 Harness 自动读取全部匹配页，模型只提供筛选、序列及视图，工具结果以 `pagination` 说明页次和完成状态；`offset`、`cursor`、`limit` 仅用于内部读取和普通 HTTP API。浏览器本地自然日包括夏令时的实际时长。

## 文件导入

支持苹果健康 export.xml、含唯一 export.xml 的 ZIP，以及 Serenita 标准 JSON/CSV。上限为上传 64 MiB、解压总量 256 MiB、250000 条输出记录；拒绝危险压缩路径和外部 XML 实体。安卓厂商原生文件待适配，当前通过标准文件接入。

JSON 外层为 `format: serenita-body-metrics` 和 records 数组，每条使用完整业务结构。CSV 列为 row_type、external_id、parent_id、kind、metric、starts_at、ends_at、timezone、precision、source、device、origin、notes、data；data 为 JSON 单元格。row_type=record 表示测量、饮食、睡眠或运动主记录；food 与 stage 表示子项，parent_id 关联主记录 external_id，子项 external_id 为 food_id/stage_id。下载模板同时覆盖四种主记录及两种子项。

上传后生成范围、类别、有效/重复/问题记录预览；用户选择日期和内容后提交后台任务。任务状态为 preview、running、complete、failed。运行中显示进度状态，失败或服务中断可重新提交。提交在单次事务中完成，未完成批次不进入统计；提交完成释放预览记录，保留统计与问题说明。问题明细最多展示前 100 条，完整数量在 unsupported 中。

导入创建记录的 `import_managed` 为真；独立创建的记录为假。有效内容更新、实际增加或解除图片关联后转为独立记录，没有实际变化的提交不改变归属。删除批次只清理仍由导入管理、且无其他批次引用的记录；独立、共享及后来有效更新的记录保留，并仅解除批次关系，不增加保留记录的排除身份。界面显示删除和保留数量。

同一上传请求通过稳定请求标识复用预览；文件摘要仅识别内容，新一次上传可创建新预览。部分导入后重新上传同一文件，按来源身份去重，并可选择尚未导入的日期与内容。

苹果适配器映射实际存在的测量、营养、睡眠分段和运动字段；未知类型、缺少成对血压、无效单位或时间等进入问题说明。没有睡眠评分、餐次、扩展体脂字段时保持缺失，不推算。实机导出文件验证仍为后续工作。

## 会话能力与图片

用户提供当前成员实际的身体指标、餐食、睡眠或运动资料时，按[产品默认导入授权](../产品/产品需求.md#fr-014-成员医疗资料)主动保存，无需额外的保存命令或保存意愿确认；缺少影响执行的必要事实时再询问。

body_metric 插件提供分类目录、记录目录、详情、统计、创建、更新、删除、图片关联与解除关联能力。工具通过 Service → Repository 执行；body-metrics Skill 由模型按当前任务读取，Observation 回到通用 Harness。查询目录只定位记录，不替代完整证据。页面 CRUD 和确定性文件解析不创建会话。

日常明细允许同时保存在[健康日记](健康日记.md)与身体指标中，具体范围由用户目标和上下文确定。日记保留原有生活记录，身体指标只接受当前分类目录支持且满足必要信息要求的记录。两处保存分别经对应工具执行、确认结果，不因创建身体指标记录而删除日记明细，后续更新不自动同步。

图片识别进入现有会话及配置模型，真实读取照片或标签。模型根据用户提供或上下文已明确的日期、餐次和份量生成饮食记录，缺少必要信息时询问；允许的未知值保持未知，估算注明 estimated 和 basis。图片保存为记录附件，可回查原图与依据；模型返回详情链接供用户继续编辑。虚构图片及来源明确标注，不能当作用户实际健康事实。



导入预览在短暂授权检查后于事务外解析文件，再重新授权并保存预览；无效单行以行错误记录，不使其它合法行丢失。导入列表使用 cursor/limit 读取摘要，返回 items、next_cursor、has_more；SQL 只投影摘要，完整 records 仅供详情与确认导入读取。身体指标局部更新参数允许省略已有字段，由领域服务合并后校验完整记录。

会话创建、更新、删除身体指标记录及增加或解除饮食图片关联成功后，工具结果提供资源引用与变更信息，在“相关内容”中打开目标记录。删除保留删除前的引用信息；当前状态按实时授权解析，不改写历史工具结果。
