# 用药记录

> 当前执行 / 领域契约。
>
> 负责：药品资料、批次库存、原件、用药计划和站内提醒的业务规则。
>
> 不负责：HTTP 路由、物理表定义与视觉数值。
>
> 上位文档：[产品需求](../产品/产品需求.md)。相关契约：[成员授权](成员与健康档案授权.md)、[HTTP 接口](../接口/HTTP接口.md)、[数据库结构](../运维/数据库结构.md)、[前端交互](../前端/行为与交互.md)。

账号在设置的“药品目录”中维护药品目录，成员在用药记录中维护“药品库存”和用药计划。目录药品不属于某一个成员，多个成员可以引用同一目录药品；各成员的库存和计划独立保存。

会话能力分为“药品目录”Skill `medication-catalog`、“药品查询”Skill `medication-query`、“药品库存”Skill `medication-inventory` 和“用药计划”Skill `medication-plan`。药品查询集中提供全部药品读取工具，查询资料与原件、库存与批次、用药计划；药品目录只提供目录资料与原件写入，库存与计划分别提供各自写入。各 Skill 只说明本领域规则，所需查询由模型按需读取药品查询 Skill 读取。已有目录资料的修正和删除通过设置页面完成；原件可由会话工具或设置页面补充。

## 药品目录

设置页面通过普通 API 创建、更新、删除药品基本信息，并补充原件。通用名必填且不得为空字符串或纯空白；商品名允许未知，浓度含量、包装规格、处方类型、备注和说明书链接允许未知。显示名称按“商品名 通用名”生成，相同名称只显示一次。名称相同不构成同一药品的判定依据。

用药记录页面只读引用目录资料，不能编辑字段、补充原件或删除目录药品。目录缺少药品时，可在聊天中按药品目录 Skill 添加，或由用户在设置中添加；添加库存药品时选择目录药品，再保存数量、有效期和批次备注。计划允许引用尚无库存的目录药品。

### 聊天中提供药品

用户通过拍照、附件或文字提供实际药品时，默认核对药品目录、收录缺少的药品资料并保存对应药品附件原件；明确只查看或不保存时遵守其限定。普通药物知识咨询、举例和假设不构成默认收录授权。

模型实际读取材料后，先用药品名称等线索查询目录，按名称、浓度含量和包装规格核对，必要时调整关键词；分页由 Harness 自动继续。无法读取、身份不明、多项匹配无法确定或查询失败时继续取证或询问，不推定目录不存在。

已有对应药品时复用该药品，将本次提供的对应附件补充为原件；没有对应药品且事实充分时，通过 `create_medication` 一次保存已确认的目录资料与对应附件原件。用户同时提供实际持有数量、批次或采用的用药安排时，按系统提示词的默认导入授权主动维护对应库存或计划，不重复询问保存意愿；只缺少影响执行的必要事实时再询问。仅有包装规格不代表持有数量，说明书剂量不代表成员用药安排，不能由药品图片自行制定计划。

这些判断由模型读取 Skill 后，根据每次 Observation 执行；Harness、附件路由与服务端不设置固定业务调用顺序。原件由模型选择当前会话可见附件，创建药品时随 `create_medication` 一同保存，为已有药品补充时使用 `add_medication_sources`；只有文字描述而没有真实附件时，不伪造原件。通用名未知时先取证或询问用户，确认后才能创建；其它目录字段未知时保持未知，写入请求重试复用稳定请求标识。

### 批次库存

库存按批次保存有效期截止日期、准确十进制数量和备注。数量由用户人工维护。有效期截止日期包含当天；页面按浏览器本地日期判断，当前日期晚于截止日期时标记“已过期”。未记录有效期时不推断过期，数量为零不影响过期状态。过期批次继续显示，并遵循原有权限查看、编辑及删除。

库存数量接受不超过 120 字符的非负普通十进制文本，不保存数量单位。有效期只接受合法日期 YYYY-MM-DD，可空；不保存精度字段。

### 药品原件与说明书

原件通过设置中手工上传或会话工具保存，归药品目录所在账号；一个药品可以有多份原件，每份原件只归属一个药品。首份来源为主来源，补充原件保留已有主来源。批量保存校验全部内容，重复或失败时不产生部分写入，物理原件独立于聊天存续。用药记录页面可预览原件，不能补充原件。

`read_medication_information` 按关键词或药品标识只读查询当前成员健康档案所有者的药品目录，支持字段选择，由 Harness 自动读取全部匹配页；选择 `sources` 时返回来源元数据并将来源原文交给模型。`read_medication_inventory` 返回当前成员在该药品下的库存批次；没有批次时返回空数组，不能推断为已明确零库存。`create_medication` 根据已确认材料一次保存目录药品与对应附件原件；资料、原件关联、文件和请求结果共同提交，任一部分失败时撤销整次创建并清理已写文件。没有附件时可仅保存药品资料。创建药品不同时创建库存或计划。会话添加和原件补充需要当前成员健康档案所有者账号权限，共享成员编辑权限不包含账号目录添加和原件补充；读写目标始终为该成员所有者的目录。

`add_medication_sources` 使用当前会话可见附件标识，文件名、类型和内容由经过权限与完整性校验的附件读取能力提供，模型不能提交路径或伪造正文。支持一次补充多份原件；重复或无效文件导致整批失败，模型依据工具结果排除已确认重复的文件或修正后继续。同一请求重试复用稳定请求标识。创建药品返回包含已保存原件的完整药品结果；给已有药品补充原件返回该次保存结果。多种药品部分完成时如实说明。

说明书链接仅接受 HTTP 或 HTTPS，未知时为空。处方与说明书记载不能自动当成成员的用药计划或实际服药经历。

## 用药计划

`read_medication_plan` 是会话中读取用药计划的唯一工具，支持关键词、状态、日期范围、计划标识 `medication_plan_id`；筛选共同生效，由 Harness 自动读取全部匹配页。每页返回 `items`、`total` 和 `pagination`，每项包含完整计划内容、当前药品身份和时间状态，`pagination.complete` 标明整个查询是否读完。指定其它成员或已删除的计划时失败；有效标识与其它筛选无交集时返回空列表。计划查询、创建和更新的工具结果不包含页面路径，界面关联通过 `resource_refs` 提供。

创建和切换用药计划从当前成员健康档案所有者账号的药品目录选择，不能直接提交药品名称或身份。目录没有药品时，按药品目录 Skill 完成有依据且获授权的药品创建后，使用工具结果中的药品标识。计划只保存 `medication_id`；每次读取、列表和通知展示都从目录读取当前药品身份。

每条计划直接保存剂量、给药途径、用药周期、频率和状态，所有字段属于同一条计划记录。相同药品允许创建多条独立计划，分别维护各自的周期和用法，不按药品合并，也不在计划内追加用药安排。计划之间不限制周期重叠。更新当前安排直接更新该计划；需要保留不同周期或用法时创建另一条计划。创建与更新均整次事务保存。使用状态保存明确反馈的值，日期计算的时间状态作为独立返回字段，不覆盖使用状态。

每条计划开始日期必填，创建时必须同时提供 starts_at 和 start_precision；更新时省略字段保持原值，不能清空。用药周期以含开始、不含结束的区间表达，结束晚于开始；结束边界 ends_at 为 long_term 表示用户明确的长期使用，为 null 表示结束日期未知；这两种值的 end_precision 必须为 null。具体结束时间为带偏移 ISO 时间，并同时提供 date 或 minute 精度。页面按进行中、未开始、已结束筛选，列表摘要仅显示本地用药周期、频率和时间。明确的在用、暂停、停用、完成或未确认状态仍按用户表述保存，不能从时间推断实际使用。用药原因、未结构化用法等补充说明统一填写计划备注。

已知时刻为带偏移 ISO 时间并保存 IANA 时区。日期精度为当地日边界；结束日期界面显示最后使用日，存储为次日日边界。开始日期不明确时须先向用户询问，不能用含糊说明代替必填日期，也不能擅自填入当天。未知剂量和途径保持未知。计划经过最后使用日仅改变时间状态，未明确完成时不推定实际完成。

频率只支持未记录、按需、每日、每隔若干日、每周指定日；未记录保存为 schedule=null。每条计划只保存一个每次剂量，所有用药时间共用；固定钟点条目只保存时间。次数已知但钟点未知可保存；缺少必要时间及按需不启用定时提醒。

### 删除

目录药品仍被任一成员的库存或计划引用时拒绝删除。删除目录药品只清理其原件；删除库存批次或计划不影响目录资料。删除成员清理其库存、计划和成员作用域请求，不删除账号目录药品及原件，也不影响其他成员引用。

## 站内提醒

统一接收、通知状态及恢复规则见[站内通知](站内通知.md)。应用层按已保存计划计算下一次到期时间，计划或权限变化立即重算；公共调度器在到期时唤醒并核验有效性。用药提醒只允许在预定时间起 10 分钟内发出，超时跳过。药品批次在有效期截止日结束后且仍有库存时发出一次过期提醒，每个账号对每个批次只接收一次；开启通知时也检查当前过期批次。

固定钟点使用保存的 IANA 时区，夏令时缺失钟点顺延至首个有效分钟，重复钟点取第一次。按需、没有固定钟点、暂停、停用和完成的计划不产生定时通知。有效性摘要覆盖药品引用、周期、精度、时区、剂量、途径、频率和使用状态；目录药品名称与规格变化后显示当前信息，通知继续有效。换药、安排变化、暂停、结束或删除使旧提醒失效。标为已读只改变通知状态。

## 共同执行规则

所有操作经实时授权。页面走 API → Service → Repository，会话走工具 → Service → Repository。工具仅提供单一能力，调用顺序由模型自主决定。普通咨询和处方解释不自动授权保存；实际药品资料的默认收录遵循上述规则，不能把建议当成实际用药。工具顶层描述见项目开发规则，完整参数说明由工具参数 Schema 提供。

页面药品目录和计划目录采用轻量投影及游标分页；会话药品信息查询按字段选择返回资料，原件按需读取，库存通过独立工具读取；涉及多个用药存储的事务使用统一锁顺序。通知由程序自动调度和投递，用户通过通知页面和设置页面管理本人通知。

药品资料、用药计划和药品批次通过工具结果的资源引用进入会话“相关内容”。创建、更新、补充原件及删除同时提供对应变更信息；批次引用包含所属药品标识，直接定位目标批次。删除保留删除前的引用信息，会话查询按实时授权解析当前可用性和更新时间，不改写历史工具结果。
