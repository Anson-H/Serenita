## 字段与解读引用契约

报告公共事实、列表统计和详情分别表达。`flagged_count`、`total_count` 属于列表统计；详情包含 `analysis_updated_at`；`other_report` 使用对象或空值。各类型的字段、存储映射、必填限制和可编辑范围由当前领域 Schema 派生，前端新建与详情编辑共用类型化字段元数据，收藏快照使用相同字段名称。

`write_report_analysis` 在服务端绑定阶段读取当前轮次可信联网工具观测，把解读结果中的合法 `[cite:引用标识]` 转成普通 Markdown 链接后保存。模型不能提交可信引用映射。无法解析时返回 `REPORT_CITATION_UNRESOLVED` 及具体标识，由行动模型决定如何继续；围栏代码、行内代码和转义文本不转换。手工编辑保存普通 Markdown，通用渲染器默认保留未知标记。保存后的解读结果、详情、收藏和复制使用相同链接，不改写既有数据。

## 报告插件与能力边界

报告插件通过通用 `PluginRuntimeContext` 获得可信 `account_id`、固定 `member_id`、模型网关、事件记录器、工具观测解析器、会话资源解析器和隔离的 `ReportService`。成员访问解析同时提供操作者的 `account_id` 与健康档案所有者账号的 `account_id`；`ReportService` 和 `ReportRepository` 始终按健康档案所有者账号 ID 定位报告库，因此账号用户标识更新后仍访问同一成员的医疗数据。

`ConversationService` 不引用报告工具名称，也不根据报告结果选择下一步。插件产生的业务影响通过通用 effect envelope 返回：

```json
{
  "resource_refs": [
    {"resource_type": "report", "resource_id": "LAB-..."}
  ],
  "affected_resource_refs": [],
  "created_entities": [],
  "changed_entities": []
}
```

查询和成功写入使用 `resource_refs` 返回当前可打开的报告快照；删除等操作可用 `affected_resource_refs` 保留已受影响对象的安全展示快照，`created_entities/changed_entities` 只描述当前轮次关系。`ConversationService` 只按通用资源解析器生成消息资源引用和当前 `resource_states`，不解释报告业务。前端根据同一轮次的真实 effect 把报告关系投影为“当前轮次创建/查阅/修改/重新分类/更新解读/关联来源/删除”，并按引用自身的成员与报告身份解析当前资源状态，显示“已修改”“已删除”或“无权访问”；“已删除”和“无权访问”条目禁止点击，不显示报告详情快照；这些展示不修改历史工具结果，也不从回答文本猜测报告。

当前报告技能：

| 技能 | 能力边界 | 实际授权工具 |
| --- | --- | --- |
| `report-import` | 解析、校验并安全导入当前可见线性会话中的医疗报告；不自动解读 | `validate_parsed_reports`、`create_report`、`link_duplicate_sources`、`merge_report` |
| `report-analysis` | 基于当前轮次真实读取的原始证据生成或重写解读结果 | `write_report_analysis` |
| `report-query` | 只读查询报告、指标和跨报告差异，也是其它报告能力的共享取证入口 | `read_report_catalog`、`read_report_information`、`read_report_analysis`、`read_lab_dictionary` |
| `report-update` | 新增检验指标记录、更新字段或元数据、重分类或删除明确目标 | `validate_parsed_reports`、`update_report_fields`、`add_lab_report_items`、`delete_lab_report_items`、`reclassify_report`、`delete_report` |

技能文件可以维护领域操作规程，包括编号步骤、必需取证、条件分支和工具调用顺序。规程由行动模型按需读取并结合真实工具观测执行；技能加载器、Harness、Service 和 Repository 不把它编译或复制为第二套业务状态机，也不通过静态 intent 替模型选择技能。导入、解读或更新需要读取当前报告证据时，模型还必须读取 `report-query`；读取某个写入技能不会隐式授权查询工具，也不会由后端替模型加载另一个技能。

## 报告工具契约

报告插件注册以下工具：

| 工具 | 类型 | 固定顶层描述 |
| --- | --- | --- |
| `read_report_catalog` | 只读 | 读取当前账号中匹配的医疗报告目录，返回用于定位医疗报告的目录信息。 |
| `read_report_information` | 只读 | 读取匹配医疗报告的报告事实。 |
| `read_report_analysis` | 只读 | 读取匹配医疗报告的既有解读结果。 |
| `read_lab_dictionary` | 只读 | 读取当前账号的完整检验指标分类目录。 |
| `validate_parsed_reports` | 校验 | 校验一批最终医疗报告并返回完整解析校验结果。 |
| `create_report` | 写入 | 将完整解析校验结果中的一份医疗报告写入报告档案库，返回创建结果。 |
| `link_duplicate_sources` | 写入 | 将已验证来源关联到一份既有医疗报告，返回关联结果。 |
| `merge_report` | 写入 | 将新增报告事实和来源合并到一份既有医疗报告，返回合并结果。 |
| `write_report_analysis` | 写入 | 将解读结果写入报告档案库中的目标医疗报告，返回保存结果。 |
| `update_report_fields` | 写入 | 更新一份医疗报告的基础信息或结构化内容，返回更新后的医疗报告。 |
| `add_lab_report_items` | 写入 | 向一份检验报告添加检验指标记录，返回更新后的医疗报告。 |
| `delete_lab_report_items` | 写入 | 从一份检验报告删除检验指标记录，返回更新后的医疗报告。 |
| `reclassify_report` | 写入 | 使用经过校验的新结构重分类一份医疗报告，返回重分类后的医疗报告。 |
| `delete_report` | 写入 | 删除一份医疗报告及其已保存内容，返回删除结果。 |

表中描述逐字对应模型可见工具顶层描述，不承载参数、格式、缺省值或行动规程。工具实际访问范围受服务端绑定的当前成员及其实时健康档案权限限制；`read_lab_dictionary` 因而读取该成员健康档案所有者账号的检验指标分类目录，不读取受邀操作者自己的目录。

工具参数结构只包含模型可决定的业务参数。不可变 `account_id` 由 Runtime 可信绑定，真实文件路径与数据库访问由服务端解析；来源、完整解析校验结果和允许引用的报告原件通过当前会话线性视图中的真实工具观测解析。

四个报告读取工具的模型可见 Schema 不接受 `cursor` 或 `page_size`，成功结果不包含 `next_cursor`。Service 先从同一份当前数据快照取得完整匹配集合，再分别按目录 24 条、详情 12 条、检验指标分类目录 100 条、解读结果 24 条形成内部逻辑页；Harness 合并后仍以完整 `reports`、`items` 或 `analyses` 数组返回。跨页 `resource_refs` 聚合去重后只随同一个结果发送一次。

## 报告导入

### 最终结构与来源

当前消息文本、图片、PDF 和多个附件由主行动模型整体理解。模型形成最终报告列表后调用 `validate_parsed_reports`，每份报告提交结构化字段和有序来源索引。

允许的可信来源包括：

- `conversation_attachment`：引用当前会话线性视图可见附件 `visible_attachments`（含历史轮已上传且仍可见的附件）中的准确 `resource_id`；附件名统一使用 `original_filename`。
- `conversation_text`：服务端绑定当前用户消息原文，模型不重传文本。
- `report_source`：重分类时引用当前轮次 `read_report_information(fields=["sources"])` 工具观测返回的当前报告原件；引用必须包含真实 `read_call_id`、`report_id` 和 `resource_id`。

一个来源可以支持多份报告，多份来源也可以共同支持一份报告。模型不得用文件名、序号、临时别名或猜测值代替真实资源 ID。

### 语料判断

导入判断使用三个独立的只读工具：`read_lab_dictionary` 一次返回健康档案所有者账号的完整检验指标分类目录，`read_report_catalog` 一次返回完整匹配目录，`read_report_information` 一次返回完整匹配医疗报告的报告事实。结果整体超出上下文预算时，模型应缩小筛选或字段后发起新的查询；失败结果不代表已取得部分语料。会话历史中的早前导入结果不代表当前报告档案库状态，判重、合并和回答是否已经导入时必须以当前轮次取得的工具观测为准。

模型根据当前轮次工具观测自主选择：

- 创建新的 canonical 报告。
- 为完全重复内容关联来源。
- 对没有旧值冲突的内容执行合并。
- 因差异或指标映射歧义询问用户。
- 判断无需写入或明确停止。

系统不使用日期、相似度或静态阈值预筛语料，也不把判重或下一步动作交给 Service 硬编码决定。

### 事务写入与冲突

三个导入写入工具都使用 `parse_call_id + report_index` 引用当前会话线性视图中 `validate_parsed_reports` 返回的完整解析校验结果；`link_duplicate_sources` 和 `merge_report` 还要求模型给出 `target_report_id`。Runtime 从对应工具观测解析医疗报告的完整内容和有序可信来源，模型不能在写入调用中重传或改写完整解析校验结果。

- 创建时第一个来源成为主来源。
- 关联和合并保持已有主来源。
- 合并只填补缺失字段和新指标。
- 不同旧值或映射歧义返回 `REPORT_IMPORT_WRITE_CONFLICT`。
- 目标报告在写入前已经删除、合并或移走时明确失败，不恢复对象或猜测替代目标。
- 失败调用没有部分写入。

完整解析校验结果、重复判断和冲突只存在于会话工具结果和工具观测，不创建候选、待审、待决、冲突或放弃实体。后续用户回复可以继续引用当前会话线性视图中的完整解析校验结果。

### 报告导入与解读隔离

医疗报告在用户没有明确要求“不保存/只查看”时默认导入，但导入不授权报告解读。未获报告解读授权时，Agent 不得顺带总结正常或异常指标、判断医学意义或写回解读结果正文；判重或合并所需的最小差异说明除外。

## 报告查询、解读与修正

### 查询与比较

`read_report_catalog` 用于定位目标，`read_report_information` 用于读取报告事实和原始证据，`read_report_analysis` 只读取既有解读结果。原始证据永不混入 `analysis_content`。

跨报告查询使用 `read_report_information` 读取原始证据，并保留报告日期、`result_text`、`reference_text` 和 `flag_text`。

### 报告解读

用户点击“开始解读”或“重新解读”，或者在当前消息明确要求报告解读，即构成当前写回授权。附件导入本身不构成授权。

`report-analysis` 技能正文规定原始证据读取要求。`write_report_analysis` 接收 `report_id` 和 `analysis_content`，Runtime 绑定会话与来源消息，Service 在事务中把解读结果写入当前成员的目标医疗报告。

### 会话内修正与删除

明确字段修正（包括就诊时间）、检验报告指标新增与删除、重分类和报告删除分别使用 `update_report_fields`、`add_lab_report_items`、`delete_lab_report_items`、`reclassify_report` 和 `delete_report`。字段修改及指标新增、删除都在单份目标报告内通过同一事务处理一个或多个项目，任一项目无效时不产生部分写入。新增指标必须存在于健康档案所有者账号的检验指标分类目录、主分类与目标报告一致且尚未存在；普通并发修改采用最后有效写入优先，不绑定内容版本。新增或删除指标后既有解读结果标记为过期。删除报告中的检验指标不影响账号检验指标定义；删除后没有剩余指标时明确失败，不自动删除整份报告。

用户已经明确目标和值时无需重复确认；目标、字段、新值或删除对象不明确时自然追问。系统不创建通用变更提案。

重分类还需通过 `read_report_information(fields=["sources"])` 读取目标报告全部已保存原件，主 Agent 基于当前原始证据和全部来源形成新的最终结构，再通过 `validate_parsed_reports` 校验。`reclassify_report` 使用 `report_id + parse_call_id + report_index` 在同一事务中替换，保持报告 ID、执行时的报告时间和全部来源不变，全程没有工具内部模型调用。

### 报告页面 CRUD

报告页的手工创建、补充原件、字段编辑、检验指标记录新增与删除、手工解读结果正文编辑和删除是用户已经明确发出的页面命令，直接走 API → Service → Repository，不创建会话、不调用工具、不追加二次业务确认。补充原件只保存并关联用户明确选择的文件，不解析或修改报告事实；目标没有来源时第一份新增原件成为主来源，已有主来源时保持不变。检验指标新增从目标报告当前分类的账号检验指标分类目录选择尚未存在的指标；删除最后一条指标会失败，不自动删除整份报告。手工创建消费用户已经填写的五类结构化字段，可以没有来源文件；它不同于 Agent 导入使用的 `create_report` 工具，不接受完整解析校验结果引用，也不替用户推断报告边界或医学内容。

页面请求不携带内容版本。目标存在时以后提交的有效操作为准；目标因删除、合并或移动已不存在时，后端返回明确错误，前端保留提示。

## 报告概念模型

报告数据库位于健康档案所有者账号的私有目录。报告业务数据只保存正式报告、可选的正式来源关联、时间戳和解读结果；会话中的完整解析校验结果不落入报告候选表。会话导入的报告必须有来源，页面手工创建的报告可以没有来源。

每份正式报告拥有稳定报告 ID，并通过不可变 `member_id` 永久关联一名成员，包含报告类型、名称、医学报告时间、可选机构以及独立的解读结果正文和过期状态。重分类不改写报告 ID。解析中、冲突中、待确认或异步报告解读等流程状态不进入报告档案库。

报告库中的 `member_id` 对应全局成员归属和健康档案所有者账号的成员资料，但这些记录位于不同数据库，SQLite 不能跨库建立外键。`ReportService` 每次操作都从当前授权解析健康档案所有者账号并限定成员作用域，成员删除事务则把已存在的报告库一同加入同一事务。报告库内部的五类明细表使用 `(report_id, member_id)` 真实外键连接主报告；成员不一致的明细会被 SQLite 拒绝，删除主报告时明细级联删除。

`reports` 的准确列、主外键、默认值、检查约束和索引见[数据库结构中的 `reports.db`](../运维/数据库结构.md#reportsdb)。本文只维护这些值的报告领域语义。

### 来源文件

报告原件保存 MIME 类型、文件字节数、受控相对路径、文件 SHA-256、来源形态和创建时间。文件成为报告来源时，服务端为它生成独立、稳定的报告原件资源 ID，并将原件保存到健康档案所有者账号的 `reports/attachments/{resource_id}.{ext}`。该资源 ID 与会话附件资源 ID 分离；接口中的 `filename` 从受控相对路径提取，不单独存储上传时的原始文件名。报告与原件形成多对多关系，并可标记主来源；一份报告可以关联多个原件，一个原件也可以被多份报告关联。页面手工创建且没有原件的报告不创建虚假来源；用户可以随后通过报告详情补充原件。补充原件按内容拒绝目标报告内的重复关联，整次选择先完成格式、大小和重复校验，再保存并关联，任一文件无效时不产生部分写入。

来源路径只存在于 Repository 控制的数据中，不接受模型或客户端传入。删除报告时，同一事务删除关系并把孤立文件加入文件清理队列；实际文件清理失败可以安全重试，不影响数据库删除结果。仍被其它报告引用的文件不清理。

文件清理队列只保存待处理的成员与相对路径，不连接已经删除的报告或来源记录。这样数据库内容可以先完成删除，文件清理失败时任务仍能独立重试。

会话消息文本作为报告来源时，由服务端保存为受控文本来源；模型不能重传或伪造原文。

### 五类报告事实

- 检验报告保存指标身份、分类、名称快照、结果原文、参考范围原文和结果标记。
- 检查报告保存检查名称、临床诊断、检查方法、检查所见和检查诊断。
- 病理报告保存送检标本、大体检查、病理诊断和取材部位。
- 手术报告保存术前/术中诊断、麻醉、起止时间、输血/失血/尿量/输注/用药、手术经过和术后生命体征。
- 其它报告保存没有适配前四类结构的正式正文。

检验结果标记只允许 `未标记`、`正常`、`异常`、`偏高`、`偏低`；未提供状态时使用 `未标记`。五类报告的准确表、列、PK/FK 和级联规则见[数据库结构](../运维/数据库结构.md#reportsdb)。

### 检验指标分类目录

检验指标分类目录由指标、分类及两者关系组成。指标 ID 稳定，展示名称允许跨主分类重复。每个指标必须有且只有一个主分类，并可关联多个关联分类；检验报告通过稳定指标 ID 引用主分类关系，同时保存当前展示名称。名称或别名只在同一主分类内冲突，不同主分类的同名指标保持不同 ID，编辑和合并均按稳定 ID 定位。目录由健康档案所有者账号内的全部自有成员共用。受邀编辑导入只能补充新指标与别名，不能修改既有分类口径；目录管理只允许操作账号自己的目录。无法唯一匹配的指标不由后端猜测映射。

字典写操作使用 `dictionary_revision` 做 CAS。指标或分类改名、更换主分类会更新受影响报告结构并使既有解读结果过期；分类改名同步更新检验报告名称。增删关联分类保持历史结果不变。指标删除执行级联清理并在响应 `effects` 中返回影响；分类删除条件为主分类关联数为零。

现有指标编辑后的规范名称或别名与同一主分类内另一指标冲突时，API 返回结构化 `LAB_DICTIONARY_NAME_CONFLICT`、冲突目标 `item_id` 和名称，设置页只提供“合并指标”或“放弃修改”。合并是单事务操作：保留目标规范名称、说明和主分类，把来源规范名称与既有别名并入目标别名，把来源分类并为关联分类，并迁移受影响结果。同一报告，或同一原件与报告时间中已经存在目标指标时，只有结果、参考值和异常标记一致才能去重；任一值不同则返回 `LAB_DICTIONARY_MERGE_RESULT_CONFLICT`，整笔合并不写入。

## 领域验收

- 报告工具目录与当前插件注册保持一致，会话写入始终经工具 → Service → Repository。
- 页面手工创建和传统 CRUD 始终经 API → Service → Repository，不伪装成会话工具。
- 导入决策只基于当前轮次的完整解析校验结果与当前报告语料，不创建候选、冲突或待确认业务实体。
- 报告事实和既有解读结果分开读取；报告解读获得明确授权后才写入解读结果。
- 删除、重分类或其它破坏性操作使目标消失后，后续操作明确失败，不恢复对象或猜测替代目标。
- 报告领域概念、来源语义和检验指标分类规则只在本文维护；SQLite 表、列、键、索引与约束见[数据库结构](../运维/数据库结构.md)；物理路径、文件权限和 Schema 生命周期见[本地存储](../运维/本地存储.md)。

## 实现与事务归属

报告插件注册入口组装技能、工具与资源适配器。`RuntimeReportService` 通过显式接口适配领域能力；`ParsedReportObservationResolver` 解析可见工具观测并再次核对来源。模型提交解析调用标识和报告索引，服务端绑定会话、可见消息和真实来源；解析后的报告与来源作为独立领域输入传给 `ReportService`。

`ReportService` 在不可变成员作用域内实时授权，使用独立的报告结构校验、呈现、缩略图和来源存储能力。来源存储完整承担复制、哈希、注册及失败清理，报告查询和报告档案库写入使用相同来源契约。

`LabCatalog` 拥有目录读写，`ReportFacts` 拥有报告使用统计、指标联动、合并冲突检查及事实修改；二者共享显式 `ReportTransaction` 的原 SQLite 连接。目录修改、报告联动、解读结果过期标记、空报告删除和来源文件清理任务在同一事务内提交。目录或事实阶段失败时全部撤销未提交变更；文件删除由已提交清理任务驱动。
