## 1. 版本定位

会话可并发执行且不设产品级数量上限，同会话后续输入进入可恢复队列。离开页面不取消任务，医疗报告任务独立执行。队列支持原样取回编辑、删除、排序和立即执行；取回重交进入队尾。执行中草稿非空只显示发送（上传），为空只显示停止。详见[前端行为与交互](../前端/行为与交互.md#执行与等候队列)。

Serenita v0.2.0 是当前执行版本，交付以下核心能力：

1. 正式交付医疗报告上传、结构化管理、解读、查询、比较和修正能力。
2. 将所有会话任务升级为统一的 Harness Agent 架构。
3. 加入默认关闭、按账号配置且可审计的公网研究能力。
4. 提供成员既往史、健康日记、药品库存与独立用药计划、身体指标及站内提醒。
5. 一个账号管理多成员，并提供逐份只读或编辑授权；不可变 `account_id` 标识操作者，可更新的用户标识服务登录，`member_id` 标识医疗资料所属的人。

Harness Agent 不是一个预先编排好的医疗问答流程。模型根据用户目标、当前会话、附件、按需读取的 Skill 指令和每次真实 Observation，自主决定继续取证、调用工具、修正参数、询问用户或结束回答。系统只提供通用行动循环、可组合能力、证据、权限和安全边界，不用页面、关键词、附件类型或静态 intent 替模型决定完整业务步骤。

这项架构升级为用户带来的直接价值包括：

- 普通健康问答、附件理解和医疗报告任务使用同一套自然交互，不需要选择工作流。
- Agent 可以根据最新 Observation 动态组合医疗报告导入、解读、查询和修正能力。
- `update_plan` 等真实工具请求与结果、上下文装配、模型输出和错误来自真实执行记录，可在界面检查；界面不伪造独立计划状态。
- 长时间运行的任务不依赖 SSE 连接；刷新或重连后可以恢复相同记录和终态。
- 医疗报告导入写入受账号授权、内容与来源校验、事务和并发控制保护；其它写入工具按各自契约校验目标与参数。

## 2. 产品目标与原则

Serenita 是私密、按不可变账号身份隔离的 AI 健康工作空间，帮助患者和家属完成健康问答、整理医疗报告、理解原始证据并控制数据变更。

v0.2.0 的成功标准是：

- 用户可以把图片、PDF 或消息文本中的医疗报告安全整理为可查询的正式医疗报告。
- 用户可以查看医疗报告原件、结构化内容和既有解读结果，并在会话中查询、比较检验指标历史。
- 用户明确要求医疗报告解读后，Agent 基于真实读取的原始证据生成并写回患者可读的解读结果。
- 用户可以用自然语言查询、比较和修正医疗报告，系统不虚构证据或静默覆盖冲突数据。
- 用户可以区分原始医学事实、既有解读结果和当前轮次模型判断。
- 用户可以授权 Agent 在时效性或知识不足时搜索公开互联网，并在相关结论附近核对来源链接。
- 任务在刷新、中断和窄屏环境下仍然可理解、可恢复。

产品保持冷静、透明和临床克制。医学解释必须保留来源、日期、数值、单位、参考范围和不确定性，不把模型回答表述为诊断或处方。

## 3. 版本范围

### 3.1 基础能力

当前版本提供以下基础能力：

- 登录、退出、登录态保持，以及基于 `account_id` 的账号数据隔离。
- 用户标识、显示名称、密码与模型服务设置。
- 普通健康问答、线性会话历史、独立子会话 fork、最新轮次编辑/重新生成与收藏。
- 文件上下文、思考模式、流式输出和生成状态恢复。
- 桌面与窄屏工作台布局。

### 3.2 能力扩展与升级

- 统一 Harness Agent 行动循环。
- 可选轻量任务计划、按需 Skill 读取和动态工具调用。
- 真实执行时间线、持久化 智能体轮次与 SSE 重放。
- 生成与向量模型统一管理、先实测接口的类型识别、对应能力检测、六类默认模型用途，以及按当前轮次实际能力临时调整生成模型推理状态。
- 上下文窗口、输出词元、向量输入及批量输入上限未知时留空，支持手工填写正整数；不通过压力测试推测上限，向量输出维度通过实际调用验证。
- 多文件医疗报告上传和会话文本医疗报告导入。
- 个人信息页面以八个栏目展示既往史，每个栏目直接填写一段文字，页面与独立读写工具共享资料；过敏史记录药物、食物或其它物质相关的过敏、不耐受、药物副作用或尚未确认的反应。
- 医疗报告页按七类结构手工录入新医疗报告。
- 检验报告、检查报告、病理报告、手术报告、门诊病历、急诊病历和其它医疗报告的结构化内容。
- 重复来源关联、无冲突合并和冲突追问。
- 医疗报告列表、类型筛选、详情、原件预览和下载。
- 医疗报告收藏、解读、重新解读和手工编辑解读结果正文。
- 基于原始证据的医疗报告查询、比较、问答和修正。
- 页面手工创建、补充原件、字段编辑、删除与最后有效写入优先的并发语义。
- 不依赖 Skill 的 `web_search`、`web_read` 直接只读工具，以及 Tavily/Exa 账号设置。
- 可验证的回答选区注释、同轮相关医疗报告和按轮次汇总的词元用量。

### 3.3 非本期范围

- 医生端、医院后台、人工审核后台和医院端角色管理。
- HealthKit 与穿戴设备自动同步；已导出文件的手工导入属于当前范围。
- 住院全流程管理、诊疗计划、处方或用药决策。
- 医疗报告公开链接分享、导出和协作审批。
- 多智能体会诊或按业务场景预置的多 Agent 工作流。
- 缺少可靠规则时的跨实验室单位自动换算。

### 3.4 多成员与健康档案授权

当前范围与验收遵循[成员与健康档案授权](../领域/成员与健康档案授权.md)。服务端为账号生成规范 UUID `account_id`，并以它维持账号级数据归属；用户可以维护用于登录的用户标识和用于界面称呼的显示名称。账号可以从零名可访问成员开始，存在可访问成员时有且只有一名默认成员，零成员时默认成员为空。第一名创建或首次获授的成员自动成为默认成员，最后一名自建成员也可删除。成员基础资料以名称为必填项。健康档案所有者账号在授权管理中逐名授予其健康档案的只读或编辑权限，成员基础资料与医疗报告随健康档案授权，聊天、附件、收藏和配置归各自操作者。个人信息以八个栏目展示既往史，每个栏目直接填写一段文字，项目与保存规则见[成员既往史](../领域/成员既往史.md)；过敏史记录药物、食物或其它物质相关的过敏、不耐受、药物副作用或尚未确认的反应；药品库存与用药计划在用药工作区维护。

聊天创建后固定归属一名成员或保持未关联成员；成员删除后清空聊天与收藏的成员关联，保留原内容，不保存名称快照，旧聊天按未关联成员聊天继续使用。选择成员或“未关联成员”都会进入空白新聊天并清空草稿与附件，不复制历史内容。启动默认记住上次选择，包括“未关联成员”；可设为每次选择默认成员。不关联成员的聊天支持健康问答和临时附件，但没有医疗报告档案库目标，也不提供医疗报告、既往史和健康日记工具；用户表达保存意图时由模型结合上下文自然提示添加或选择成员，不设置固定回复或前端强制流程。当前成员的健康档案撤权后静默回到替代默认成员或不关联成员的新聊天，撤权后的旧聊天显示成员当前名称且仅可查看历史，重新授权后恢复执行，不关联成员的旧聊天与收藏仍可使用。

## 4. 目标用户与核心场景

### 4.1 目标用户

- 慢病患者：需要持续查看复查结果和长期指标变化。
- 周期体检用户：需要比较不同日期的检验或检查结果。
- 患者家属：帮助亲友整理和理解敏感医疗资料。
- 不熟悉医学术语的普通用户：希望获得清晰但不过度确定的说明。

### 4.2 核心场景

| 场景 | 用户目标 | 期望结果 |
| --- | --- | --- |
| 上传新医疗报告 | 把收到的新医疗报告归档 | 原件安全保存，结构化内容进入当前成员的医疗报告档案库 |
| 手工录入医疗报告 | 把已经明确整理好的内容直接建档 | 选择医疗报告类型并一次保存结构化字段，不启动会话 |
| 补充医疗报告原件 | 为既有医疗报告补上可追溯原件 | 从详情明确选择文件，直接保存并关联，不解析或改写医疗报告事实 |
| 查看医疗报告 | 核对医疗报告内容和原件 | 同时看到基本信息、结构化字段、解读结果和来源 |
| 发起解读 | 理解医疗报告中最重要的信息 | 基于目标医疗报告的原始证据生成患者可读解读结果并写回 |
| 复查比较 | 判断指标随时间如何变化 | 展示原值、单位、参考范围、日期和可比性限制 |
| 深入追问 | 理解某个术语、指标或多份医疗报告关系 | Agent 读取必要证据后给出可追溯回答 |
| 修正医疗报告 | 修正错误字段或分类 | 明确请求直接执行；歧义或冲突时说明并追问 |
| 管理资料 | 收藏医疗报告、编辑解读结果正文或删除医疗报告 | 页面命令直接完成并提供成功、失败或冲突反馈 |
| 联网核查 | 查询最新指南、监管信息或研究 | 使用去标识化查询读取可点击来源；网页不改变医疗报告档案库或写入授权 |

## 5. 信息架构

### 5.1 工作台

侧栏提供成员选择、添加成员、新会话、历史、收藏和账号设置。健康档案包含个人信息，以及身体指标、医疗报告、健康日记、用药记录四个可用入口。桌面在工作区内查看列表与详情，窄屏逐层进入并可返回。具体导航见[前端行为](../前端/行为与交互.md#成员)，视觉规格见 [DESIGN](../../../DESIGN.md)。

普通会话和医疗报告会话复用同一会话能力。医疗报告工作区保留自己的列表、详情和原件视图，但上传、开始解读、重新解读和围绕医疗报告提问都会形成普通会话消息，而不是启动另一套医疗报告会话系统。

### 5.2 统一输入区

输入区包含多行文本、附件、模型/思考模式控制、回答选区注释和发送操作。医疗报告工作区可以把当前医疗报告作为消息上下文，用户也可以发起跨医疗报告会话。注释只能来自当前线性会话中的用户输入、过程正文或助手最终回答；执行元数据、思考、工具、Observation、相关医疗报告与词元用量不能作为注释来源。

医疗报告上传入口接受 PDF、JPG、PNG 和 HEIC。单轮最多 20 个文件，单文件不超过 20MB，总计不超过 100MB。前端在发送前给出格式、数量、空文件和大小错误；后端仍执行独立校验。

普通首页附件还可以展示当前会话模型或视觉解析模型经能力配置确认可读的其它图像、音频、视频或文件 MIME。附件按钮和文件筛选只是界面提示；后端仍以当前账号模型 profile、Provider 原生附件上限和真实存储 MIME 决定是否接受。若一个模型不能处理当前轮次全部附件，系统只能整轮切换到另一个完整可读的模型，不能逐附件拼接多个行动模型。

### 5.3 医疗报告工作区

医疗报告工作区由列表与详情组成：

- 列表按医疗报告日期降序组织，支持全部及七类医疗报告筛选。
- 列表项展示医疗报告类型和名称，日期作为分组标题；异常医疗报告保留原医疗报告异常提示。
- 详情展示基本信息、结构化内容、解读结果和来源文件，并允许有编辑权限的用户补充原件。
- 原件支持缩略图、图片/PDF/文本预览和下载；只显示当前账号有权访问的来源。
- “添加医疗报告”允许选择上传文件或手工录入；上传进入 Harness，手工录入选择医疗报告类型并填写当前结构化字段后直接创建。
- 从医疗报告详情开始解读、重新解读或提问时进入标准单栏会话页，不建立医疗报告详情与会话的左右分栏；窄屏的列表、详情和原件逐层进入并提供明确返回操作。

### 5.4 收藏与历史

医疗报告可以保存为 `report` 收藏，无论是否已有解读结果。收藏保存来源引用以及收藏时的完整医疗报告快照，包括医疗报告事实和当时已有的解读结果；`analysis_content` 随医疗报告收藏，但不能作为独立收藏对象。会话历史恢复当前线性视图、医疗报告引用、执行记录和最终回答；父子会话继承相同消息 ID 时仍以 `(source_session_id, source_id)` 隔离收藏。

### 5.5 联网设置

账号设置提供“联网”区域，包括总开关、当前 Tavily/Exa 服务，以及两家各自的 API 地址、API key 保存、显隐和测试。联网默认关闭；启用前当前服务必须已有密钥。API 地址按账号和服务分别保存，并由连接测试、搜索和网页读取共同使用；普通加载不返回密钥，用户主动点击眼睛时可以查看当前账号已保存的明文。

## 6. 产品行为边界

### 6.1 统一会话入口

普通问答、附件理解、医疗报告上传、导入、解读和重新解读都通过统一 Harness 执行。会话内自然语言医疗报告查询、比较、修正、重分类和删除也进入同一行动循环。

医疗报告页面中的手工录入、列表、类型筛选、详情、原件补充与读取、字段编辑、解读结果正文编辑和删除通过普通 API 完成。

### 6.2 医疗报告导入与解读授权

附件或消息文本实际包含医疗报告时，除非用户明确要求“不保存”或“只查看”，Agent 默认尝试安全导入。Agent 按医疗报告目录定位相近医疗报告，只读取判断所需的医疗报告事实；没有相近医疗报告且证据支持独立创建时，可以直接选择创建新医疗报告。写入工具内部校验内容和来源，涉及检验报告时还须读取检验指标分类目录。具体规则见[医疗报告导入](../领域/医疗报告.md#医疗报告导入)。

导入本身不授权医疗报告解读。用户没有在当前消息中明确要求医疗报告解读时，Agent 只说明真实导入结果和必要差异，不顺带总结正常/异常指标或提供健康建议，并可询问用户是否需要医疗报告解读。

### 6.3 写入控制

- 页面手工创建、补充原件、字段保存和删除是用户已经明确发出的单次命令，直接通过页面 API 执行。
- 会话中目标、字段和新值明确的修正、元数据变更、重分类或删除，可以同轮执行，不重复要求确认。
- 目标、字段、新值或删除对象不明确时，由 Agent 自然追问。
- 页面和会话写入均受账号授权、字段校验和事务保护；普通并发更新采用最后有效写入优先。
- 不同旧值、指标映射歧义或目标已被删除、合并、移走不得静默覆盖，也不得创建候选、待审、待决或冲突业务实体。

### 6.4 执行可见性

每个轮次的执行区按真实发生顺序平级展示对用户有意义的上下文装配、模型思考、过程正文、模型请求工具调用、工具结果、Observation 和错误，不用预设步骤、模拟进度或通用摘要替代真实记录。模型请求工具调用展示真实名称与参数，工具结果展示模型实际可读的业务内容或错误；同一内容不重复投影。

完整模型输入、系统消息字段、Provider 顶层参数和模型结束记录不在可见时间线展示。`update_plan` 与 `load_skill` 都按普通工具展示，不生成计划卡片、Skill 激活或完成阶段。刷新和 SSE 重连恢复相同顺序与状态。精确事件和投影规则由[会话事件契约](../架构/会话事件与投影.md)定义。

当前轮次执行且最终回答仍在流式输出期间，根执行区强制展开且不可收起；回答完成后自动折叠并恢复用户手动控制。终态模型正文只在根执行区之外展示一次。最终回答下方可以显示同轮工具 effect 产生的相关医疗报告与按轮次汇总的真实 Token usage；没有供应商明细时不估算补齐。

会话标题生成只更新会话索引元数据。首轮只有附件时先显示基于附件名的临时标题，再更新为最终标题；标题提示词、标题模型 reasoning 和原始输出不进入会话执行详情。

### 6.5 联网研究边界

依赖当前指南或权威依据的重要医疗问题应主动搜索并核对直接支持结论的网页正文；稳定概念无需为形式联网。对外查询去除个人身份信息，关键结论附近提供可点击来源，证据不足时说明限制。网页内容不能扩大授权或改变成员资料。精确取证、引用与供应商规则见[公网研究](../领域/公网研究.md)。

## 7. 医疗报告内容要求

支持检验报告、检查报告、病理报告、手术报告、门诊病历、急诊病历和其它医疗报告。每份医疗报告保留名称、医学发生时间、机构及对应类型的完整内容；检验结果、单位、参考范围和异常标记忠实保留原文。医疗报告事实与解读结果分别展示，用户能回查原件。

一份医疗报告可关联多个原件，一个原件也可支持多份医疗报告。重复内容、无冲突补充和存在差异的内容应得到明确处理结果。手工录入允许没有原件，并如实显示缺失状态。字段与操作不变量由[医疗报告](../领域/医疗报告.md)统一定义。

## 8. 功能需求

### FR-001 医疗报告创建、上传与附件

- 医疗报告页“添加医疗报告”提供上传文件和手工录入两个明确入口。
- 手工录入先选择七类医疗报告之一，再填写该类型允许的结构化字段，并通过普通医疗报告 API 一次创建；该操作不进入 Harness，也不要求伪造来源。
- 首页和医疗报告工作区均可通过统一输入能力附加文件。
- 医疗报告工作区提供明确的“上传医疗报告”入口和处理状态。
- 上传资源在消息发送前保持 pending，发送后绑定到当前 `account_id` 与会话；fork 后父子会话各自持有引用并共享不可变原文件。
- 文件签名、MIME、大小和模型可读能力不满足要求时给出真实错误，不伪造导入成功。
- PDF 原生传输或完整渲染全部已验证页面；超过支持页数时明确失败，不能静默截断。

### FR-002 医疗报告理解与结构校验

- 当前消息文本、图片、PDF 和多个附件作为同一份用户输入整体理解。
- 主 Agent 决定最终医疗报告边界、类型、医学分类和每份医疗报告的全部来源。
- 结构校验只验证当前 Schema、日期、医学类别和来源授权，不替模型拆分或判断业务处置。
- 每份通过会话导入的医疗报告必须至少绑定一个当前会话线性视图真实可见的来源；页面手工创建的医疗报告可以没有来源。

### FR-003 安全导入

- 通过目录按需选读相近医疗报告，写入工具内部校验内容和来源；涉及检验报告时依据完整检验指标分类目录确认指标映射。
- Skill 建议及时写入已具备条件的医疗报告，数量较少时可集中处理；具体安排由 Agent 自主决定，结束前核对是否有遗漏。
- Agent 可以根据证据选择创建医疗报告、关联重复来源、无冲突合并、向用户追问或不写入。
- 创建时保留来源顺序；来源关联与合并保留已有主来源。
- 导入合并发现不同旧值、指标映射歧义或目标已不存在时，整次工具调用失败，不产生部分更新。
- 导入完成后展示真实创建、关联、合并、未写入、需追问和失败结果。

### FR-004 医疗报告列表与类型筛选

- 列表只返回当前成员的医疗报告。
- 支持全部、检验报告、检查报告、病理报告、手术报告、门诊病历、急诊病历和其它医疗报告筛选。
- 医疗报告按日期降序分组展示。
- 空列表、加载、失败和筛选无结果都有清晰状态。

### FR-005 医疗报告详情与原件

- 详情展示通用字段和对应医疗报告类型的完整结构化内容。
- 显示主来源及其它来源，支持有权限的缩略图、预览和下载。
- 检验异常强调忠实使用医疗报告中的 `异常`、`偏高`、`偏低` 原始标记，并提供可访问名称，不重新诊断。
- 页面刷新后可以通过医疗报告 ID 恢复详情。

### FR-006 医疗报告解读与重新解读

- 尚无解读结果的医疗报告展示“开始解读”，已有解读结果的医疗报告展示“重新解读”。
- 用户点击操作或在当前消息明确要求医疗报告解读，即构成当前写回授权，无需重复确认。
- 进行医疗报告解读时覆盖目标医疗报告日期及此前的全部成员医疗资料；准确取证与缺口处理要求由医疗报告解读 Skill 承载。既有解读结果仅作为待审核内容。
- Agent 按 `report-analysis` Skill 正文读取原始证据，并通过 `write_report_analysis` 把 Markdown 正文写入目标医疗报告。
- 解读结果以患者可读 Markdown 展示，保留证据范围、日期、数值、单位、参考范围、可比性限制和不确定性。
- 用户可以在详情页直接编辑或清空解读结果正文，该页面操作不进入 Harness。

### FR-007 医疗报告查询与问答

- 支持查询最近医疗报告、指定日期或类型医疗报告、异常项、单项指标和跨医疗报告差异。
- Agent 回答只能使用当前轮次工具实际返回的原始证据。
- 已有解读结果可以单独读取和引用，但不能冒充原始证据。
- 目标不明确或证据不足时，自然询问用户或说明限制。
- 实际读取或更新的医疗报告作为安全资源引用保存在对应消息中，供历史恢复和文件索引使用。

### FR-008 页面创建、字段编辑与删除

- 用户可以在医疗报告页手工创建七类结构化医疗报告；检验报告的指标来自健康档案所有者账号的检验指标分类目录。
- 检验报告以检验分类作为名称；其它六类医疗报告的名称可编辑。
- 机构、时间、类型结构化字段和解读结果正文可编辑。
- 检验指标编辑携带目标 `item_id`；`item_name_zh` 是允许重复的中文指标名称。
- 普通并发保存和删除采用最后有效写入优先，不要求内容版本令牌。
- 若目标已被删除、合并或移走，操作失败并提示用户，不恢复或猜测替代目标。
- 删除医疗报告后清理不再被其余医疗报告引用的源文件；共享来源继续保留。

### FR-009 会话内修正、重分类与删除

- Agent 可向明确的检验报告添加检验指标分类目录中的指标记录、修正指标字段、更新医疗报告元数据或删除明确目标。
- 重分类需要读取已保存原件，由主 Agent 形成新的最终结构，写入工具内部校验后在同一事务中替换。
- 重分类保持原医疗报告时间和全部来源不变；医疗报告时间变化使用独立元数据更新。
- 任何失败都作为真实 Observation 返回，由 Agent 决定重试、换能力、追问或停止。

### FR-010 收藏

- 已保存的医疗报告可添加或取消收藏，尚未生成解读结果的医疗报告同样可以收藏。
- 收藏记录绑定操作账号的不可变 ID、可空成员 ID、来源类型和来源 ID；不关联成员的回答显示“未关联成员”。
- 收藏失效或源医疗报告删除后的行为不得泄漏其它账号数据。

### FR-011 执行记录与恢复

- 消息提交后任务独立于页面订阅继续执行；离开、断线或刷新不取消任务。
- 执行期间根执行区保持展开，终态回答完成后自动折叠；用户随后可检查真实上下文、模型、工具、Observation 和错误。
- `update_plan` 只显示为普通模型工具调用请求和工具结果，不生成独立计划记录、状态或卡片。
- 模型请求工具调用、工具结果与 Observation 在视觉上保持平级且可以准确对应。
- 模型工具调用请求显示真实名称与参数；工具结果显示真实业务 output 或错误，不重复控制元数据，也不用通用摘要替代。
- 稳定回答下方“相关内容”依据同轮成功工具 effect 统一展示医疗报告、健康日记、药品资料、用药计划、药品批次和身体指标，支持打开当前详情及查看更新、删除和权限状态，并汇总同轮所有模型调用返回的 Token usage。
- 断线、刷新和重新连接恢复相同事件顺序、状态和最终回答。

### FR-012 联网搜索与正文读取

- 公网搜索从首个行动步骤直接可用，支持主题、日期范围和域名约束，并完整保留供应商返回的搜索结果摘要。
- 网页正文只能从当前会话真实搜索结果中选择，不能传入任意 URL、账号或供应商来绕过来源链。
- 网页正文不做本地有损截断；无法读取正文或无法完整交给模型时明确失败，不把部分内容伪装成成功结果。
- 当前服务失败不自动调用另一服务；禁用、未配置、认证、限流、额度、超时、无正文和无效响应均形成真实 Observation。

精确工具参数、逻辑分页、上下文预算和引用标识由[公网研究领域契约](../领域/公网研究.md)定义。

### FR-013 自动上下文压缩

- 长会话自动整理上下文，保留当前请求、必要证据和未完成操作，用户无需手动管理。
- 界面展示真实压缩状态、前后用量及失败情况；失败不能丢失原始历史，重试不能重复业务写入。
- 刷新后可继续检查原始执行记录；摘要正文遵循输入追溯偏好。

预算、分块与提交规则见[会话事件契约](../架构/会话事件与投影.md#上下文压缩)。

### FR-014 成员医疗资料

会话中提供当前成员的实际健康资料默认授权主动导入健康档案，包括日记式陈述、身体感受、餐食、身体指标、药品及用药资料、既往史和医疗报告，无需额外的保存命令或保存意愿确认。智能体根据上下文、Skill 和 Observation 选择记录类型及创建、补充或修正，避免重复创建和覆盖无关内容；同一消息兼有咨询时兼顾保存与回答。仅询问影响归属、事实准确性或执行的必要信息。明确只查看或不保存时遵守限定；纯知识咨询、假设、示例、旧资料整理及模型建议不作为新的默认写入目标。默认导入不扩大成员权限，不授权删除、清空或自行制定治疗方案，医疗报告解读仍遵循独立授权。

- [既往史](../领域/成员既往史.md)提供八项健康经历，页面与会话共用已保存内容。
- [健康日记](../领域/健康日记.md)记录日常生活、身体感受、就医经过及后续情况，保留完整日常明细并支持按时间整理；身体指标支持的明细可以按用户目标同时保存为对应记录。日记不维护用药清单和常规服药明细。
- [用药记录](../领域/用药记录.md)提供账号药品目录与原件、成员药品库存和独立用药计划，以及操作者统一管理的站内提醒。聊天中提供实际药品图片或文字时主动核对并收录目录与原件；同时提供实际持有数量、批次或采用的用药安排时主动维护对应库存或计划，必要事实不足时询问，不由包装或说明书推定实际使用。设置页面维护目录与原件，具体授权和取证遵循领域契约。
- [身体指标](../领域/身体指标.md)提供测量、饮食、睡眠、运动、来源区分、趋势及苹果健康或标准文件导入。图片识别结果可编辑并回查原图。

### FR-015 统一站内通知

全局通知中心接收用药提醒、药品过期提醒和回答已生成通知，点击分别进入用药计划、药品批次或对应聊天。用药提醒只在预定时间起 10 分钟内发出，超过时限跳过；药品过期按仍有库存的批次只提醒一次。设置中总开关单独一个列表，三个类型开关共同组成另一列表。全部开关默认关闭。开启总通知时全部子通知开启，关闭总通知时全部子通知关闭；任意子通知开启则总通知开启，全部子通知关闭则总通知关闭。关闭保留已有通知，重新开启不补发关闭期间的用药提醒和回答通知；药品过期提醒检查当前过期批次。最终回答成功保存后仅通知发起聊天的账号，每个完成轮次一条，后续提问或重新生成完成后产生新通知；失败、取消、标题生成和工具保存不单独通知。完整规则见[站内通知](../领域/站内通知.md)。

## 9. 页面状态与交互

医疗报告列表至少覆盖加载、空状态、筛选无结果、失败和已加载状态。详情至少覆盖未选择、加载、已加载、保存中、保存失败、目标已不存在和删除后状态。医疗报告会话任务至少覆盖附件上传、等待执行、执行中、等待用户补充、成功、失败和中断状态。

执行记录在当前轮次运行且最终回答仍在流式输出期间强制展开；最终回答完成后自动折叠，此后允许用户手动展开或收起。刷新和重连按持久化状态恢复相同行为。长文本、表格、工具参数和错误必须在容器内换行或滚动，不能破坏窄屏布局。

删除是用户明确的页面命令，直接执行并反馈结果，不追加二次确认。会话中的明确删除请求按 Agent 写入边界处理。

## 10. 非功能要求

### 10.1 可用性与无障碍

- 所有交互使用语义控件、可见焦点和有意义的辅助名称。
- 折叠、模态框、列表选择、保存和删除可通过键盘操作。
- 状态不能只依赖颜色表达；异常标记同时提供文本或可访问名称。
- 尊重减少动态效果偏好，避免装饰性动画干扰医疗内容。
- 在窄屏和低高度窗口下保持可读、可编辑和可返回。

### 10.2 可靠性

- 已提交会话事件只追加并可重放。
- 工具写入使用事务、账号权限和各自参数契约；导入写入在工具内部校验内容和来源，写入解读结果时在同一事务中确认目标存在，检验指标分类目录写入使用独立 revision 校验。
- 可能已经产生副作用但结果未知的调用不自动重试。
- 医疗报告解析、解读或写入失败保留真实错误，并由行动模型根据 Observation 决定后续处理。

### 10.3 安全与隐私

- 医疗报告与来源在健康档案所有者账号的 `account_id` 目录内保存，并按 `member_id` 隔离所属成员；聊天、收藏、模型及联网配置按操作者 `account_id` 隔离。
- 客户端提交的资源 ID、文件名、模型文本和 Observation 都不能扩大权限。
- API Key、登录凭证、Cookie 和附件二进制不写入会话事件。
- 医疗报告源文件使用私有目录与文件权限，拒绝符号链接和路径越界。
- 非空数据库在写连接前只读验证当前 Schema；不支持的结构返回 `UNSUPPORTED_SCHEMA`，不自动更新。

### 10.4 时间

显示、编辑和按日浏览统一使用浏览器本地时区；打开日期选择器、再次选择相同日期或失焦均不能改变原时刻。纯日期保持日历含义。统计使用同一时区的日期边界，并正确处理跨日和夏令时。来源时区可追溯，传输和存储规则见[职责边界](../接口/前后端职责边界.md)。

## 11. 验收标准

### 11.1 Harness Agent

- 普通问答和医疗报告任务都进入同一个行动循环，没有页面或关键词专用编排器。
- 简单回答或单一明确操作不会被强制创建任务计划。
- Agent 可以按需读取一个或多个 Skill；完整 Skill 目录不会因读取历史缩减。
- 工具成功和失败都形成真实 Observation，并能影响模型下一步行动。
- 原生工具调用与文本工具协议共用同一逻辑工具参数 Schema 和行动循环。
- 模型能力按非思考/思考状态探测和持久化；仅当另一状态完整满足当前轮次文本、原生工具调用与附件要求时才临时调整有效推理模式，并在轮次后恢复用户偏好。两种状态都没有原生工具调用时仍可使用文本工具协议。

### 11.2 上传与导入

- 支持限定格式、数量和大小的多文件发送，并拒绝伪造文件签名。
- 一个附件可以形成多份医疗报告，多份附件也可以共同支持一份医疗报告。
- 默认导入和“只查看/不保存”都按用户表达正确处理。
- 读取目录后由 Agent 按需选择相近医疗报告详情；没有相近医疗报告且证据充分时可直接创建，写入工具内部校验内容和来源，涉及检验报告时读取检验指标分类目录。
- 处理节奏由 Skill 建议和 Agent 自主判断决定，结束时如实说明处理结果及未完成事项。
- 重复来源、无冲突合并、不同旧值、映射歧义和目标已不存在均得到符合契约的结果。

### 11.3 医疗报告工作区

- 七类医疗报告均能在列表和详情正确展示对应字段。
- 类型筛选、日期降序分组、空状态、原件预览、下载和窄屏返回可用。
- 页面手工创建、补充原件、字段保存、解读结果正文编辑和删除不创建会话或工具记录。
- 普通字段保存采用最后有效写入优先；目标已被删除、合并或移走时失败且不改写其它对象。

### 11.4 解读结果与查询

- 导入完成但未获授权时不自动进行医疗报告解读。
- 明确要求医疗报告解读时，完成历史资料取证并说明证据范围后写回解读结果。
- 查询和比较保留证据日期、原值、单位、参考范围和不确定性。
- 医疗报告可以连同已有解读结果一起收藏、取消收藏和从收藏详情重新访问；解读结果不单独收藏。

### 11.5 修正与删除

- 页面命令直接走 API → Service → Repository，普通并发更新采用最后有效写入优先。
- 会话内明确修正或删除可以同轮执行；歧义时自然追问。
- 重分类提交当前原件和新结构并由写入工具内部校验，不启动工具内部模型。
- 删除共享来源的某一医疗报告不会删除其余医疗报告仍在使用的文件。

### 11.6 执行可见性与恢复

- 真实执行事件按单层时间线持久化并通过 SSE 重放。
- 可见记录不伪造 Skill 阶段、业务流程或模拟进度。
- 完整模型输入和模型结束记录存在于数据契约，但不会显示在页面时间线。
- 附件首轮标题可以更新，但标题模型细节不会出现在 Agent 执行记录。
- 刷新和重连后记录、医疗报告引用、终态和 Token 汇总保持一致。
- 失败轮次在会话内展示真实持久化错误；注释和相关医疗报告来源均经后端或工具 effect 验证，不从执行元数据或回答文本猜测。

自动上下文压缩的用户验收：长会话可以继续，原始历史仍可追溯；无效摘要不替换有效上下文；取消、重试和重连不重复执行已完成操作；用量和状态如实展示。技术验证遵循[会话事件契约](../架构/会话事件与投影.md#上下文压缩)。

### 11.7 联网研究

- Web 插件自动发现但不增加 Skill 数量；联网规则直接存在于主系统提示词。
- 两个 Web 工具首步可见，医疗报告工具仍需读取对应 Skill；可见性只依据通用 `model_exposure` 元数据。
- 依赖当前指南或权威证据的重要医疗问题会主动搜索，关键医学结论会继续读取直接支持它的正文；稳定概念不强制联网。
- Tavily/Exa 输出统一、使用当前账号为对应服务保存的 API 地址、搜索结果摘要和网页正文均无本地有损截断且支持单次逻辑分页装配、安全搜索/审核和大小/超时边界有效，且不采用供应商生成答案。
- 密钥账号隔离、密文落盘；普通 API 不回传明文，只有认证用户主动触发的 reveal 接口可以读取，且响应禁止缓存。网页证据完整进入现有审计时间线但不产生医疗报告资源引用。
- 设置页在桌面和窄屏可键盘操作，明确展示密钥状态、连接反馈和第三方数据说明；Markdown 外链安全打开。

### 11.8 账号身份与资料

- 注册由服务端生成规范 UUID `account_id`，并创建对应账号私有目录和空成员偏好。
- 用户标识保持大小写不敏感且全局唯一；显示名称支持 Unicode 与内部空格，去除首尾空白后的长度为 1–50 个 Unicode 码点。
- 账号资料保存原子更新 `account` 与 `account_name`，并返回与注册、登录和认证恢复一致的完整认证会话；当前标签页直接采用响应，同账号其它标签页收到刷新事件后读取当前值。
- 用户标识更新保持账号目录、聊天、收藏、健康档案授权、模型与联网配置、凭证以及账号级聊天偏好连续一致；同一账号更换浏览器后继续使用已保存的聊天偏好。
- 授权列表和共享健康档案读取连接当前账号资料，展示接收方与健康档案所有者账号的当前用户标识和显示名称；共享关系始终由不可变账号 ID 与成员 ID 确定。账号资料保存保持双方授权修订号，成员集合、健康档案授权和成员选择偏好变化负责推进对应修订号。

### 11.9 医疗资料与整体体验

- 医疗报告解读覆盖医疗报告日期及此前的全部成员医疗资料；文本资料完整读取，高频身体指标通过完整统计和必要明细覆盖。日期未知、读取失败或预算不足时说明缺口，不能宣称完成完整解读。
- 保存期间继续输入、输入法组合、切分区和导航均不丢草稿；失败保留页面并可重试，迟到响应不覆盖当前对象。
- 身体指标导入支持同文件追加范围；删除批次保留独立、共享及有效更新后的记录，并告知删除与保留数量。
- 不同设备、方法、单位和评分满分的序列可区分；过期睡眠评分明确标记并退出当前评分统计。
- 切换计划药品后旧提醒立即失效；只读共享成员的操作者仍可处理本人有效通知。
- 长列表按需加载；列表翻页不重载统计；大文件处理期间会话仍可响应。
- 桌面、窄屏、低高度、触摸拖动、键盘和主题切换均保持操作可达；图表提供文字详情。

### 11.10 通知时效与可靠性

在后台正常运行、前台在线环境中，以 10 个在线账号、每账号 100 条有效计划，覆盖 50 条同时到期和多个账号的回答完成，持续采集至少 200 次实际展示；端到端 P99 不超过 3 秒，同时报告最大延迟和失败。禁用 30 秒复核后正常到期和即时回答通知分发仍可更新。

验收重复提交、新轮次、账号隔离、失败及取消、提交前后退出、部分失败、断线重连、关闭和重开、权限变化、重启补发、固定遗漏区间、时区、夏令时和系统时间变化。用药与回答通知共享公共表及页面；回答通知读取不创建用药数据库。本期不包含关闭页面或锁屏后的系统推送。
