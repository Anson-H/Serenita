# 本地存储结构

> 文档层级：当前执行 / 运维与存储契约
>
> 负责：本地数据根、物理目录、数据库文件分配、不可变账号作用域、会话事件日志、密钥、文件权限和 Schema 生命周期。
>
> 不负责：详细 SQLite 表、列、键、索引与约束，JSONL 逐行格式与恢复算法，领域流程、HTTP 路由、页面行为、报告字段语义或事件投影。
>
> 上位文档：[技术架构总览](../架构/技术架构总览.md)；准确表结构见[数据库结构](数据库结构.md)，JSONL 编码、header、事件行和恢复见[会话 JSONL 格式](会话JSONL格式.md)，数据归属见[成员](../领域/成员与健康档案授权.md)，报告模型见[报告领域](../领域/医疗报告.md)，事件语义见[会话事件](../架构/会话事件与投影.md)。

本地开发数据根为 `serenita_files/`，测试通过 `DATA_ROOT` 使用隔离的临时目录。每个账号拥有一个以规范 UUID `account_id` 命名的私有目录；用户标识 `account` 独立承担登录与查找职责。成员基础资料、医疗报告与原件在健康档案所有者账号目录内按不可变 `member_id` 隔离所属成员，聊天、附件、收藏和配置使用操作者的 `account_id` 目录。`all_users` 保留为共享系统目录名，同时也是受保护的用户标识。

```text
serenita_files/
  all_users/
    auth/auth.db
    secrets/provider_master.key
    secrets/web_access_master.key
  accounts/
    {account_id}/
      config/settings.db
      conversations/db_storage/conversations.db         # 会话索引、轮次、资源与清理队列
      conversations/sessions/{session_id}.jsonl         # 唯一的会话事件日志
      conversations/sessions/{session_id}.jsonl.lock    # JSONL advisory lock 载体
      conversations/attachments/{session_id}/{resource_id}
      favorites/db_storage/favorites.db
      members/db_storage/members.db
      reports/db_storage/reports.db
      reports/attachments/{resource_id}.{ext}
```

会话事件只保存在 JSONL，`conversations.db` 保存会话、轮次、资源与清理队列索引。会话附件直接写入各自会话的最终平铺目录，不设置统一临时目录；`resource_id` 本身就是实际存储文件名，数据库 `original_filename` 单独保留安全规范化后的原始显示文件名。首次上传 `报告.pdf` 使用同名 `resource_id`，后续同名上传依次使用 `报告-002.pdf`、`报告-003.pdf`，界面仍显示 `报告.pdf`。命名同时检查该会话的全部资源记录和磁盘遗留项，已经使用的名称不再复用；`sha256` 用于写入恢复时的完整性校验，不参与判重或命名。准确表集合见[数据库结构](数据库结构.md#conversationsdb)。JSONL 锁文件正常长期保留且通常为零字节；文件存在不代表当前有进程持锁。新建或全量替换时还可能短暂出现同目录隐藏 `.tmp` 文件，正常成功后移除。

短成员删除、撤权与聊天调度操作通过认证目录内的 `member_lifecycle.lock` 跨线程、跨进程排序：普通操作共享读取锁，删除与撤权独占锁，授权数据库事务负责与报告短操作排序；不跨模型网络请求持锁，不在启动时扫描或改写历史数据。

## 存储职责

- `auth.db` 是全局账号与访问控制面，保存账号身份、登录会话、成员归属索引、逐名成员的健康档案授权和账号授权修订号；不保存操作者设置、成员基础资料或医疗内容。
- `login_sessions` 是登录会话的唯一持久化位置，每行通过 `account_id` 关联当前账号资料；浏览器以 HttpOnly Cookie 持有原始会话令牌。
- 健康档案所有者账号的 `members.db` 保存该账号创建的全部成员基础资料。它与全局 `member_ownerships` 通过相同的 `member_id` 一一对应；SQLite 不能跨数据库检查这项关系，因此成员创建、更新和删除事务共同保证两边一致。病史、过敏史和用药当前不建业务数据。
- 健康档案所有者账号的 `reports.db` 只保存正式医疗报告、报告原件索引、检验指标分类目录和文件清理任务。它与 `members.db` 以及未来身体指标、医疗日志、用药记录等成员作用域数据库平级，业务操作通过 `member_id` 定位同一成员并实时检查授权。
- `settings.db` 保存操作者自己的成员启动模式、默认与最近选择，输入框与回答显示偏好，以及模型 Provider、模型能力与上下文配置、四类默认用途、联网开关、当前服务、服务地址和密文凭证。默认与最近成员 ID 由成员选择事务对照全局成员身份和实时可访问集合写入、替换或清空，不复制成员资料或授权关系。模型与附件语义见[模型运行](../架构/模型附件与推理模式.md)，联网语义见[公网研究](../领域/公网研究.md)。
- 模型 Provider API key 使用带 `serenita-provider-secret:v3:` 前缀的 AES-GCM 密封格式、独立 `provider_master.key`，并以 `account_id + provider_id` 组成 AAD。普通设置接口返回配置状态，认证用户主动点击眼睛时可通过禁止缓存的专用接口读取当前账号密钥。
- Web 凭证与模型 Provider 配置共用 `settings.db`，并使用独立命名空间、带 `serenita-web-secret:v2:` 前缀的密封格式、`account_id + provider_id` AAD 与 `web_access_master.key`。普通 API 返回 `has_api_key`，显式 reveal 响应进入当前设置页；会话事件与前端持久存储始终保持密钥隔离。
- 会话内容保存在版本 2 JSONL 事件日志；`conversations.db` 同时保存会话、轮次、资源和文件清理所需索引。空成员字段表示未关联成员，包括成员删除后清空的关联，分叉索引保留父会话与 seed 关系；标题、置顶和运行摘要是索引元数据，不进入事件时间线。JSONL 格式见[会话 JSONL 格式](会话JSONL格式.md)，事件与投影语义见[会话事件](../架构/会话事件与投影.md)，准确主键、外键和部分唯一索引见[数据库结构](数据库结构.md#conversationsdb)。
- 会话附件先以 `storage_status=writing, lifecycle_status=pending, expires_at=NULL` 登记写入意图，再排他创建并刷新最终文件，完成后改为 `ready + pending` 并设置 24 小时过期时间。正常失败删除意图并把精确路径写入清理队列。进程重启后的维护先按大小与 SHA-256 恢复完整文件；不完整文件不超过五分钟时保持，超过五分钟后删除意图并排队清理。只有 `ready` 能预览、发送或进入模型输入。随消息发送或进入等候队列后原子改为 `ready + attached` 并清空过期时间；定时清理只让到期的 `ready + pending` 依次进入 `expired`、`deleted`，不会清理 `attached`。单轮限制是 20 个文件、单文件 20MB、总计 100MB。fork 固定创建 `ready + attached` 引用行但复用原路径，父子按任意顺序删除都只在最后一个有效引用消失后清理二进制。
- `members.db` 与各平级领域库中的数据都按 `member_id` 隔离。报告原件位于健康档案所有者账号的 `reports/attachments/` 目录；受邀编辑的聊天附件仍位于其操作账号目录，导入时原件复制到健康档案所有者账号目录。成员删除以认证库锁定访问关系，附加所有受影响操作者的 `settings.db` 完成选择回退，再由显式平级库参与注册表在同一事务中清除现有成员数据；提交后执行可重试的物理文件清理。SQLite 表、列、键、索引与约束见[数据库结构](数据库结构.md#membersdb)与[报告库](数据库结构.md#reportsdb)；报告业务含义与操作不变量见[医疗报告](../领域/医疗报告.md)。
- 收藏保存在操作账号的私有数据库中，不逐行重复 `account_id`，只记录可空的 `member_id`；不关联成员的回答依靠来源会话和消息保持唯一，报告来源由非空成员 ID 与报告 ID 共同定位。成员名称由已保存关联实时读取，不保存名称快照。删除成员会在同一事务中清空所有操作者已有聊天与收藏的成员关联，包括曾被撤权的账号；聊天与收藏正文保留。撤权后关联保留，聊天只可查看历史并显示当前成员名称，实时来源访问重新校验健康档案权限。

账号敏感目录使用私有目录权限，SQLite、sidecar、JSONL、附件和密钥使用私有文件权限。所有路径 API 明确接收 `account_id`，先验证为规范 UUID，再作为目录组件；生产访问从已认证账号和会话索引解析目标。注册创建完整 `accounts/{account_id}` 目录和当前 `settings.db`，并在认证库事务中附加配置库写入该账号的空成员选择偏好；认证库已有账号但对应目录或配置库缺失时返回明确的数据缺失错误，以便运维恢复原目录。数据根本身必须是受信任的本地目录。

用户标识可在账号资料中修改，并保持大小写不敏感的全局唯一。资料事务只更新 `accounts` 中当前账号的用户标识、显示名称和更新时间，`access_revision` 继续表达成员集合、健康档案授权与成员选择偏好的变化。`accounts/{account_id}`、登录会话、会话事件、收藏和凭证持续使用同一不可变身份；既有登录会话按 `account_id` 连接账号行并立即返回当前值，共享界面在下一次成员或授权读取时取得当前展示值。

空数据根和空 SQLite 数据库创建[数据库结构](数据库结构.md)定义的当前表。认证数据库模块统一拥有账号、登录会话和成员访问元数据的 DDL 与结构描述；配置数据库模块拥有成员选择偏好与其它操作者设置；成员数据库模块拥有成员基础资料 Schema；各领域 Repository 拥有各自平级数据库 Schema。成员库在首次创建成员时初始化，报告库只在报告或检验指标分类目录实际使用时初始化。已有数据库在任何可写连接之前按组件边界只读核对表与列；认证、成员、报告、会话和收藏库同时核对主键顺序、唯一约束、索引和外键目标，配置库严格核对完整表集合、成员启动模式、模型默认用途单例行与四个外键，以及模型 v3、联网 v2 密封格式。全部结构匹配后开放业务读写；任一差异返回 `UNSUPPORTED_SCHEMA`，数据库与文件内容维持原样，不迁移、双读或回退到旧 Schema。

## 存储组件绑定

报告、会话和模型物理 Schema 分别由 `storage/report_database.py`、`storage/conversation_database.py`、`storage/model_database.py` 唯一定义并创建、检查；模型能力的数据库编码与行解码由 `storage/model_codec.py` 承担。显式传入的数据根贯穿账号、成员、配置、主密钥、文件和事件访问。

会话索引、轮次索引与附件存储分别提供内部能力，`ConversationRepository` 保留 JSONL 及索引的提交协调。附件命名预留、独占创建、刷盘、ready 状态和失败清理由 `ConversationAttachments` 完整负责。
