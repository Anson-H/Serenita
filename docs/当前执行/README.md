## 唯一内容归属

| 内容 | 唯一权威位置 | 其它文档怎么写 |
| --- | --- | --- |
| 用户价值、版本范围、用户可见结果 | 产品需求 | 只摘要并链接 |
| 系统组成和跨模块不变量 | 技术架构总览 | 不复制精确协议 |
| 前端、HTTP API、Harness、插件、Service 与 Repository 的职责边界 | 前后端职责边界 | 前后端 README 说明具体模块入口，行为和协议回到对应专题 |
| 业务身份、授权、证据和领域操作不变量 | 对应领域契约 | 接口与 UI 只引用 |
| HTTP 方法与路径 | HTTP API | 领域文档不维护第二张端点表 |
| 会话事件语义、Provider payload 溯源、顺序与规范投影 | 会话事件 | 前端只规定如何显示，物理行格式外链 |
| 页面导航、动作、保存时机和反馈 | 前端行为 | 领域文档不写像素级 UI |
| 数据根、文件及数据库路径、密钥、权限、会话事件日志和 Schema 生命周期 | 本地存储 | 架构总览只保留安全摘要 |
| SQLite 表、列、PK/FK、唯一/检查约束、索引及跨存储引用清单 | 数据库结构 | 领域与存储文档说明授权、操作和文件生命周期，并链接准确字段映射 |
| JSONL 编码、header、事件信封、最低 `data` 字段、写入与恢复 | 会话 JSONL 格式 | 会话事件文档只维护语义、顺序和投影 |
| 字号、颜色、间距和组件视觉语言 | 根目录 `DESIGN.md` | 前端行为只引用视觉角色 |
| 跨文档固定术语 | 当前术语表 | 专题文档不另造同义词 |

一个主题只能有一个权威正文。跨文档需要上下文时写最短摘要并链接，不复制表结构、端点表、事件字段或完整流程。文档冲突时先按上表确定主题归属，再修正非权威副本；不能笼统地让“技术总览”覆盖所有专题契约。

## 变更时更新哪里

- 改版本范围或用户验收：`产品/产品需求.md`。
- 改 Harness 行动语义、Skill 或工具暴露：`架构/智能体运行时.md`。
- 改事件语义、顺序、投影或压缩行为：`架构/会话事件与投影.md`。
- 改 JSONL 编码、header、事件信封、最低字段、锁或损坏恢复：`运维/会话JSONL格式.md`。
- 改模型能力、附件路由或推理模式：`架构/模型附件与推理模式.md`。
- 改健康档案授权或医疗报告业务不变量：对应 `领域/` 文档。
- 改 HTTP 路由：`接口/HTTP接口.md`；再检查调用方文档是否只需更新链接或行为。
- 改前后端分工、状态所有者或组件调用边界：`接口/前后端职责边界.md`；模块移动同步前后端 README，系统组成变化同步`架构/技术架构总览.md`。
- 改页面动作与反馈：`前端/行为与交互.md`；改视觉尺度则更新根目录 `DESIGN.md`。
- 改目录、数据库文件位置、密钥、权限、会话事件日志或 Schema 生命周期：`运维/本地存储.md`。
- 改表、列、键、索引或约束：`运维/数据库结构.md`；业务含义同步对应领域契约。

开发入口分别是根目录 [`AGENTS.md`](../../AGENTS.md)、[`backend/README.md`](../../backend/README.md) 和 [`frontend/README.md`](../../frontend/README.md)。它们说明如何开发，不替代当前契约。


- [站内通知](领域/站内通知.md)：公共接收、事件身份、到期唤醒、可靠分发和在线更新。
