# 前端与后端职责边界

> 文档层级：当前执行 / 接口与组件边界
>
> 负责：跨前端、HTTP API、Agent Harness、插件、Service 与 Repository 的职责划分。
>
> 不负责：完整页面交互、端点清单、事件字段、数据库表或领域流程。
>
> 上位文档：[技术架构总览](../架构/技术架构总览.md)；精确路由见 [HTTP API](HTTP接口.md)，页面行为见[前端行为](../前端/行为与交互.md)。

## 时间契约

日期时间显示与编辑采用浏览器本地时区。前端将带偏移时刻转换为本地表单值，提交时转换为带偏移时刻；纯日期不经过 UTC 时刻转换。未实际更新的选择保持原时刻及精度。身体指标存储和统计边界见[身体指标](../领域/身体指标.md#时间与业务内容)，其它领域继续使用各自有效时间字段。Unix 时间戳与耗时不依赖时区。

## 账号、成员与健康档案

账号由三项清晰字段表达：`account_id` 是操作者、账号私有目录和内部归属的稳定身份，`account` 是可更新的用户标识，`account_name` 是便于人识别的账号名称。成员由 `member_id` 标识医疗资料所属的人，成员名称使用 `member_name`。身份、逐成员健康档案授权、启动偏好、固定聊天绑定和撤权语义见[成员与健康档案授权](../领域/成员与健康档案授权.md)。健康档案所有者账号目录由后端认证与授权上下文解析，界面控件负责呈现该结果。

## 生命周期与传输职责

认证生命周期在登录、退出、账号切换和认证失效时更新。请求、上传、流订阅和设置保存队列都绑定发起时的生命周期；迟到结果不能更新其它生命周期的界面或使其失效。页面请求另外绑定成员、会话、资源和操作序号，返回到同一资源也不会重新激活旧请求。

会话 Service 返回事件迭代器，HTTP 层创建流响应。文件读取在 HTTP 层做有界读取后交给 Service；医疗报告 Service 返回来源身份和元数据，HTTP 投影层生成下载及缩略图地址。后台任务只维护持久化事件和执行状态，流订阅从同一记录投影追尾。

成员访问版本和资源可用性通过成员 Service 查询。成员授权查询在同一事务内提供权限与授权生效时间，通知复用该授权结果。收藏来源及受保护的会话归属检查通过会话 Service 查询。成员存储参与者只执行事务内的数据操作，提交后的文件清理由应用层组织；账号设置通过唯一清理入口按账号执行一次有上限的清理，失败任务留待重试。

## 前端

全工作台由 `frontend/src/app/workspace/` 组合，领域模块暴露所需数据和操作。草稿、会话数据、编辑、模型配置和布局继续挂载于工作台生命周期。会话列表的初始化、轮询、操作回读和本地事件更新统一经过 `conversationIndex`，旧读取不能覆盖更晚的更新；完整详情、权限、资源状态和流式正文保留各自的应用方式。

模型目录由工作台持有一份 `ModelCatalog`。配置更新后读取一次模型与默认用途，并直接发布完整结果给设置和聊天；通知消费者时不再次读取目录。模型编辑、检验指标和分类、提供方及收藏标签保留各自的保存规则和队列，切换详情不重建其所有者。共享账号偏好位于 `accountPreferences`，API 类型按领域声明，成员文案由成员展示模块负责。

医疗报告详情控制器持有选择、详情、请求代次与结果发布校验；来源预览控制器持有读取请求和对象 URL 的创建与释放；编辑、集合操作及解读入口分别持有各自操作状态。工作区订阅只读快照并组合公开操作，选择失效由详情控制器通知相关能力清理。普通更新共享成功结果应用与失败回读，由每个操作检查权限、互斥条件和请求作用域。上传控制器组合已有附件上传和标准消息提交，管理成功资源、剩余文件及重试；原件预览显式使用所属医疗报告的成员、医疗报告和资源标识。

可见会话订阅与 HTTP 提交分别管理；离开页面只解除订阅。执行中草稿非空只显示发送（上传），为空只显示停止。等候队列允许原样取回编辑，禁止覆盖未提交草稿，重交创建新的队尾项。自动提升只刷新会话记录，不清空正在编辑的草稿。

- 负责路由、布局、表单、附件选择、会话/医疗报告视图和执行记录展示。
- 所有业务通信通过 `frontend/src/api/` 调用当前 HTTP 契约，包括成员访问事件订阅。普通请求、上传、文件读取和会话流共享 API 地址、结构化错误解析及认证和成员授权失效通知；页面负责订阅生命周期和交互反馈。
- 普通问答以及医疗报告上传和解读发送标准会话消息；医疗报告页手工录入新医疗报告、查询、编辑和删除调用普通医疗报告 API。
- 使用同源 HttpOnly Cookie，不保存登录令牌、API key 或可信业务状态。
- 前端以一个 `AuthenticatedSession` 结构承接注册、登录、认证恢复和账号资料更新；资料保存成功后直接替换当前会话，并通知同账号的其它标签页刷新。会话提交快捷键、上下文装配显示和工具执行显示由账号设置接口读写，后端以稳定 `account_id` 隔离并保存到操作者的 `settings.db`。
- 模型设置分别呈现只读汇总与非思考/思考 profile；添加模型后触发能力识别，手动刷新同时展示元数据与能力结果。输入区切换模型通过 `/api/model-access-settings` 更新账号 `chat` 默认值，当前轮次有效推理模式与持续偏好分开显示。
- 附件入口使用后端附件能力接口返回的类型；后端统一检查模型能力、Provider 原生附件支持和视觉解析能力。模型或默认配置刷新后重新查询，只有当前查询成功后才移除草稿中不再可读的 pending 文件。查询失败保留草稿并提供重试；迟到响应不得覆盖新的模型选择。上传和发送仍由后端实时校验。
- 附件上传进度只保存在当前页面内存，不建立上传标识、任务状态或结果查询。网络错误、HTTP 错误和无效响应都会移除进度项并显示明确错误；用户重新选择文件即可再次上传，前端不推断响应丢失前服务端是否已完成。
- 设置页的“联网”区域默认只接收 `has_api_key`；认证用户主动点击眼睛时，前端才调用禁止缓存的账号级 reveal 接口，把解密结果放入当前页面的密码输入框。前端负责总开关、当前服务、每个服务各自的 API 地址与密钥、显隐以及保存、测试、删除反馈；后端重新校验并使用已保存配置。
- 流式消费后端持久化事件的规范投影，按真实顺序展示允许可见的上下文、模型、工具、Observation 和错误；不拼接第二套输入、不补造工具内容、不伪造计划或 Skill 阶段。精确记录类型、字段来源、隐藏项和编码只在[会话事件契约](../架构/会话事件与投影.md#投影与展示)维护。
- 首轮只有附件而没有文本时，仍显示附件名临时标题；后端标题模型可读取附件时同时接收附件本体，否则根据附件名生成最终标题。用户原位重命名会话时，前端只提交目标标题并等待服务端返回，不判断标题任务是否运行；后端负责先取消该会话的标题任务与上游请求，再原子保存手工标题。
- 会话列表行内不显示创建分支或删除按钮。前端通过右击、触屏长按和键盘上下文菜单提供多选、置顶/取消置顶、重命名、创建分支和删除；多选时根据所选会话是否全部置顶，只提供“置顶”或“取消置顶”中的一个，并同时提供删除。稳定助手回答继续提供“创建分支”。前端不维护消息树、分支页码、活动路径或持久化轮次状态；列表图钉由摘要的 `is_pinned` 投影，旋转等候图标由 `pending_turn_status` 投影，发送、编辑和重新生成只做即时乐观标记，终态与刷新均回读后端摘要。编辑只出现在最新已结束轮次的用户消息上，重新生成只出现在对应助手回答上。
- 只允许从用户输入、过程正文和助手最终回答创建选区注释；稳定回答下的“相关内容”仅消费同轮工具 effect 与当前资源状态，Token 区仅汇总持久化模型 usage。上述区域都不从正文猜测可信数据。

## 后端

`main.py` 负责应用入口，`application/services.py` 负责按数据根装配能力。会话公开操作位于 `application/conversations/service.py`，提交、生命周期、执行、查询和流订阅由该子包内的协作者承担。事件契约与纯投影位于 `domain/conversations/`，模型能力位于 `domain/model_capabilities.py`，输入字段约束位于 `schemas/`；Repository 和存储层直接使用这些底层契约，应用层负责授权与执行。逐文件归属和调用链见[后端开发入口](../../../backend/README.md#模块入口)。

成员偏好保存先将账号配置库附加到认证库连接，再开始 `BEGIN IMMEDIATE` 事务，在读取偏好前持有两库的写入保留锁。并行配置保存按事务等待，不在读取后升级配置库锁；授权检查、偏好写入和访问序号更新仍在同一事务完成。

队列以输入事件投影为可信源，提交固化上下文资源和模型偏好，提升时才进入模型可见上下文。同会话的持久化活动轮次约束不限制其它会话；所有终态推进队首。取消与调整方向从已持久化模型正文保留内容，队列附件按执行消息、剩余队列和已取回草稿的引用清理。

- 认证 API 负责请求字段、Cookie 与响应投影，`AuthService` 负责规范化、密码校验、会话编排和账号目录生命周期，`AuthRepository` 负责 SQL 与事务。公共认证依赖向业务路由提供可信 `CurrentUser`，全局异常处理器统一投影认证错误。
- 负责从认证会话解析可信 `account_id`，再解析目标成员、健康档案所有者账号与有效健康档案权限，并完成每次读写及后续模型请求前授权、资源授权、模型/附件能力校验、预算、事务与并发一致性。
- 会话附件以 `writing + pending` 记录保护最终路径写入，维护时先校验并恢复强杀遗留写入，再扫描 `ready + pending` 过期资源；只有 `ready` 可以预览、发送或进入模型输入。正常写盘失败与超时不完整写入都通过账号作用域内的精确路径清理队列处理。
- 模型能力按非思考/思考 profile 与 Provider 原生附件上限校验；需要时整轮切换到能读取全部附件的视觉解析模型。所选状态缺少原生工具调用或附件能力而另一状态完整可用时，只追加当前轮次 `turn/thinking_mode_changed`，不更新用户偏好；两种状态都无原生工具调用时仍可走统一文本工具协议。
- 用户消息携带已保存医疗报告时，后端按会话固定成员重新授权并读取该医疗报告，把医疗报告事实和可选 `existing_ai_analysis` 放在同一个 `ATTACHED EXISTING CONTENT` 文本 part 的两个独立字段中并装入真实 Provider payload；既有解读结果不会混入 `report` 证据对象。前端提交的医疗报告名称、类型和显示字段不作为原始证据。
- Harness 统一执行所有会话并由行动模型按需记录任务计划；插件拥有领域 Skill、工具、Service 与资源解析器。
- Harness 按通用 `Tool.model_exposure` 元数据组合首步直接工具与已读取 Skill 允许的工具；后端不按页面、关键词或工具名称路由联网。
- Web 插件负责固定 Tavily/Exa 上游、以 `account_id` 定位的联网设置、密钥密封、搜索/正文归一化和当前会话线性视图的搜索引用校验。网页 Observation 不成为医疗报告资源或写入授权。
- 消息提交启动独立智能体轮次任务；SSE 仅重放/跟随持久化事件。
- `conversations` 保存置顶和手工标题标记；列表按置顶优先、最近活跃时间倒序返回。`pending_turn_status` 从 turn 索引派生，不在会话表重复持久化。标题任务按 `(account_id, session_id)` 登记取消信号，手工重命名会关闭仍在阻塞的上游请求；自动标题写入以手工标题标记仍为 false 为条件，迟到结果不得覆盖，也不产生会话事件。
- fork 在同一事务中复制稳定事件前缀与资源引用到新会话；编辑和重新生成追加替代轮次，旧执行只保留在审计日志，不进入页面或后续模型上下文。
- 后端验证 `record_annotation` 的来源记录属于当前线性投影且选区确实存在，再把它装入真实当前用户消息；插件 effect 通过通用资源解析器生成 `resource_states`，不由会话 Service 解释医疗报告动作。
- 会话 Agent 写入经工具 → Service → Repository；医疗报告页手工创建和其它传统 CRUD 经 API → Service → Repository。两条入口共享领域校验与事务，但页面 API 不调用工具或 Harness。
- 以只读方式验证当前数据库和事件格式；结构匹配后进入业务读写，校验失败时返回 `UNSUPPORTED_SCHEMA`。

## 收藏与模型配置分层

收藏请求按 API → `FavoriteService` → `FavoriteRepository` 执行。Service 负责读取授权来源、保存收藏快照和成员生命周期边界，Repository 负责 SQL 与事务。收藏来源通过会话和医疗报告 Service 读取，不依赖其它 API 的内部函数。

模型配置按 API → `ModelSettingsService` → `ModelProviderRepository` 执行。模型调用 Service 使用同一 Repository 读取配置，并共享模型响应投影。能力探测取消按账号与模型登记，探测与删除继续使用现有取消检查和事务边界；密钥密封保留账号身份和当前主密钥。

医疗报告操作后，前端通过会话详情接口重新读取受影响医疗报告的资源状态，只更新 `resource_states`，保留同时到达的会话正文。资源按 `member_id` 与 `resource_id` 定位，响应受当前成员、会话和请求顺序约束；缺少状态或刷新失败时显示“状态待刷新”，不推断当前有效、已删除或无权访问。

## 医疗报告边界

前端医疗报告页只有上传和开始/重新解读进入 Harness；手工录入、列表、详情、类型筛选、补充与读取原件、字段编辑、检验指标记录添加与删除、解读结果正文编辑和删除使用普通 API。补充原件只关联用户明确选择的文件，不解析或更新医疗报告事实；目标没有来源时第一份补充的原件成为主来源。添加检验指标只接受当前检验指标分类目录中尚未存在的指标，删除最后一条指标会被拒绝。列表按日期降序分组，详情路由为 `/reports/{member_id}/{report_id}`。手工录入可以没有原件。普通更新采用最后有效写入优先；目标或依赖不存在时返回明确错误。会话内明确的指标记录添加、字段修正和删除使用工具。导入写入工具内部校验医疗报告内容和来源，失败时返回错误，不创建待决业务记录。

成员既往史页面通过普通 HTTP API 读写，会话通过独立工具读写，两者复用同一 Service 与 Repository，并在实际操作时检查成员权限。字段及参数语义见[成员既往史](../领域/成员既往史.md)。

## 健康日记

健康日记页面经由 API → Service → Repository，会话经由工具 → Service → Repository，共用实时权限和事务。普通页面操作直接执行用户命令。

## 用药记录职责

`MedicationCatalogSettings` 在账号设置中维护药品基本信息和原件，走 API → Service → Repository。药品目录归账号所有；成员读取时通过实时授权解析健康档案所有者。

`MedicationWorkspace` 负责当前成员的药品库存与计划。药品详情只读展示目录字段和原件；添加库存药品时从目录选择药品并录入批次数量、有效期与备注。库存相关写入只针对批次，计划保持独立维护。

`plugins/medication` 提供 `medication-catalog`、`medication-query`、`medication-inventory` 与 `medication-plan` 四个 Skill。全部药品读取工具只由 `medication-query` 开放，另外三个 Skill 各自开放目录、库存和计划的写入工具。会话先识别并查询药品，目录缺少时通过 `create_medication` 一次保存资料与对应附件原件；是否加入药箱或建立计划按用户意愿处理。匹配到已有目录药品后，通过 `add_medication_sources` 补充当前会话对应附件原件。已有药品资料修正和删除由设置页面完成。Observation 回到通用行动循环，不由后端规定下一步。

## 草稿与查询所有者

医疗报告、设置、药品、批次和健康日记共用资源草稿及串行保存能力，资源键包含对应的账号、成员及对象标识；分别维护服务器值、已确认值、当前草稿、已提交内容和请求状态。同一资源串行提交，成功只确认对应草稿，背景刷新不覆盖编辑中内容。领域模块拥有字段校验、创建条件和提交内容；公共保存机制处理组合输入、等待、删除与失败恢复。草稿序号只处理前端请求与响应，不增加医疗报告内容版本令牌。页面行为见[保存与反馈](../前端/行为与交互.md#保存反馈与安全)。

工作区仅激活当前领域的数据读取。列表、完整统计和序列明细分别查询；筛选及路由状态决定当前请求，迟到响应不得改变新的作用域。设置由账号、供应商、模型、联网和通知控制器各自持有状态，外壳负责组合与导航；识别入口复用附件上传、发送和失败恢复能力。

## 公共通知职责

NotificationService 和 NotificationRepository 统一管理接收设置、通知投影、状态操作和可靠分发；应用层直接装配批量读取、有效性、展示及到期能力。轮次完成索引和待发送事项在同一个文件主库跨库事务中提交，提交后立即唤醒分发器；用药到期使用内存队列，30 秒任务用于恢复和复核。调度及数据库操作在线程池中执行，等待不阻塞事件循环。公共模块不替 Harness 选择业务步骤。

应用外壳的 NotificationProvider 统一持有账号级 SSE、数量与接收设置。NotificationWorkspace 使用公共卡片展示待处理和已读，按 target 导航到具体对象。通知由应用层自动生成、调度和投递；页面通过普通 HTTP API 访问通知 Service。会话智能体不提供通知工具。精确业务规则见[站内通知](../领域/站内通知.md)。
