## 审查阶段结论与适用范围

存在值得调整的职责边界、封装区域和冗余。下文记录 16 个有当前代码依据的改进项，其中 F16 为低优先级、可独立安排的局部封装。优先处理职责交叉和重复数据刷新，再处理高风险交互模块；不以文件长度或拆出的文件数量衡量成果。

本次检查对象是当前工作区实际文件，包含大量已有未提交修改；HEAD 为 `6fb302c`，但该提交不能代表本次审查内容。检查了前端 141 个 TypeScript/TSX 文件的本地导入关系、样式归属、业务请求入口、主要状态与交互模块、已有测试及相关前后端契约。重点沿账号、成员、会话、报告、收藏、设置的调用链阅读实现。静态检查未发现本地模块导入环，也未发现明显无人引用的完整业务模块；这不等同于运行时验收。

本文件记录审查阶段的发现，不替代 `docs/当前执行/` 的现行契约。实施后的职责说明已同步到前端 README 和前后端职责文档；实际执行结果以实施记录为准。

用户要求的功能与服务稳定性作为实施门槛：每个阶段必须证明受影响行为符合原有契约，才允许继续。仅凭静态审查和计划，不能提前保证未来实现绝对没有缺陷。当前测试也不足以证明全部真实页面和外部服务均正常。遇到原有失败，应单独记录和处理，不能把故障修复、产品行为调整混进封装重构。

## 审查时约定的实施边界

1. 业务通信统一经过 `src/api/`。Cookie、API 地址、账号请求头、认证生命周期、错误码和成员授权失效通知继续使用当前契约。请求路径、方法、参数、返回字段及 SSE 事件语义均保持一致。
2. 账号、成员、会话、报告与操作序号共同限制异步结果。账号重新登录、成员 A→B→A、报告 A→B→A、卸载再挂载都不能重新激活旧操作。抽取函数时保留闭包所属作用域，不能改成总是读取“最新页面”的回调。
3. 解除会话订阅与停止后台执行继续分开。离开页面、切换成员和切换工作区不停止后台轮次。发送、停止、排队、取回、立即执行、编辑、重新生成和创建分支保持原有语义。
4. 报告上传、开始解读和重新解读发送标准会话消息；手工录入、读取、字段保存、检验指标记录增删、补充原件、解读结果正文编辑及删除继续使用普通 API。不得引入固定工具顺序、额外会话、版本令牌或二次确认。
5. 普通报告修改继续采用最后有效写入优先；检验指标分类目录继续使用自己的 revision 和冲突机制。两者不能合成一种保存策略。
6. 每个账号、提供方、模型、联网服务和收藏的保存次序及失败语义按现有契约保留。主动显示密钥、迟到密钥响应隔离、清空草稿、保存失败保留输入和删除前收敛队列均要验收。
7. 前端展示后端持久化记录及真实资源状态。不得从回答正文推断报告状态、工具行为或医学事实，不改变模型输入和授权来源。
8. 路由、懒加载边界、React 状态存续位置、焦点、滚动、输入法、无障碍行为和移动端层级均属于需要保留的功能。
9. 初始范围限于前端职责调整，保留数据库、数据目录、账号身份、主密钥、模型与联网配置，不增加依赖或更换状态管理、路由、CSS 技术栈。实施中追加的后端成员偏好事务修复及授权依据见[实施记录](verification/frontend-refactor-implementation.md#授权追加的后端事务修复)；当前事务约束见[前后端职责边界](../docs/当前执行/接口/前后端职责边界.md#后端)。

## 审查问题与实施方案

### F01：整个工作台的组合职责归在会话功能目录

证据：`frontend/src/features/conversations/useWorkspacePageModel.ts:38`、`frontend/src/features/conversations/WorkspaceRouteContent.tsx:76`、`frontend/src/features/conversations/WorkspacePage.tsx:18`。这三个入口协调成员、报告、收藏、设置、全局外壳、路由和通知，已经超出会话页面职责。

计划：将全工作台的组合入口归入 `app/workspace/`。功能目录暴露页面视图与明确的操作接口，应用层负责连接。先移动现有组合代码并更新引用，再单独收窄接口；不同时调整状态生存期。导入路由类型本身不是缺陷，不要求为了目录纯粹而删除所有跨目录依赖。

验收：所有路由直接打开、刷新和浏览器前进后退；桌面与窄屏返回层级；报告问答入口；从收藏和会话打开报告；懒加载失败重试；离开会话后后台持续执行。

### F02：会话状态暴露面过宽，数据刷新由多个模块共同负责

证据：`frontend/src/features/conversations/useConversationPageState.ts:28` 将草稿、列表、详情、模型、附件、编辑和 DOM 引用集中返回；`frontend/src/features/conversations/useConversationLifecycle.ts:37` 接收大量 setter。`frontend/src/features/conversations/useWorkspacePageModel.ts:104` 的成员同步与轮询、生命周期初始化、提交操作和流控制器都能更新会话列表及详情。

计划：在原工作台挂载位置保留状态，明确草稿、会话数据、编辑行为、模型目录、DOM 布局各自的所有者；向消费者提供必要数据和操作，不直接传递整个状态对象。建立会话列表刷新和合并的单一入口，接入初始化、成员变更、轮询及操作完成事件。详情的完整替换与流式正文保留合并仍是不同操作，不能简单统一成 `setDetail(response)`。从会话操作中分离队列操作和侧栏列表操作，保留原有前端即时标记与后端回读。

验收：初始化、轮询、成员刷新、手工重命名与标题事件交错；流式正文同时到达时不被旧详情覆盖；置顶顺序、队列数量、活动状态、编辑和重新生成资格正确；草稿、附件、注释、来源定位及停止行为完整保留。

### F03：设置外壳同时管理多个互不相同的业务域

证据：`frontend/src/features/settings/SettingsShell.tsx:166` 管理账号资料、密码、提供方草稿、密钥读取、连接测试、模型增删与识别、默认用途、联网和页面导航；`frontend/src/features/settings/SettingsView.tsx:148` 的输入接口跨越这些全部职责。现有外壳与视图划分没有形成足够清楚的领域边界。

计划：按账号资料与安全、提供方连接配置、模型管理、默认模型、联网、设置导航分组，各自提供状态与操作。外壳负责组合。队列和请求作用域先保持在当前外壳生命周期，不能因切换详情卸载子面板而丢失待保存内容。保留既有 `ConversationSettingsPanel`、`SettingsNavigation` 等组件，继续收敛其输入接口。

验收：逐个入口进入、切换、返回；资料跨标签页更新；有效值失焦保存；无效值保持；两个提供方交错保存互不阻塞；修改连接字段后旧测试结果失效；失败通知与重试指向原操作。

### F04：模型编辑器内嵌保存队列、草稿转换和界面导航

证据：`frontend/src/features/settings/SettingsView.tsx:407` 定义模型草稿及补丁计算；`frontend/src/features/settings/SettingsView.tsx:555` 的 `ModelSettingsEditor` 自行管理延迟保存、队列合并、删除等待、识别等待和格式弹窗。

计划：拆出模型草稿与补丁纯函数、模型编辑控制器、能力编辑视图和远程模型选择视图。控制器显式提供修改、提交有效草稿、等待已排队保存完成等操作。可以用可等待的队列完成信号替代轮询等待，但必须作为单独小步骤验收。模型能力汇总、非思考与思考配置继续分别呈现。

验收：连续修改多个字段；保存期间继续输入；失败后的新输入；卸载前提交；无效数字；识别与人工编辑；删除与尚未完成的保存/识别并发。不能出现丢字段、旧草稿覆盖或删除后重新写回。

### F05：设置和聊天各自维护模型目录，存在可确认的重复读取

证据：`frontend/src/features/settings/SettingsShell.tsx:974` 附近的能力识别完成逻辑与 `updateAddedModel` 都读取模型及默认用途，然后调用 `onModelsChanged`；`frontend/src/features/settings/SettingsWorkspacePanel.tsx:27` 又通过 `frontend/src/features/conversations/modelCatalog.ts:12` 读取相同两项数据。这是具体调用链中的重复请求，不只是相似代码。

计划：将模型目录及刷新能力归入共享的账号模型配置模块，让同一次成功读取向设置和聊天提供同一份结果。保留后端回读来获得完整规范值；去掉紧邻的第二轮相同读取。默认用途写入仍使用 `modelProviderApi` 已有共享串行队列。错误、最后成功数据和未配置状态仍分别表达。

验收：保存、增加、删除、识别、默认用途变更后，设置、输入区及附件能力同步；失败后保留最后成功目录；快切模型拒绝旧响应；请求记录证明重复读取消失且必要回读仍执行。

### F06：检验指标分类目录把列表、编辑和冲突处理集中在一个组件

证据：`frontend/src/features/settings/LabDictionaryEditor.tsx:379` 负责目录读取、选择、多选、表单、自动保存、revision 更新、合并确认和删除；指标保存队列从 674 行开始，分类保存队列从 911 行开始，删除从 1030 行开始。

计划：拆出目录数据与选择控制、指标编辑、分类编辑、创建/合并对话框和目录列表视图。优先整体搬移已存在的函数边界。已有 `labCatalogDeletion.ts` 继续负责批量删除规则。两类队列共有的定时及顺序机制只有在行为测试证明相同后才抽取；指标名称冲突和分类保护继续各自处理。

验收：最新 revision 串行删除、主分类保护、指标合并、放弃修改、合并失败、切换详情时提交、空目录/筛选无结果、多选跨筛选保留，以及报告影响刷新。不能把普通报告无版本令牌的保存规则移植到目录。

### F07：报告工作区控制器同时负责数据、修改、会话提交、收藏和原件

证据：`frontend/src/features/reports/useReportWorkspace.ts:76` 集中维护列表、详情、字段与指标修改、解读入口、删除、收藏及原件预览。字段更新、指标增删、解读结果删除和补充原件中重复出现作用域检查、应用更新、刷新列表、刷新会话资源状态及失败回读。

计划：拆成报告查询与选择、报告修改、原件管理、解读入口与报告收藏等明确能力，由报告工作区组合。将成功结果应用和失败后的当前报告回读封装为有限的共享函数，保留各操作自己的权限、互斥条件、返回值和反馈。`ReportStateRefresher` 继续作为会话资源状态刷新入口。列表、详情、原件分别保持自己的请求序号；需要持久使用的回调不能捕获已失效的初次作用域。

验收：成员/报告 A→B→A；请求晚返回；报告字段与指标增删；删除最后指标失败；补充原件失败；批量删除部分成功；收藏失败；原件对象 URL 清理。报告更新后只刷新会话 `resource_states`，不覆盖并行到达的正文。

### F08：报告详情包含多个可独立封装区域，原件缩略图的成员来源也不一致

证据：`frontend/src/features/reports/ReportDetailPanel.tsx:98` 的内联编辑、322 行的行高测量、397 行的检验指标编辑、893 行的原件预览、979 行的缩略图和 1096 行的解读结果编辑均在同一文件。缩略图自行从 `useMembers()` 读取当前成员，其他原件操作使用报告工作区的成员，存在两个身份来源。

计划：按现有函数拆出内联字段、结构化字段布局、检验指标表及弹窗、原件预览/缩略图、解读结果编辑器。组件只接收需要的数据与动作，逐步去掉对完整 `ReportWorkspaceState` 的依赖。原件相关组件显式接收所属报告的 `member_id/report_id/resource_id`，与实际显示报告保持一致。

验收：直接打开不同成员报告、只读成员、缩略图晚返回、原件切换与关闭；保存失败恢复编辑；日期与空值；指标行选择；弹窗关闭后焦点和滚动位置；解读结果编辑与删除。不得改变报告结构或字段名。

### F09：报告批量上传逻辑藏在路由渲染组件中

证据：`frontend/src/features/conversations/WorkspaceRouteContent.tsx:177` 的 `startReportUpload` 管理格式检查、能力检查、成功资源、剩余文件、继续上传、会话提交及作用域；上传状态与路由渲染混在一起。

计划：建立报告上传控制器，由应用组合层传入现有批量附件上传能力和标准消息提交能力。报告组件只接收选择文件、进度、失败和继续上传操作。保留普通草稿与报告上传资源的独立性，沿用现有文件校验及 HEIF/HEIC 处理，不扩展或缩减支持格式。

验收：部分成功后停止、成功资源保留、继续剩余文件、整批成功后只提交一次；提交失败与上传失败分别处理；切换成员/路由时晚结果不能跳回；空 MIME、格式不支持、超量和超大文件；重复选择相同文件能重试。

### F10：执行记录组件混合记录类型渲染、计时和折叠控制

计划：保留顶层执行记录排序与组合，拆出折叠行为、耗时显示及按记录类型划分的渲染组件；复用已有 `contextAssemblyDisplay`、`toolTracePresentation`、`conversationTurnPresentation` 等投影函数，不再复制事件解释。类型筛选属于显示规则，不能影响后端记录或模型输入。

验收：真实记录顺序、流式增量、完成/失败/取消、压缩的两个摘要层、延迟展开、选区注释来源、联网引用、工具结果与工具观测、显示偏好，以及已完成记录的计时停止。

### F11：滚动控制器包含可分离的 DOM 测量和输入适配

证据：`frontend/src/features/conversations/useConversationScrollController.ts:87` 起包含几何读取和嵌套滚动判断，563 行起协调滚动，1099 行起安装滚轮、键盘、指针和触摸处理器；`useConversationLayout` 另负责输入区遮挡和视口测量。

计划：保留 `conversationScrollStateMachine.ts` 为唯一滚动决策实现。先抽出几何读取及手势归一化，再抽出监听器安装/清理能力；控制器继续持有操作令牌、动画调度和锚点。不要把原来有先后关系的单个 effect 随意拆成若干独立 hook，不删除浏览器差异处理，不合并用途不同的可读区域和输入区区域计算。

验收：上滑暂停、下滑恢复、异步图片增长、流式增量、历史内容插入、来源定位只执行一次、回到底部、取消定位、超时重试、焦点转移、嵌套滚动、WebKit 弹性滚动、短视口与千轮会话。该项最后实施，收益不足时可保留控制器主体。

### F12：资源条的预览几何、交互和内容投影混在一起

证据：`frontend/src/features/conversations/ResourceChips.tsx:25` 解释模型输入展示文本，49 行起的 `ContextInputPreview` 管理视口测量、上下翻转、观察器、悬停/固定状态、外部点击和 Escape，同时服务报告、注释及附件资源。

计划：提取资源预览布局与固定状态控制，保留资源类型对应的内容渲染和模型输入展示投影。优先保持现有 DOM、边界元素、类名及事件阶段。它与下拉选择器的锚点和交互不同，不要求强行套用 `useSelectPopover`。

## 已检查但不安排强制重构的区域

- `request`、认证生命周期和统一错误投影已形成明确入口。XHR 用于上传进度，fetch 用于普通请求及流，EventSource 用于成员事件，三者并存有实际用途；不因底层实现不同就统一重写。
- `streamingMessages`、会话轮次投影、报告资源状态刷新、列表选择、串行任务和附件批量上传已经有独立能力。优先使用现有实现，不再建立平行工具集。
- `MarkdownContent` 的懒加载包装、`DeferredContentBoundary`、单选/多选公共 hook、`GroupedList`、日期控件、图标目录的大小或薄包装不构成拆分理由。尤其不把大量 SVG 图标拆成无收益的零散文件。
- `favoritePresentation.ts` 对后端生成的报告快照标题和字段行存在格式依赖，后端 `favorite_service.py` 有对应生成逻辑。这是需要保护的接口行为，但目前已有独立展示模块；本计划只增加相关契约样例，不改收藏快照格式或数据库字段。
- 前端的必填、日期、大小和附件能力检查用于输入反馈，后端仍负责校验。两端都有校验不能被当成可直接删除的重复业务逻辑。
- CSS 媒体查询覆盖、读写状态与显示状态、请求序号与认证生命周期分别解决不同问题。保留有意义的重叠保护。
